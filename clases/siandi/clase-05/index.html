El Patrón Arquitectónico de 3 Capas.

Para cumplir con las directrices de robustez y flexibilidad requeridas en el Proyecto #1, prohibiremos el antipatrón Smart UI (mezclar cálculos en ventanas). Dividiremos el sistema en tres paquetes estrictos:

Contiene POJOs puros. Representan entidades de dominio mediante atributos encapsulados.

Creación y Diseño de Formularios

Funcionamiento interno de IntelliJ GUI Designer.

El Acoplamiento Biunívoco

Al crear un GUI Form, IntelliJ genera dos archivos íntimamente vinculados: un archivo con extensión .form (metadatos de maquetación) y un archivo .java.

Compilación por el IDE: Java estándar no entiende el archivo `.form`. En tiempo de compilación, IntelliJ lee el XML e inyecta directamente en el archivo .class (código de bytes o bytecode) las instrucciones de inicialización y posicionamiento geométrico.

Administración de Propiedades Complejas

Cada componente arrastrado posee propiedades en el Inspector que alteran su comportamiento:

  • field name: Nombre de la variable en la clase Java (Ej: btnAceptar). Debe usar notación húngara.
  • text: Cadena literal expuesta al usuario.
  • preferredSize / minimumSize: Controla los límites dimensionales que el Layout Manager debe respetar.

4.1. El ciclo básico de atención de eventos

Asincronía profunda, Event Queue y el Event Dispatch Thread (EDT).

Las aplicaciones de escritorio no operan de manera secuencial; se rigen por un modelo de ejecución basado en un hilo único. Cuando un formulario se despliega, el método main delega el control al Event Dispatch Thread (EDT).

Cada interacción física del usuario genera un objeto derivado de EventObject que se almacena de forma ordenada en la Cola de Eventos (Event Queue). El EDT extrae continuamente estos objetos de la cola mediante un ciclo infinito y ejecuta sus métodos correspondientes.

Regla de Oro: Bloqueo del Hilo Único

Debido a que el EDT es un hilo síncrono, si se ejecuta una tarea de alta demanda temporal dentro de un listener, el EDT se suspenderá. Como consecuencia directa, la cola de eventos se acumulará, provocando que la interfaz se congele de inmediato, impidiendo redibujar la ventana o responder a clics del usuario.

El Hilo de Eventos: Event Dispatch Thread (EDT)

¿Por qué una ventana se congela?

Concepto Vital

El Hilo Dedicado de GUI

Java Swing es Single-Threaded (No Thread-Safe). Esto significa que un solo hilo (el EDT) se encarga de:

  • Pintar y redibujar los componentes gráficos en pantalla (paint(), repaint()).
  • Atender las pulsaciones del teclado y clics del mouse.
  • Ejecutar el código que tú escribes dentro de los métodos actionPerformed(), keyPressed(), etc.
¡Peligro de Congelamiento! Si dentro de un Listener ejecutas una tarea pesada (ej: descargar un archivo de 500MB o un Thread.sleep(10000)), bloqueas el EDT. La ventana no se redibuja, el usuario ve el cursor de reloj de arena y el sistema operativo reporta "La aplicación no responde".

La buena práctica de inicialización segura:

SwingUtilities.invokeLater(() -> {
    new VentanaPrincipal().setVisible(true);
});
¿Por qué se muere tu ventana? Demostracion.java 
//  ERROR COMÚN: Bloquear el EDT
btnDescargar.addActionListener(e -> {
    // Al estar en el EDT, este ciclo congela la UI
    for (int i = 0; i < 100; i++) {
        Thread.sleep(200); // ¡La ventana se vuelve blanca!
        lblProgreso.setText(i + "%"); // Nunca se ve en tiempo real
    }
});

//  FORMA CORRECTA: Tarea pesada en hilo separado (Semana 14)
// El EDT solo se encarga de recibir clics instantáneos

Regla de diseño:

Los métodos que atienden eventos deben ejecutarse en milisegundos. Solo toman los datos y delegan.

4.2.1. Eventos originados por Hardware: El Ratón

Intercepciones físicas de bajo nivel mediante MouseListener.

Los eventos de hardware transmiten señales directas de los periféricos. Un MouseEvent se propaga inmediatamente cuando el cursor interactúa sobre el área geométrica de un componente.

La interfaz MouseListener exige la sobreescritura obligatoria de 5 de estos comportamientos. Para mitigar la creación de código innecesario, Java provee la clase abstracta MouseAdapter, actuando como filtro estructural.

btnVender.addMouseListener(new MouseAdapter() {
    @Override
    public void mouseEntered(MouseEvent e) { // Cuando entra el puntero
        btnVender.setBackground(Color.CYAN); // Cambia color
    }
    @Override
    public void mouseExited(MouseEvent e) { // Cuando sale el puntero
        btnVender.setBackground(Color.LIGHT_GRAY); // Restaura color
    }
});

4.2.1. Eventos originados por Hardware: Teclado

Validación asíncrona de entradas en tiempo real.

Un KeyEvent se genera exclusivamente en el elemento que posee el foco de entrada. Es vital para auditar restricciones de caracteres en objetos JTextField.

Mediante un KeyAdapter, podemos interceptar la constante virtual KeyEvent.VK_ENTER para activar flujos de guardado de forma veloz.

txtPrecio.addKeyListener(new KeyAdapter() {
    @Override
    public void keyPressed(KeyEvent e) {
        if (e.getKeyCode() == KeyEvent.VK_ENTER) { // Si oprime Enter
            btnVender.doClick(); // Ejecuta clic virtual
        }
    }
});

Validación en Tiempo Real con KeyListener

Filtrar caracteres con e.consume() y restricción de longitud.

La Interfaz KeyListener

Se dispara cuando un componente tiene el Foco Activo y se toca una tecla:

1. keyPressed(e)

Al pulsar la tecla física hacia abajo. Sirve para teclas especiales como F1, Ctrl, flechas o Enter.

2. keyTyped(e)

Ocurre cuando se genera un carácter Unicode imprimible (letras, números, símbolos). ¡Aquí es donde se validan campos numéricos o de solo letras!

3. keyReleased(e)

Al soltar la tecla física hacia arriba. Ideal para búsquedas en tiempo real en una tabla mientras se escribe.

e.getKeyChar() devuelve la letra o dígito.
e.getKeyCode() devuelve el código entero (ej: KeyEvent.VK_ENTER).
Validación de Campo: Solo Números ValidacionTeclado.java 
JTextField txtTelefono = new JTextField(10);

// Restringir para que el usuario NO pueda escribir letras
txtTelefono.addKeyListener(new KeyAdapter() {
    @Override
    public void keyTyped(KeyEvent e) {
        char c = e.getKeyChar();

        // Si el carácter NO es un dígito del 0 al 9:
        if (!Character.isDigit(c)) {
            // ¡CONSUMIMOS el evento! Java lo destruye y NO lo escribe
            e.consume();
            Toolkit.getDefaultToolkit().beep(); // Alerta sonora opcional
        }
    }
});
¿Qué hace e.consume()? Le dice a Java: "Este evento ya fue atendido, destrúyelo y no permitas que llegue al componente de texto". El usuario presiona una letra y simplemente nada se escribe en la caja.

4.2.2. Eventos de Sistema

Auditoría de los ciclos de vida de las ventanas y contenedores.

Los eventos de sistema provienen directamente del entorno operativo o de las transiciones estructurales del contenedor raíz. Un WindowEvent monitoriza el ciclo de vida de un JFrame.

El método windowClosing es indispensable para interceptar la destrucción de la ventana, permitiendo desplegar diálogos confirmatorios de precaución antes de liberar el hilo de ejecución principal.

frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);
frame.addWindowListener(new WindowAdapter() {
    @Override
    public void windowClosing(WindowEvent e) { // Al dar clic a la X
        int resp = JOptionPane.showConfirmDialog(frame, "¿Salir?");
        if (resp == JOptionPane.YES_OPTION) System.exit(0);
    }
});

4.2.3. Eventos de Aplicación (Pseudoeventos)

Abstracción semántica y alta cohesión lógica.

Un pseudoevento representa una abstracción conceptual de alto nivel. Ignora el periférico físico exacto (ratón o teclado) y se enfoca estrictamente en que el componente ha cumplido su acción semántica principal. Su mayor exponente es ActionEvent, procesado mediante un ActionListener.

Beneficio de la Abstracción

Al asociar un ActionListener a un botón, el EDT ejecutará el bloque de código de forma idéntica si el usuario hace clic con el ratón, si navega con el teclado usando la tecla Tabulador y oprime la Barra Espaciadora, o si se invoca programáticamente mediante el método doClick().

Otros Pseudoeventos Esenciales:

ItemEvent: Notifica cambios de estado en componentes de selección selectiva (como casillas de verificación o menús desplegables).

DocumentEvent: Monitorea de forma directa las modificaciones en el buffer de texto de un JTextField, abstrayendo si los caracteres entraron por tipeo directo o por comandos de pegado de portapapeles.

Creando Nuestros Propios Eventos de Aplicación

Desacoplamiento total con eventos personalizados.

¿Qué es un Pseudoevento?

No todos los eventos nacen de un clic de mouse o de una tecla. Un Pseudoevento es un evento creado por nosotros mismos para comunicar cambios internos en nuestro sistema.

Ejemplo en el mundo real:

Cuando una cuenta bancaria llega a saldo negativo, la clase Cuenta dispara un SaldoAgotadoEvent. La vista se entera y se pinta en rojo automáticamente.

Beneficio Arquitectónico:

Permite que el Modelo y el Controlador le avisen a la Vista que algo cambió sin conocer los componentes gráficos (desacoplamiento total).

Este es el corazón del Patrón de Diseño Observer que veremos en la Semana 7.
Cómo crear tu propio evento a la medida StockEvent.java 
// 1. Creamos el objeto del evento personalizado
public class StockAgotadoEvent extends java.util.EventObject {
    private String codigoProducto;

    public StockAgotadoEvent(Object source, String codigo) {
        super(source);
        this.codigoProducto = codigo;
    }
    public String getCodigo() { return codigoProducto; }
}

// 2. Creamos la interfaz del Listener personalizado
public interface StockListener {
    void onStockAgotado(StockAgotadoEvent e);
}
¡Cualquier clase de tu sistema ahora puede suscribirse a StockListener y enterarse al instante cuando se acabe el inventario!

4.2.4. Jerarquías de Atención de Eventos

Arquitectura de filtrado, propagación y segregación de listeners.

Java delega los eventos de forma explícita. Un componente visual no propaga eventos hacia sus contenedores padres a menos que existan escuchadores específicamente suscritos. Podemos organizar la atención bajo dos enfoques jerárquicos:

Atención Dedicada: Cada componente posee su propio listener único e independiente, comúnmente implementado a través de una expresión lambda. Esto promueve una alta cohesión.

Atención Compartida: Un único objeto Listener se suscribe a múltiples fuentes gráficas. Al activarse el método común, se utiliza la instrucción e.getSource() para comparar las referencias en memoria y bifurcar el flujo operativo de la aplicación.

btnVender.addActionListener(e -> {
    if (e.getSource() == btnVender) { // Identifica origen
        procesarVenta(); // Llama al flujo
    }
});

Las 4 Formas de Implementar Listeners

Evolución histórica y sintáctica: ¿Cuál usar en cada caso?

Forma 1 (Clásica)

implements ActionListener

La propia ventana implementa la interfaz. Obliga a poner un if/else gigante con e.getSource() para saber qué botón se presionó.

public void actionPerformed(ActionEvent e) {
  if (e.getSource() == btn1) { ... }
  else if (e.getSource() == btn2) { ... }
}
Forma 2

Clase Interna Anónima

Se instancia la interfaz directamente dentro del addActionListener. Muy usada antes de Java 8 y en adaptadores con múltiples métodos.

btn.addActionListener(new ActionListener() {
  @Override
  public void actionPerformed(ActionEvent e) {
    guardar();
  }
});
Forma 3 (Estándar Moderno)

Expresiones Lambda (->)

Sintaxis compacta y limpia introducida en Java 8. Aplica para cualquier Interfaz Funcional.

// Limpio, directo y legible
btnGuardar.addActionListener(e -> {
  guardar();
});
Forma 4 (Eventos Complejos)

Clases Adapter

Para interfaces con muchos métodos (MouseListener, WindowListener). Permite sobreescribir solo 1 método en vez de 5.

comp.addMouseListener(new MouseAdapter() {
  @Override
  public void mouseClicked(MouseEvent e) {
    seleccionar();
  }
});

public void actionPerformed(ActionEvent e)

String pel = txtPelicula.getText();

Usa la función getText() para extraer los caracteres que la persona escribió dentro de la caja de texto del formulario y los guarda en una variable común de texto.

double pre = Double.parseDouble(txtPrecio.getText());

Extrae el texto de la caja de precio y usa Double.parseDouble() para convertirlo de texto a número real, permitiendo operar con decimales en la taquilla.

taquillaService.venderBoleto(new Boleto(pel, pre));

Explicación: Escuchadores de Ratón

btnVender.addMouseListener(new MouseAdapter() { ... });

Instancia un oyente de hardware físico. Usar MouseAdapter nos evita tener que escribir obligatoriamente otros 4 métodos de ratón vacíos que no nos interesan.

public void mouseEntered(MouseEvent e)

Método asíncrono que reacciona justo en el instante en que el cursor físico del ratón cruza la frontera geométrica del botón, cambiando su fondo a celeste.

public void mouseExited(MouseEvent e)

Método de salida: Restaura el color gris estándar del botón en el momento en que el usuario retira el cursor de encima.

Explicación: Escuchadores de Teclado

if (e.getKeyCode() == KeyEvent.VK_ENTER)

Inspecciona el código binario de la interrupción del teclado que mandó el Sistema Operativo y evalúa si concuerda con el código físico de la tecla Enter.

btnVender.doClick();

Fuerza el disparo lógico del botón mediante software. Logra que el programa reaccione como si el usuario le hubiera dado un clic físico al botón de vender.

Explicación: Eventos de Cierre de Sistema

frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);

Cancela la destrucción automática del JFrame que hace el sistema operativo por defecto al tocar la X roja. Así, el control pasa enteramente a nuestro código.

public void windowClosing(WindowEvent e)

Atrapa la señal de intención de salida, levanta una cajita de diálogo confirmatoria y, si el usuario dice que sí, apaga la máquina virtual por completo con System.exit(0).
