Java vs JavaScript

Suenan parecido, pero son muy distintos.

Java

  • Lenguaje compilado → se convierte a bytecode que corre en la JVM.
  • Orientado a objetos desde el inicio (todo es clase).
  • Tipado estático → las variables tienen un tipo fijo (int x = 5;).
  • Se usa para: aplicaciones empresariales, Android, backend, sistemas grandes.
  • Corre en un servidor o en una máquina virtual.
  • WORA (Write Once, Run Anywhere).
public class Hola { public static void main(String[] a) { System.out.println("Hola"); } }

JavaScript

  • Lenguaje interpretado → el navegador o Node.js lo ejecuta línea por línea.
  • Multiparadigma → funcional, orientado a objetos, imperativo.
  • Tipado dinámico → una variable puede cambiar de tipo (let x = 5; x = "hola";).
  • Se usa para: frontend web (interactividad en páginas), backend con Node.js.
  • Corre en el navegador (del lado del cliente) o en servidores.
  • No tiene relación con Java más que el nombre (por marketing).
console.log("Hola"); // JS no necesita clases para esto

Analogía: Java es como un tren (todo planificado, rígido, potente). JavaScript es como un carro de montaña rusa (flexible, ágil, se adapta sobre la marcha). Ambos te llevan a destino, pero de formas muy diferentes.

Array vs ArrayList

Ambos guardan múltiples elementos, pero con reglas muy diferentes.

Array Tamaño fijo
ArrayEjemplo.java 
int[] numeros = new int[5]; // Tamaño fijo: 5
numeros[0] = 10;
numeros[1] = 20;
// numeros[5] = 30; → ERROR: índice fuera de rango

String[] nombres = {"Ana", "Carlos"}; // Tamaño 2
  • ✓ Rápido, memoria contigua.
  • ✓ Soporta tipos primitivos (int, double, etc.).
  • ✗ Tamaño fijo al crearlo.
  • ✗ No tiene métodos para agregar/eliminar fácilmente.
ArrayList Tamaño dinámico
ArrayListEjemplo.java 
import java.util.ArrayList;

ArrayList<Integer> nums = new ArrayList<>(); // Tamaño 0
nums.add(10);   // ahora tamaño 1
nums.add(20);   // tamaño 2
nums.add(30);   // tamaño 3 → crece solo
nums.remove(1);  // elimina el 20, tamaño 2

String nombre = nums.get(0); // "Ana"
  • ✓ Tamaño dinámico (crece y se encoge).
  • ✓ Métodos útiles: add(), remove(), get(), size().
  • ✗ Solo guarda objetos (no primitivos, usa wrappers).
  • ✗ Un poco más lento que un array por la gestión interna.

Regla de oro: Si sabe cuántos elementos va a tener y no va a cambiar → use array. Si la lista puede crecer o encogerse → use ArrayList.

for tradicional vs foreach (enhanced for)

Dos formas de recorrer, cada una con su propósito.

for Tradicional 
for (int i = 0; i < lista.size(); i++) {
    String elemento = lista.get(i);
    System.out.println(elemento);
}
  • ✓ Tiene control total del índice.
  • ✓ Puede modificar la lista mientras la recorre (con cuidado).
  • ✓ Útil cuando necesita el índice para algo.
  • ✗ Más verboso (más código).
foreach Enhanced for 
for (String elemento : lista) {
    System.out.println(elemento);
}
  • ✓ Más legible y menos propenso a errores.
  • ✓ No necesita el índice, solo el elemento.
  • ✗ No puede modificar la lista mientras la recorre (tiraría ConcurrentModificationException).
  • ✗ No tiene acceso al índice.

Regla de oro: Si solo necesita leer los elementos → use foreach. Si necesita el índice o modificar la lista → use el for tradicional.

@Override y las anotaciones

Son etiquetas que le dan instrucciones al compilador.

¿Qué es una anotación?

Una anotación es un metadata que se puede agregar a clases, métodos, variables, etc. Empiezan con @. No cambian la lógica del programa, pero le dan información adicional al compilador, al framework o a herramientas.

@Override
@Deprecated
@SuppressWarnings
@FunctionalInterface
@SafeVarargs
@Retention
@Target

Java tiene anotaciones predefinidas, y también se pueden crear las propias.

@Override en detalle

@Override le dice al compilador: "Este método está sobrescribiendo (override) un método de la clase padre o de una interfaz". Es opcional pero muy recomendado porque:

  • • Previene errores: si se escribe mal el nombre, el compilador le avisa.
  • • Mejora la legibilidad: otros programadores saben que es un override.
class Animal {
    public void hacerSonido() { ... }
}
class Perro extends Animal {
    @Override  // ← esto es una anotación
    public void hacerSonido() {
        System.out.println("Guau");
    }
}

¿Qué pasa si no se usa @Override? El código funciona igual. Pero si se equivoca en el nombre (ej. hacerSonido2), el compilador no se queja y crea un método nuevo en vez de sobrescribir. @Override te salva de ese error.

Anotaciones útiles en Java

Más allá de @Override, hay muchas anotaciones integradas que te ayudan.

@Deprecated

Marca un elemento (clase, método, campo) como obsoleto. El compilador muestra una advertencia si se usa. Se recomienda explicar por qué y qué usar en su lugar (con @deprecated en la documentación).

@Deprecated
public void metodoViejo() { ... }

@SuppressWarnings

Le dice al compilador que suprima advertencias específicas. Útil cuando se sabe que una advertencia es segura de ignorar (ej. "unchecked" en código legacy).

@SuppressWarnings("unchecked")
public void metodoLegacy() { ... }

@FunctionalInterface

Indica que la interfaz tiene un solo método abstracto (SAM). Permite que se use con lambdas. El compilador verifica que solo tenga un método abstracto.

@FunctionalInterface
interface Calculadora {
    int sumar(int a, int b);
}

@SafeVarargs

Suprime advertencias sobre operaciones inseguras con varargs (argumentos variables) de tipo genérico. Se usa en métodos static o final.

@SafeVarargs
public static <T> T[] toArray(T... items) { ... }

@Override

Verifica que el método esté sobrescribiendo correctamente un método de la superclase o interfaz. Previene errores de escritura en el nombre del método.

class Circulo extends Figura {
    @Override
    public double calcularArea() { ... }
    }

@Retention y @Target

Son meta-anotaciones que especifican cuándo y dónde se puede usar una anotación personalizada. Ej. @Retention(RetentionPolicy.RUNTIME) para que esté disponible en tiempo de ejecución.

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MiAnotacion { ... }

Consejo: Siempre que veas una anotación, investigue qué hace. Son una herramienta poderosa para mejorar la calidad y legibilidad del código.

¿Por qué la carpeta src?

No es magia, es organización y convenciones.

Estructura de proyectos Java

En Java (y en muchos lenguajes), se sigue una estructura de carpetas estándar para organizar el código fuente, los recursos y los archivos compilados. 

mi-proyecto/
├── src/           ← Código fuente (.java)
│   └── com/
│       └── una/
│           └── progra3/
│               └── Main.java
├── out/          ← Archivos compilados (.class)
└── lib/          ← Bibliotecas externas (.jar)

La carpeta src (source) es donde va todo tu código Java. Los archivos .class (bytecode) se generan en otra carpeta (como out).

Source Root: ¿qué es y para qué sirve?

En IntelliJ, marcar una carpeta como Source Root (Mark Directory as → Sources Root) le dice al IDE:

  • • “Aquí está mi código fuente” → el compilador va a buscar archivos .java ahí.
  • • “Resuelva los imports desde aquí” → los paquetes se resuelven desde esta raíz.
  • • “No compile nada que esté fuera de aquí” → separa código de otros archivos.
// Si src/ es Source Root, entonces:
package com.una.progra3; // ← ruta: src/com/una/progra3/

¿Por qué no hay que importar las clases al main? Porque si están en el mismo paquete o en un paquete que está en el Source Root, el compilador las encuentra automáticamente. Solo se necesita import si la clase está en otro paquete.

¿Por qué IntelliJ solo corre la clase con main?

La JVM necesita un punto de entrada.

El método main es la puerta de entrada

Cuando ejecutás java MiClase, la JVM:

  1. Carga la clase MiClase en memoria.
  2. Busca un método public static void main(String[] args).
  3. Si lo encuentra, lo ejecuta. Si no, tira un error.
Error: Main method not found in class MiClase

¿Por qué tiene que ser static? Porque la JVM necesita llamar al método sin crear un objeto de la clase. Si no fuera static, tendría que hacer new MiClase().main(), pero no sabe cómo construir el objeto.

¿Y las otras clases?

Las clases que no tienen main son como plantillas o componentes. No se pueden ejecutar por sí solas porque la JVM no sabe qué hacer con ellas.

  • • Estudiante → define qué es un estudiante, pero no "hace" nada por sí mismo.
  • • Calculadora → tiene métodos para sumar, pero no se ejecuta sola.
  • • Main → usa a Estudiante y Calculadora para orquestar el programa.
// Main.java — el director de orquesta
public class Main {
    public static void main(String[] a) {
        Estudiante e = new Estudiante("Ana");
        System.out.println(e.getNombre());
    }
}

Analogía: El main es como el chef ejecutivo en una cocina. Las otras clases son los ingredientes y recetas. El chef las usa para preparar el plato (el programa). Sin chef, los ingredientes no se cocinan solos.

Herencia

Reutilización y jerarquía con extends.

¿Qué es la herencia?

La herencia es un mecanismo que permite que una clase (subclase) herede atributos y métodos de otra clase (superclase).

En Java solo se permite herencia simple: una clase solo puede extenderse de una única superclase.


¿Para qué sirve?

Para reutilizar código, establecer relaciones jerárquicas ("es-un") y aplicar polimorfismo.



¿Cuándo usarla?

Cuando varias clases comparten atributos y comportamiento común, conviene extraerlos a una clase padre.

Ejemplo básico 

class Animal {
    protected String nombre;
    public void comer() {
        System.out.println(nombre + " está comiendo");
    }
}

class Perro extends Animal {
    // Hereda nombre y comer()
    public void ladrar() {
        System.out.println("¡Guau!");
    }
}

protected permite que las subclases accedan a los miembros de la superclase.

Analogía: La herencia es como una familia: los hijos heredan características de sus padres (apellido, rasgos físicos), pero también pueden tener los suyos propios. En programación, la clase hija hereda atributos y métodos de la clase padre.

Herencia

super, constructores y @Override.

Uso de super

super se usa para:


  • Llamar al constructor de la clase padre (super(parámetros)).
  • Acceder a métodos o atributos de la clase padre que han sido sobrescritos.

Regla: la llamada a super() debe ser la primera instrucción en el constructor de la subclase.

Jerarquía de constructores

Cuando se crea un objeto de una subclase, se ejecuta primero el constructor de la superclase (implícitamente o con super()), y luego el de la subclase. 

// Constructor sin parámetros
class Animal {
    public Animal() {
        System.out.println("Constructor Animal");
    }
}
class Perro extends Animal {
    public Perro() {
        super(); // se llama implícitamente
        System.out.println("Constructor Perro");
    }
}
Ver ejemplo con super(parámetros) 
// Constructor con parámetros
class Animal {
    protected String nombre;
    public Animal(String nombre) {
        this.nombre = nombre;
        System.out.println("Animal: " + nombre);
    }
}
class Perro extends Animal {
    public Perro(String nombre) {
        super(nombre); // ← obligatorio: pasa el parámetro
        System.out.println("Perro: " + nombre);
    }
}
// new Perro("Firulais") → Animal: Firulais → Perro: Firulais

Si la clase padre no tiene constructor sin parámetros, debe llamar explícitamente a super(parámetros).

Sobrescritura de métodos con @Override

Las subclases pueden sobrescribir métodos de la superclase para proporcionar su propia implementación. La anotación @Override es opcional pero muy recomendada para detectar errores de escritura. 

class Perro extends Animal {
    @Override
    public void comer() {
        System.out.println("El perro come croquetas");
    }
}

Interfaces

Contratos que definen qué hacer, no cómo hacerlo.

¿Qué es una interfaz?

Una interfaz es un contrato que especifica un conjunto de métodos que una clase debe implementar.
Todos los métodos de una interfaz son abstractos (sin cuerpo) hasta Java 8, que introdujo métodos default y static.


¿Para qué sirve?

Para definir comportamientos comunes que pueden ser implementados por clases no relacionadas (herencia múltiple de comportamiento).



¿Cuándo usarla?

Cuando se quiere que clases de diferentes jerarquías compartan un comportamiento (ej. Comparable para ordenar).


Cada interface va en su propio archivo (.java), igual que una clase. No se declaran dentro de Animal ni de Pato.

Sintaxis básica 

// Volador.java — archivo independiente
interface Volador {
    void volar();  // método abstracto
}

// Nadador.java — archivo independiente
interface Nadador {
    void nadar();
}

// Pato.java — hereda de Animal e implementa las interfaces
class Pato extends Animal implements Volador, Nadador {
    public void volar() { System.out.println("Pato volando"); }
    public void nadar() { System.out.println("Pato nadando"); }
}

Una clase puede implementar múltiples interfaces, logrando una forma de herencia múltiple.

Analogía: Las interfaces son como roles o profesiones. Una persona puede ser médico, músico y deportista al mismo tiempo. Cada rol define un conjunto de acciones que debe realizar, pero la forma de hacerlas depende de cada persona.

¡No confundir! Una interfaz en programación (interface) es un contrato de código que define métodos que una clase debe implementar. Una interfaz gráfica (GUI) es la parte visual de un programa (ventanas, botones, menús).
Son conceptos totalmente distintos.

Polimorfismo con interfaces

Tratar objetos de diferentes clases de manera uniforme.

¿Qué es el polimorfismo?

El polimorfismo (poli = muchas, morfos = formas) permite que una misma variable pueda referirse a objetos de diferentes clases, siempre que compartan una interfaz o superclase común.


¿Cómo se aplica?

  1. 1. Se define una interfaz (ej. Mascota) con los métodos que deben cumplir.
  2. 2. Varias clases implementan esa interfaz, cada una a su manera.
  3. 3. Se escribe un método que recibe el tipo de la interfaz, no una clase concreta.
  4. 4. Al llamar al método, Java decide en tiempo de ejecución qué versión del método se ejecuta, según el objeto real que se pasó.

Ejemplo: el método divertir(Mascota m) acepta un Perro, un Gato o cualquier clase que implemente Mascota. Cuando llama a m.jugar(), Java ejecuta el jugar() correspondiente al objeto que realmente recibió.

Ejemplo en acción 

interface Mascota {
    void jugar();
}

class Perro implements Mascota {
    public void jugar() { System.out.println("Perro juega a la pelota"); }
}

class Gato implements Mascota {
    public void jugar() { System.out.println("Gato juega con un ovillo"); }
}

public static void divertir(Mascota m) {
    m.jugar();  // ← ¡mismo código, distinto resultado!
}

¿Qué pasa al ejecutar?

divertir(new Perro()) → "Perro juega a la pelota"
divertir(new Gato()) → "Gato juega con un ovillo"

La magia: el parámetro Mascota m puede recibir cualquier objeto que implemente Mascota. Java automáticamente ejecuta el jugar() correcto según el tipo real del objeto.

Ventaja: se puede escribir código genérico que funcione con cualquier objeto que cumpla el contrato de la interfaz, sin importar su clase concreta. Si mañana se agrega Hamster, ¡divertir() funciona sin cambios!

Paquetes

Organización arquitectónica: Espacios de nombres y dependencias.

package

Técnicamente: Define el espacio de nombres (namespace) de la clase para evitar colisiones de identificadores y agrupar componentes lógicamente. Debe coincidir obligatoriamente con la estructura de directorios del sistema.

En simple: Un paquete es una carpeta dentro del disco duro para organizar los archivos .java. Sin esta organizacion, un proyecto de 300 clases seria imposible de mantener.

package com.una.progra3.modelo;

El archivo físico debe estar en la ruta: src/com/una/progra3/modelo/.

import

Técnicamente: Resuelve las dependencias externas. Permite instanciar clases de otros espacios de nombres sin tener que escribir su ruta absoluta (Fully Qualified Name) cada vez.

En simple: Es pedir prestada una herramienta de otra caja. Le avisa a Java: "Oye, en este archivo voy a usar código que guardamos en otra carpeta".

import com.una.progra3.utilidades.Calculadora;

Sin esto, tendrías que escribir com.una.progra3.utilidades.Calculadora calc = new...

Un paquete = Una carpeta en tu disco duro

src/
└── com/
    └── una/
        └── progra3/
            ├── modelo/ 
            │   ├── Estudiante.java   // package com.una.progra3.modelo;
            │   └── Curso.java        // package com.una.progra3.modelo;
            ├── utilidades/
            │   └── Calculadora.java  // package com.una.progra3.utilidades;
            └── Main.java             // Necesita importar modelo.* y utilidades.Calculadora

Esta separación nos permitirá implementar arquitecturas profesionales como el patrón MVC (Modelo-Vista-Controlador) más adelante.

Genéricos

Escribir código que funcione con cualquier tipo de dato.

¿Por qué existen?

Antes de Java 5 (2004), no había genéricos. Si querías una lista que guardara Integer, tenías que hacer casting explícito cada vez que sacabas un elemento. Esto era propenso a errores y menos legible. 

// Sin genéricos (Java 4 y anteriores)
List lista = new ArrayList();
lista.add(5);
Integer num = (Integer) lista.get(0); // ← casting obligatorio

Problemas: el casting es propenso a errores (ClassCastException en tiempo de ejecución) y el compilador no podía verificar que el tipo fuera correcto.

La solución: Genéricos

Los genéricos te permiten parametrizar clases, interfaces y métodos con un tipo que se define al usarlos. 

// Con genéricos (Java 5+ )
List<Integer> lista = new ArrayList<>();
lista.add(5);
Integer num = lista.get(0); // ← sin casting, el compilador sabe que es Integer
  • • Seguridad en tiempo de compilación → menos errores en runtime.
  • • Código más legible → el tipo queda explícito.
  • • Reutilización → una misma clase sirve para varios tipos.

Clases genéricas

Cree sus propias plantillas reutilizables.

Sintaxis y propósito

Una clase genérica se declara con uno o más parámetros de tipo entre <> (ej. T, E, K, V).
Estos parámetros actúan como placeholders para el tipo real que se usará al instanciar la clase.


Convención

T = Tipo genérico  |  E = Elemento  |  K/V = Clave/Valor


Ventaja

La clase puede manejar cualquier tipo sin duplicar código. Una sola implementación sirve para String, Integer, etc.


Usos típicos

ArrayList · HashMap · contenedores


Ejemplo: Caja<T> 

public class Caja<T> {
    private T contenido;

    public void poner(T algo) {
        this.contenido = algo;
    }

    public T sacar() {
        return contenido;
    }
}

// Uso con String
Caja<String> cajaTexto = new Caja<>();
cajaTexto.poner("Hola");
String s = cajaTexto.sacar(); // sin casting

// Uso con Integer
Caja<Integer> cajaNum = new Caja<>();
cajaNum.poner(42);
Integer n = cajaNum.sacar();

Analogía: Una clase genérica es como un molde para galletas. El molde es el mismo, pero podés usarlo con diferentes masas (tipos). El resultado siempre tiene la misma forma, pero con distinto sabor.

Métodos genéricos

Parametrizá métodos individuales, no solo clases.

¿Cuándo usar un método genérico?

Cuando el método debe operar con diferentes tipos y el tipo no está definido en la clase. Es útil para métodos de utilería estáticos que trabajan con colecciones o algoritmos genéricos.

Sintaxis: el tipo genérico se declara antes del tipo de retorno: <T> T metodo(T param).

Ejemplo práctico 

public class Utilidades {
    // Método genérico para obtener el primer elemento de una lista
    public static <T> T obtenerPrimero(List<T> lista) {
        if (lista.isEmpty()) return null;
        return lista.get(0);
    }

    // Método genérico para imprimir un array de cualquier tipo
    public static <T> void imprimirArray(T[] arr) {
        for (T elem : arr) {
            System.out.println(elem);
        }
    }
}

// Uso:
List<String> nombres = List.of("Ana", "Carlos");
String primero = Utilidades.obtenerPrimero(nombres);  // "Ana"

Integer[] nums = {1, 2, 3};
Utilidades.imprimirArray(nums);

El tipo T se infiere automáticamente según los argumentos.

Wildcards en Genéricos

El símbolo ? da flexibilidad a los tipos genéricos.

¿Qué es un wildcard?

Un wildcard (?) es un comodín — como un joker en un juego de cartas 🃏. Representa un tipo desconocido y se usa cuando no necesitás saber exactamente qué tipo es, solo que es algo.

? — Sin límite

Acepta cualquier tipo. Solo podés leer como Object.

? extends T

Acepta T o subtipos. Límite superior. Usado para leer.

? super T

Acepta T o supertipos. Límite inferior. Usado para escribir.

Analogía: El cajero automático

Un cajero automático acepta cualquier tarjeta bancaria sin importar el banco. No necesita saber si es del BAC, del Nacional o del BCR. Solo le importa que implemente la interfaz de "tarjeta".

Así funciona List<? extends Tarjeta>: recibe cualquier lista de algo que sea Tarjeta. El método procesarPago() funciona igual sin importar la marca concreta.

💡 Usá wildcards cuando el método solo necesita saber "es algo de esta familia", no exactamente qué miembro.

Ejemplo: wildcard sin límite 

// Imprime cualquier lista, sin importar el tipo
public static void imprimirLista(List<?> lista) {
    for (Object o : lista) {
        System.out.println(o);
    }
}

// Uso: funciona con List<String>, List<Integer>, etc.
List<String> nombres = List.of("Ana", "Carlos");
List<Integer> numeros = List.of(1, 2, 3);
imprimirLista(nombres);  // compila
imprimirLista(numeros);  // compila

El wildcard sin límite es útil cuando solo se necesita leer elementos. No se puede agregar elementos (excepto null), porque el compilador no puede garantizar que el tipo sea compatible.

¿Cuándo y por qué usar wildcards?

Los wildcards se usan cuando no necesitás saber el tipo exacto, solo te interesa que el objeto cumpla cierta relación con un tipo conocido.

Ejemplo: Un método que imprime una lista no necesita saber si es List<String> o List<Integer>, solo necesita recorrerla. Usa List<?>.

Ejemplo: Un método que calcula el máximo de una lista de números puede aceptar List<Integer>, List<Double>, etc. Usa List<? extends Number>.

Wildcards con límites

extends y super para mayor control.

? extends T (límite superior)

Acepta cualquier tipo que sea subclase de T (o el mismo T). Solo se puede leer (no agregar), porque no sabemos exactamente qué tipo concreto se puede agregar de forma segura. 

public static <T> T max(List<? extends T> lista) {
    if (lista.isEmpty()) return null;
    T max = lista.get(0);
    for (T elem : lista) {
        if (elem.compareTo(max) > 0) max = elem;
    }
    return max;
}

Útil cuando la lista es un productor (provee elementos).

? super T (límite inferior)

Acepta cualquier tipo que sea superclase de T (o el mismo T). Se puede agregar elementos de tipo T (o subtipos), pero al leer solo obtenemos Object. 

public static <T> void copiar(List<? super T> destino, List<T> origen) {
    for (T elem : origen) {
        destino.add(elem);  // seguro: destino acepta T o supertipos
    }
}

Ideal cuando la lista es un consumidor (recibe elementos).

Principio PECS

Producer Extends, Consumer Super — una guía para usar wildcards.

¿Por qué se llama PECS?

PECS es un acrónimo acuñado por Joshua Bloch (autor de Effective Java) para recordar cuándo usar extends y cuándo super.

  • Producer → usa Extends (solo lees).
  • Consumer → usa Super (solo escribes).

Si una estructura de datos produce elementos (los da), usa ? extends T. Si consume elementos (los recibe), usa ? super T.

Ejemplo completo: copia 

// Copia elementos de una lista (productor) a otra (consumidor)
public static <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}

// Uso:
List<Integer> origen = List.of(1, 2, 3);
List<Number> destino = new ArrayList<>();
copy(origen, destino);  // src: ? extends Number, dest: ? super Number

Aquí src produce elementos (se leen), dest los consume (se agregan).

Resumen: Si solo leés → extends. Si solo escribís → super. Esto hace tu API más flexible y segura.

Casting en Genéricos

Conversión de tipos: cast explícito e implícito.

¿Qué es el casting?

El casting es la conversión de un tipo de dato a otro. En Java, puede ser implícito (automático, sin pérdida de información, ej. int a long) o explícito (cuando hay riesgo de pérdida o se necesita forzar la conversión).

En el contexto de genéricos, antes de Java 5, el casting era obligatorio al sacar elementos de colecciones sin tipo. Con genéricos, el compilador elimina la necesidad de casting en la mayoría de los casos.

Ejemplo: antes y después 

// Sin genéricos (Java 4)
List lista = new ArrayList();
lista.add("Hola");
String s = (String) lista.get(0);  // ← casting explícito

// Con genéricos (Java 5+)
List<String> lista2 = new ArrayList<>();
lista2.add("Hola");
String s2 = lista2.get(0);  // ← sin casting

Los genéricos hacen que el casting sea innecesario y más seguro, ya que el compilador garantiza el tipo.

Advertencia: Aún se puede hacer casting explícito (ej. (String) objeto), pero puede lanzar ClassCastException en runtime si el tipo no coincide. Los genéricos minimizan esta necesidad.

Características modernas de Java (Parte 1)

Lambdas, Streams, Optional y más.

Expresiones Lambda

Una lambda es una función sin nombre que se escribe directamente donde se necesita. Antes de Java 8, para pasar una "acción" como parámetro tenías que crear una clase entera. Las lambdas eliminan ese código repetitivo.

Analogía: El control remoto

Una lambda es como un control remoto: no necesitás saber cómo funciona por dentro, solo presionás el botón y "hace algo". (a, b) -> a.compareTo(b) es como decir "tomá estos dos y ordenalos alfabéticamente".

Sintaxis: (parámetros) -> expresión

// 1. Ordenar una lista alfabéticamente
List<String> nombres = List.of("Carlos", "Ana");
nombres.sort((a, b) -> a.compareTo(b));
// (a, b) son dos elementos de la lista
// -> "hacé esto con ellos"
// a.compareTo(b) compara a con b

// 2. Recorrer e imprimir cada elemento
nombres.forEach(n -> System.out.println(n));
// n es cada elemento, -> lo imprime
// Resultado: Ana  /  Carlos

Solo funcionan con interfaces funcionales (un solo método abstracto, como Comparator o Consumer).

Stream API

Un Stream es como una línea de producción : los datos pasan por una serie de estaciones donde se filtran, transforman y ordenan, sin modificar la colección original. Son lazy: nada se ejecuta hasta que pedís el resultado final.

.filter(n -> n % 2 == 0) Filtra: solo deja pasar los números pares.

.map(n -> n * n) Transforma: cada elemento se eleva al cuadrado.

.sorted() Ordena: organiza los resultados.

.collect(toList()) Recolecta: junta todo en una lista final.

Lista original: [1, 2, 3, 4, 5]

List<Integer> resultado = nums.stream()   // abre el flujo
    .filter(n -> n % 2 == 0)  // [2, 4]    — solo pares
    .map(n -> n * n)        // [4, 16]   — al cuadrado
    .sorted()              // [4, 16]   — ya está ordenado
    .collect(Collectors.toList());
// resultado = [4, 16]

Cada paso transforma el flujo: [1,2,3,4,5] [2,4] [4,16] [4,16]. La lista original no se modifica.

¿Por qué usarlos? Evitan bucles manuales, son más legibles y permiten procesar datos en paralelo con .parallelStream().

Características modernas de Java (Parte 2)

Optional, var, Records y más.

Optional

Optional<T> es un contenedor que puede o no tener un valor. Ayuda a evitar NullPointerException al forzar a manejar la ausencia de valor.

Optional<String> opt = Optional.ofNullable("Hola");
opt.ifPresent(s -> System.out.println(s));

var (inferencia de tipos)

Desde Java 10, var permite declarar variables sin escribir el tipo explícito. El compilador infiere el tipo en tiempo de compilación. Útil para reducir código repetitivo.

var lista = new ArrayList<String>(); // tipo: ArrayList<String>
var num = 42; // tipo: int

Records

Desde Java 14 (estable en 16), los record son clases inmutables y transparentes para datos. Generan constructor, getters, equals, hashCode y toString automáticamente.

record Persona(String nombre, int edad) { }
Persona p = new Persona("Ana", 25);
System.out.println(p.nombre()); // getter automático

Switch expressions (Java 14+)

El switch ahora puede devolver un valor (con ->) y no necesita break. También soporta múltiples casos y yield para bloques.

String resultado = switch (dia) {
    case 1, 7 -> "Fin de semana";
    case 2, 3, 4, 5, 6 -> "Laborable";
    default -> "Inválido";
};

Nueva API de fechas (java.time)

Introducida en Java 8, reemplaza a Date y Calendar con clases inmutables como LocalDate, LocalTime, LocalDateTime, Period y Duration.

LocalDate hoy = LocalDate.now();
LocalDate futuro = hoy.plusDays(5);
int mes = hoy.getMonthValue();

¿Por qué usar estas características? Hacen tu código más conciso, seguro y expresivo. Java ha evolucionado para competir con lenguajes modernos, y estas herramientas son la prueba.
