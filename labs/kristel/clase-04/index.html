Introducción

En este laboratorio daremos el salto definitivo desde la consola de comandos hacia el desarrollo de aplicaciones de escritorio con ventanas e interfaces gráficas (GUI), donde el flujo deja de ser secuencial y pasa a estar controlado por los eventos del usuario (clics, tecleo, botones), tal como estudiamos en la Clase 4.

El paradigma visual se fundamenta en el estándar WIMP: construiremos una ventana JFrame, la organizaremos con contenedores JPanel y ordenadores de espacio (Layout Managers), y la llenaremos con componentes atómicos (JLabel, JTextField, JButton) que responderán a eventos.

Objetivo: Al finalizar este laboratorio, serás capaz de:
  • Entender el funcionamiento de una ventana creada con JFrame.
  • Organizar controles con contenedores JPanel y ordenadores de espacio (Layout Managers: BorderLayout, GridLayout, FlowLayout).
  • Leer datos de cajas de texto JTextField y ejecutar acciones en botones JButton mediante eventos (ActionListener).
  • Desplegar ventanas emergentes de alerta e información usando JOptionPane.
  • Lanzar aplicaciones gráficas de forma segura en el hilo de eventos de Swing (EDT) con SwingUtilities.invokeLater().

Paso 1: Crear el Repositorio en GitHub y Clonarlo con GitHub Desktop

1.1 Crear el Repositorio Remoto en GitHub

Primero crearemos el repositorio directamente en la página web de GitHub, para que exista una copia remota (en la nube) del proyecto. Sigue estos pasos:

  1. Entra a github.com e inicia sesión con tu cuenta.
  2. Haz clic en New.
  3. Repository name: Escribe Lab03_GUI.
  4. Description (opcional): Escribe algo como "Laboratorio 3 — Interfaces Gráficas con Java Swing".
  5. Selecciona la visibilidad: Public o Private (a su criterio).
  6. Haz clic en el botón verde Create repository.
  7. Haz clic en el botón verde <> Code y copia la URL del repositorio.
¿Qué es un repositorio remoto?

Es una copia del proyecto almacenada en los servidores de GitHub (en la nube). Sirve como respaldo central y como punto de colaboración: cualquier persona con acceso puede clonarlo, hacer cambios y sincronizarlos mediante push y pull. El repositorio local es la copia que trabajas en tu computadora; el remoto es la versión "oficial" compartida.

1.2 Clonar el Repositorio con GitHub Desktop

Atajo: desde la página del repositorio en GitHub también puedes hacer clic en Code → Open with GitHub Desktop y la aplicación se encargará de clonarlo automáticamente (Solo si inicias sesión en GitHub Desktop).
¿Qué significa clonar un repositorio?

Clonar significa descargar una copia exacta del repositorio remoto a tu máquina. A diferencia de "crear uno nuevo en GitHub Desktop", al clonar el repositorio local ya queda vinculado al remoto: GitHub Desktop sabrá a qué repositorio subir tus commits cuando hagas push.

Es una carpeta que IntelliJ reconoce como raíz del código fuente. Allí busca los paquetes y clases para compilarlos, autocompletar y detectar errores. Si no marcas src como Sources Root, IntelliJ no sabrá dónde empieza tu código y no podrá ejecutar el programa.

1.5 Crear el Paquete Raíz Lab03
  1. Haz Clic Derecho sobre la carpeta azul src.
  2. Selecciona: New → Package.
  3. Escribe Lab03 y presiona Enter.
¿Qué es un paquete en Java?

Un paquete es una carpeta lógica que agrupa clases relacionadas. En Java se declara con la palabra clave package al inicio de cada archivo. Nos permite organizar el proyecto en módulos y evitar conflictos de nombres, tal como vimos en el laboratorio anterior.

1.6 Crear los Subpaquetes modelo y vista

Para aplicar la separación de responsabilidades que estudiamos en la Clase 4, separaremos los datos de la interfaz gráfica:

  1. Haz Clic Derecho sobre el paquete Lab03 → New → Package. Escribe modelo y presiona Enter.
  2. Haz Clic Derecho sobre el paquete Lab03 → New → Package. Escribe vista y presiona Enter.
¿Por qué separamos el código en modelo y vista?

Esta separación es la base de la arquitectura Modelo-Vista (una simplificación de MVC). El paquete modelo contiene las clases de datos (sin ninguna lógica de ventanas), mientras que vista contiene la interfaz gráfica (Swing). Así, si mañana cambia la apariencia de la ventana, los datos no se ven afectados, y viceversa.

La jerarquía completa de archivos y carpetas debe verse así en el explorador de IntelliJ:

src/ └── Lab03/ ├── modelo/ // Almacenará la clase Estudiante (datos) ├── vista/ // Almacenará VentanaRegistro (Swing) └── Main.java // Almacenará el punto de inicio ejecutable

Paso 2: Crear el Modelo de Datos (Estudiante.java)

2.1 Crear el Archivo Estudiante.java en IntelliJ
  1. Haz Clic Derecho sobre el subpaquete modelo (ubicado dentro de Lab03).
  2. Selecciona: New → Java Class.
  3. Escribe el nombre Estudiante y presiona Enter.
2.2 Declarar el Paquete

Al inicio del archivo, escribe la línea que indica a qué paquete pertenece la clase:

// Indica que esta clase vive dentro del paquete Lab03.modelo package Lab03.modelo;
¿Qué hace esta línea?

Asigna la clase al espacio de nombres del paquete Lab03.modelo. Sin esta línea, IntelliJ marcaría un error porque la clase no coincidiría con la ubicación de la carpeta donde la creamos.

2.3 Declarar la Clase Pública Estudiante
// Declara la clase pública Estudiante (molde para crear objetos de estudiantes) public class Estudiante {
¿Qué es una clase?

Es una plantilla o molde para crear objetos. Estudiante definirá qué datos tiene cada estudiante y qué puede hacer. Es la clase del modelo, por lo que NO contiene nada de Swing.

2.4 Declarar los Atributos Privados

Dentro de la clase, declara los tres datos que caracterizan a un estudiante. Deben ser private para garantizar el encapsulamiento:

// Atributo privado para el número de carnet (encapsulado) private String carnet; // Atributo privado para el nombre completo del estudiante private String nombre; // Atributo privado para la carrera que cursa private String carrera;

Recuerda: String con mayúscula, y private para que solo la clase pueda acceder directamente.

2.5 Escribir el Constructor

El constructor recibe carnet, nombre y carrera, y los asigna a los atributos:

// Constructor: se ejecuta con 'new' para inicializar los 3 atributos public Estudiante(String carnet, String nombre, String carrera) { // 'this.carnet' es el atributo; 'carnet' es el valor recibido en el parámetro this.carnet = carnet; // Asigna el nombre recibido al atributo de la clase this.nombre = nombre; // Asigna la carrera recibida al atributo de la clase this.carrera = carrera; }
¿Qué significa this.carnet = carnet;?

Significa: "al atributo de la clase (this.carnet, el private String carnet de arriba) asígnale el valor del parámetro del constructor (carnet)". Sin this, Java no sabría a cuál de los dos te refieres porque tienen el mismo nombre.

2.6 Agregar los Getters

Para que la capa de vista pueda leer los datos (por ejemplo, para mostrarlos en un mensaje), proporcionamos métodos de consulta:

// Getter público que permite leer el carnet public String getCarnet() { return carnet; } // Getter público que permite leer el nombre public String getNombre() { return nombre; } // Getter público que permite leer la carrera public String getCarrera() { return carrera; }
¿Por qué no accedemos directo a carnet?

Por el encapsulamiento: los atributos son private, así que la única forma de leerlos desde fuera de la clase es mediante métodos públicos (los getters). Esto nos permite controlar el acceso y modificar la implementación interna sin romper a quienes usan la clase.

2.7 Sobrescribir toString()

Para que al imprimir un estudiante se vea una cadena legible (en vez de la dirección de memoria), sobrescribimos toString():

@Override // Sobrescribe toString() para imprimir el estudiante de forma legible public String toString() { // Concatena carnet, nombre y carrera con el formato "carnet - nombre (carrera)" return carnet + " - " + nombre + " (" + carrera + ")"; }
¿Qué hace la anotación @Override?

Le indica al compilador que estamos sobrescribiendo un método que ya existe en la superclase (Object). Es opcional, pero recomendada: si nos equivocamos en la firma, el compilador nos avisa con un error.

Paso 3: Crear la Ventana — Estructura y Contenedores (VentanaRegistro.java)

3.1 Crear el Archivo VentanaRegistro.java en IntelliJ
  1. Haz Clic Derecho sobre el subpaquete vista (ubicado dentro de Lab03).
  2. Selecciona: New → Java Class.
  3. Escribe el nombre VentanaRegistro y presiona Enter.

Esta clase es la Vista de nuestro programa: contiene únicamente componentes Swing y delega en el modelo los datos.

3.2 Declarar el Paquete y las Importaciones
// Paquete al que pertenece esta clase (la capa de vista) package Lab03.vista; // Importa el modelo Estudiante para crear objetos con los datos ingresados import Lab03.modelo.Estudiante; // Importa todos los componentes gráficos de Swing (JFrame, JPanel, JButton...) import javax.swing.*; // Importa las herramientas de maquetación AWT (BorderLayout, Font, Color...) import java.awt.*;
¿Qué importa cada línea?

import javax.swing.*; trae todos los componentes gráficos (JFrame, JPanel, JLabel, JTextField, JButton...).
import java.awt.*; trae las herramientas de maquetación AWT (BorderLayout, Font, Color...).
import Lab03.modelo.Estudiante; trae la clase del modelo para poder crear estudiantes con los datos ingresados.

3.3 Declarar la Clase y los Componentes Atómicos
// 'extends JFrame': esta clase HEREDA todo el comportamiento de una ventana public class VentanaRegistro extends JFrame { // Caja de texto donde el usuario escribe el carnet private JTextField txtCarnet; // Caja de texto para el nombre completo private JTextField txtNombre; // Caja de texto para la carrera private JTextField txtCarrera; // Botón para procesar e inscribir al estudiante private JButton btnGuardar; // Botón para borrar las cajas de texto private JButton btnLimpiar;
¿Qué significa extends JFrame?

Heredar de JFrame significa que nuestra clase es una ventana y adquiere todos sus poderes: título, tamaño, botones de cerrar/minimizar, etc. Los JTextField y JButton son componentes atómicos (el nivel inferior de la jerarquía visual): no pueden contener otros componentes, solo interactuar con el usuario.

3.4 Configurar la Ventana

Dentro del constructor, definimos el título, el tamaño, el comportamiento al cerrar y la posición:

// Título que aparece en la barra superior de la ventana setTitle("Sistema de Gestión de Estudiantes — UNA"); // Dimensiones: 450 píxeles de ancho por 300 de alto setSize(450, 300); // Al tocar la 'X', el programa se detiene por completo setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); // Centra la ventana en la pantalla del monitor setLocationRelativeTo(null);
¿Para qué sirve setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE)?

Define qué pasa cuando el usuario toca la X de la ventana. Con EXIT_ON_CLOSE el programa Java se detiene por completo. Si lo omitieras, la ventana se cerraría pero el programa seguiría ejecutándose en segundo plano sin que lo veas.

¿Qué hace setLocationRelativeTo(null)?

Posiciona la ventana en el centro geométrico de la pantalla. El valor null le indica a Java: "no lo centres respecto a otra ventana, sino respecto al monitor".

3.5 Crear el Contenedor Principal con BorderLayout
// Contenedor principal con BorderLayout (5 regiones) y 10px de separación JPanel panelPrincipal = new JPanel(new BorderLayout(10, 10)); // Margen interno de 15px para no pegar el contenido con el borde panelPrincipal.setBorder(BorderFactory.createEmptyBorder(15, 15, 15, 15));
¿Qué es un Layout Manager?

Es un algoritmo de distribución que coloca automáticamente los componentes dentro de un contenedor. BorderLayout divide el área en 5 regiones: NORTH, SOUTH, EAST, WEST y CENTER. Los números (10, 10) son el espacio horizontal y vertical entre regiones.

¿Por qué un JPanel intermedio?

El JFrame solo puede tener un contenido principal. Al agrupar todo dentro de un JPanel con un layout, podemos organizar las cajas y botones en zonas (arriba, centro, abajo) y luego "pegar" el panel completo a la ventana. Esta es la jerarquía de contenedores de la Clase 4: JFrame (nivel alto) → JPanel (nivel intermedio) → componentes atómicos (nivel inferior).

3.6 Crear la Etiqueta de Título con JLabel
// Etiqueta de texto centrada para el título del formulario JLabel lblTitulo = new JLabel("Inscripción de Estudiantes", SwingConstants.CENTER); // Aplica tipografía en negrita (BOLD) y tamaño 18 lblTitulo.setFont(new Font("Nunito", Font.BOLD, 18)); // Color del texto: rojo institucional UNA (RGB: 200, 16, 46) lblTitulo.setForeground(new Color(200, 16, 46)); // Lo coloca en la región superior (NORTH) del panel principal panelPrincipal.add(lblTitulo, BorderLayout.NORTH);
¿Qué es un JLabel?

Es un componente atómico que muestra texto estático (no editable). SwingConstants.CENTER lo centra horizontalmente; setFont cambia la tipografía (negrita, tamaño 18) y setForeground el color del texto, aquí el rojo institucional UNA (RGB: 200, 16, 46). Finalmente lo colocamos en la región NORTH (superior) del panel.

3.7 Crear el Formulario con GridLayout y JTextField

El formulario es una cuadrícula de 3 filas × 2 columnas (etiqueta + caja de texto por campo):

// Panel del formulario en cuadrícula de 3 filas x 2 columnas con 8px de separación JPanel panelFormulario = new JPanel(new GridLayout(3, 2, 8, 8)); // [Fila 1] Etiqueta + caja de texto para el carnet panelFormulario.add(new JLabel("Carnet:")); txtCarnet = new JTextField(); panelFormulario.add(txtCarnet); // [Fila 2] Etiqueta + caja de texto para el nombre completo panelFormulario.add(new JLabel("Nombre Completo:")); txtNombre = new JTextField(); panelFormulario.add(txtNombre); // [Fila 3] Etiqueta + caja de texto para la carrera panelFormulario.add(new JLabel("Carrera:")); txtCarrera = new JTextField(); panelFormulario.add(txtCarrera); // Coloca el formulario en el área central (CENTER) del panel principal panelPrincipal.add(panelFormulario, BorderLayout.CENTER);
¿Cómo funciona GridLayout(3, 2, 8, 8)?

Crea una cuadrícula de 3 filas y 2 columnas donde todos los componentes tienen el mismo tamaño. Los 8, 8 son los píxeles de separación horizontal y vertical entre celdas. Los componentes se agregan en orden: fila 1 (etiqueta Carnet, caja), fila 2 (etiqueta Nombre, caja), fila 3 (etiqueta Carrera, caja). El panel del formulario ocupa la región CENTER del panel principal.

¿Qué es un JTextField?

Es una caja de texto de una sola línea donde el usuario escribe datos. Leeremos su contenido con getText() y lo borraremos con setText("").

3.8 Crear la Zona de Botones con FlowLayout y JButton
// Panel con FlowLayout alineado a la derecha, separación horizontal de 10px JPanel panelBotones = new JPanel(new FlowLayout(FlowLayout.RIGHT, 10, 0)); // Botón para borrar los campos (etiqueta 'Limpiar') btnLimpiar = new JButton("Limpiar"); // Botón para procesar e inscribir (etiqueta 'Guardar Estudiante') btnGuardar = new JButton("Guardar Estudiante"); // Agrega ambos botones al panel secundario panelBotones.add(btnLimpiar); panelBotones.add(btnGuardar); // Coloca el panel de botones en la región inferior (SOUTH) panelPrincipal.add(panelBotones, BorderLayout.SOUTH);
¿Cómo funciona FlowLayout?

Coloca los componentes uno tras otro en línea (como palabras en un párrafo) y, si no caben, baja a la siguiente línea. Con FlowLayout.RIGHT los alinea a la derecha, y (10, 0) define la separación horizontal y vertical. El panel de botones va en la región SOUTH (inferior) del panel principal.

Paso 4: Conectar los Eventos de los Botones

Ahora daremos vida a la ventana. En el paradigma visual el flujo es controlado por eventos: el programa queda a la espera de que el usuario haga clic, y solo entonces ejecuta el código asociado a ese clic.

4.1 ¿Qué es un evento?

Un evento es una señal que el sistema genera cuando el usuario interactúa (clic en un botón, tecla presionada, etc.). En Swing usamos el patrón de delegación: registramos un "oyente" (listener) en un componente y, cuando ocurre el evento, el oyente se encarga de ejecutar la respuesta.

¿Qué es un ActionListener?

Es una interfaz funcional de Java que define el método actionPerformed(ActionEvent e). Al registrarla con boton.addActionListener(...), el código dentro del método se ejecuta cada vez que el usuario presiona el botón.

4.2 El Botón Guardar con una Lambda
// Registra un oyente: el código se ejecuta al hacer clic en 'Guardar' btnGuardar.addActionListener(e -> { // Lee el texto escrito en la caja del carnet String carnet = txtCarnet.getText(); // Lee el texto escrito en la caja del nombre String nombre = txtNombre.getText(); // Lee el texto escrito en la caja de la carrera String carrera = txtCarrera.getText(); });
¿Qué es una lambda (e -> ...)?

Es una forma abreviada de escribir una clase anónima. e -> { ... } significa: "cuando ocurra el evento e, ejecuta lo que está entre llaves". Es la programación funcional que ya usamos en el laboratorio anterior.

¿Qué hace getText()?

Lee el texto que el usuario escribió dentro de cada JTextField y lo devuelve como un String. Ese texto es lo que después enviaremos al modelo.

4.3 Validar los Campos Vacíos con JOptionPane
// Si alguna de las tres cadenas está vacía... if (carnet.isEmpty() || nombre.isEmpty() || carrera.isEmpty()) { // Muestra una ventana emergente de advertencia (WARNING) JOptionPane.showMessageDialog(this, "Por favor complete todos los campos.", "Campos Incompletos", JOptionPane.WARNING_MESSAGE); }
¿Qué es JOptionPane?

Es una clase de Swing que muestra ventanas emergentes (pop-ups) sin necesidad de crear un JFrame nuevo. showMessageDialog(...) muestra un mensaje con un ícono: aquí WARNING_MESSAGE (advertencia). El primer parámetro this indica la ventana "padre" que centrará el diálogo.

¿Qué hace isEmpty()?

Devuelve true si el String está vacío (""). Con el operador || (o) validamos que ninguno de los tres campos esté vacío antes de guardar.

4.4 Crear el Objeto Estudiante y Confirmar
// Si todos los campos están completos... else { // Crea el objeto Estudiante en la capa de modelo con los datos leídos Estudiante nuevo = new Estudiante(carnet, nombre, carrera); // Muestra una ventana emergente informativa con los datos del registro JOptionPane.showMessageDialog(this, "Estudiante registrado con éxito:\n" + nuevo.toString(), "Registro Exitoso", JOptionPane.INFORMATION_MESSAGE); }
¿Por qué creamos el objeto Estudiante?

La vista no debe guardar lógica: solo toma los textos y los convierte en un objeto del modelo usando new Estudiante(...). Luego el mensaje usa nuevo.toString() para mostrar los datos con el formato que definimos en el Paso 2.

4.5 El Botón Limpiar
// Registra un oyente: se ejecuta al hacer clic en 'Limpiar' btnLimpiar.addActionListener(e -> { // Blanquea la caja del carnet txtCarnet.setText(""); // Blanquea la caja del nombre txtNombre.setText(""); // Blanquea la caja de la carrera txtCarrera.setText(""); });
¿Qué hace setText("")?

Reemplaza el contenido del JTextField por una cadena vacía, es decir, blanquea la caja de texto para que el usuario pueda volver a escribir desde cero.

4.6 Ensamblar el Contenido de la Ventana
// Ensambla el panel principal como contenido visible de la ventana this.add(panelPrincipal);

Al final del constructor, agregamos el panel principal ya construido como contenido visible del JFrame.

¿Por qué un JPanel intermedio y no agregar todo directo?

Por la jerarquía de contenedores: el JFrame solo admite un contenido. Al agrupar los componentes en JPanel con sus layouts (NORTH, CENTER, SOUTH) logramos una ventana ordenada y redimensionable, en vez de una pila desordenada de componentes.

Paso 5: Crear el Punto de Entrada (Main.java)

5.1 Crear el Archivo Main.java en IntelliJ
  1. Haz Clic Derecho directamente sobre el paquete raíz Lab03.
  2. Selecciona: New → Java Class.
  3. Escribe el nombre Main y presiona Enter.
5.2 Declarar el Paquete y las Importaciones
// Paquete principal de la aplicación package Lab03; // Importa la ventana creada en el paquete vista import Lab03.vista.VentanaRegistro; // Importa utilidades de Swing para lanzar la interfaz en el hilo correcto (EDT) import javax.swing.SwingUtilities;
¿Por qué importamos SwingUtilities?

Es la clase de utilidades de Swing que nos permite manejar los hilos de ejecución de forma segura. Con SwingUtilities.invokeLater(...) lanzamos la creación de la interfaz en el hilo correcto.

5.3 El Método main y el Hilo de Eventos (EDT)
// Método principal: punto de entrada que busca la JVM public static void main(String[] args) { // Lanza la creación de la GUI en el hilo de eventos de Swing (EDT) SwingUtilities.invokeLater(() -> { // Construye la ventana llamando a su constructor VentanaRegistro ventana = new VentanaRegistro(); // La hace visible (por defecto las ventanas nacen invisibles) ventana.setVisible(true); }); }
¿Qué es el EDT y por qué usamos invokeLater?

El EDT (Event Dispatch Thread) es el hilo especial de Swing que procesa los eventos y dibuja la interfaz. SwingUtilities.invokeLater(...) le pide a ese hilo: "cuando puedas, ejecuta esto". Así la ventana se crea y se muestra en el hilo correcto, evitando problemas de concurrencia y ventanas "congeladas".

¿Por qué setVisible(true)?

Las ventanas de Swing nacen invisibles. Sin esta línea el programa se ejecutaría correctamente pero no verías ninguna ventana en pantalla.

  6. Visibilidad y EDT: ¿Qué sucede si eliminamos la línea ventana.setVisible(true); del archivo Main.java? ¿Y si quitas SwingUtilities.invokeLater(...)?
