Java vs JavaScript

Son como carro y carroza: suenan parecido, pero son muy distintos.

Java

  • Lenguaje compilado → se convierte a bytecode que corre en la JVM.
  • Orientado a objetos desde el inicio (todo es clase).
  • Tipado estático → las variables tienen un tipo fijo (int x = 5;).
  • Se usa para: aplicaciones empresariales, Android, backend, sistemas grandes.
  • Corre en un servidor o en una máquina virtual.
  • WORA (Write Once, Run Anywhere).
public class Hola { public static void main(String[] a) { System.out.println("Hola"); } }

JavaScript

  • Lenguaje interpretado → el navegador o Node.js lo ejecuta línea por línea.
  • Multiparadigma → funcional, orientado a objetos, imperativo.
  • Tipado dinámico → una variable puede cambiar de tipo (let x = 5; x = "hola";).
  • Se usa para: frontend web (interactividad en páginas), backend con Node.js.
  • Corre en el navegador (del lado del cliente) o en servidores.
  • No tiene relación con Java más que el nombre (por marketing).
console.log("Hola"); // JS no necesita clases para esto

Analogía: Java es como un tren (todo planificado, rígido, potente). JavaScript es como un carro de montaña rusa (flexible, ágil, se adapta sobre la marcha). Ambos te llevan a destino, pero de formas muy diferentes.

Array vs ArrayList

Ambos guardan múltiples elementos, pero con reglas muy diferentes.

Array Tamaño fijo
ArrayEjemplo.java 
int[] numeros = new int[5]; // Tamaño fijo: 5
numeros[0] = 10;
numeros[1] = 20;
// numeros[5] = 30; → ERROR: índice fuera de rango

String[] nombres = {"Ana", "Carlos"}; // Tamaño 2
  • ✓ Rápido, memoria contigua.
  • ✓ Soporta tipos primitivos (int, double, etc.).
  • ✗ Tamaño fijo al crearlo.
  • ✗ No tiene métodos para agregar/eliminar fácilmente.
ArrayList Tamaño dinámico
ArrayListEjemplo.java 
import java.util.ArrayList;

ArrayList<Integer> nums = new ArrayList<>(); // Tamaño 0
nums.add(10);   // ahora tamaño 1
nums.add(20);   // tamaño 2
nums.add(30);   // tamaño 3 → crece solo
nums.remove(1);  // elimina el 20, tamaño 2

String nombre = nums.get(0); // "Ana"
  • ✓ Tamaño dinámico (crece y se encoge).
  • ✓ Métodos útiles: add(), remove(), get(), size().
  • ✗ Solo guarda objetos (no primitivos, usa wrappers).
  • ✗ Un poco más lento que un array por la gestión interna.

Regla de oro: Si sabés cuántos elementos vas a tener y no va a cambiar → usá array. Si la lista puede crecer o encogerse → usá ArrayList.

for tradicional vs foreach (enhanced for)

Dos formas de recorrer, cada una con su propósito.

for Tradicional 
for (int i = 0; i < lista.size(); i++) {
    String elemento = lista.get(i);
    System.out.println(elemento);
}
  • ✓ Tenés control total del índice.
  • ✓ Podés modificar la lista mientras la recorrés (con cuidado).
  • ✓ Útil cuando necesitás el índice para algo.
  • ✗ Más verboso (más código).
foreach Enhanced for 
for (String elemento : lista) {
    System.out.println(elemento);
}
  • ✓ Más legible y menos propenso a errores.
  • ✓ No necesitás el índice, solo el elemento.
  • ✗ No podés modificar la lista mientras la recorrés (tiraría ConcurrentModificationException).
  • ✗ No tenés acceso al índice.

Regla de oro: Si solo necesitás leer los elementos → usá foreach. Si necesitás el índice o modificar la lista → usá el for tradicional.

@Override y las anotaciones

Son etiquetas que le dan instrucciones al compilador.

¿Qué es una anotación?

Una anotación es un metadata que se puede agregar a clases, métodos, variables, etc. Empiezan con @. No cambian la lógica del programa, pero le dan información adicional al compilador, al framework o a herramientas.

@Override
@Deprecated
@SuppressWarnings

Java tiene anotaciones predefinidas, y también podés crear las tuyas.

@Override en detalle

@Override le dice al compilador: "Este método está sobrescribiendo (override) un método de la clase padre o de una interfaz"[reference:0]. Es opcional pero muy recomendado porque:

  • • Previene errores: si escribís mal el nombre, el compilador te avisa[reference:1].
  • • Mejora la legibilidad: otros programadores saben que es un override.
class Animal {
    public void hacerSonido() { ... }
}
class Perro extends Animal {
    @Override  // ← esto es una anotación
    public void hacerSonido() {
        System.out.println("Guau");
    }
}

¿Qué pasa si no usás @Override? El código funciona igual. Pero si te equivocás en el nombre (ej. hacerSonido2), el compilador no se queja y crea un método nuevo en vez de sobrescribir. @Override te salva de ese error.

¿Por qué la carpeta src?

No es magia, es organización y convenciones.

Estructura de proyectos Java

En Java (y en muchos lenguajes), se sigue una estructura de carpetas estándar para organizar el código fuente, los recursos y los archivos compilados. 

mi-proyecto/
├── src/           ← Código fuente (.java)
│   └── com/
│       └── una/
│           └── progra3/
│               └── Main.java
├── out/          ← Archivos compilados (.class)
└── lib/          ← Bibliotecas externas (.jar)

La carpeta src (source) es donde va todo tu código Java. Los archivos .class (bytecode) se generan en otra carpeta (como out o target).

Source Root: ¿qué es y para qué sirve?

En IntelliJ, marcar una carpeta como Source Root (Mark Directory as → Sources Root) le dice al IDE:

  • • “Aquí está mi código fuente” → el compilador va a buscar archivos .java ahí.
  • • “Resolvé los imports desde aquí” → los paquetes se resuelven desde esta raíz.
  • • “No compilez nada que esté fuera de aquí” → separa código de otros archivos.
// Si src/ es Source Root, entonces:
package com.una.progra3; // ← ruta: src/com/una/progra3/

¿Por qué no hay que importar las clases al main? Porque si están en el mismo paquete o en un paquete que está en el Source Root, el compilador las encuentra automáticamente. Solo necesitás import si la clase está en otro paquete.

¿Por qué IntelliJ solo corre la clase con main?

La JVM necesita un punto de entrada.

El método main es la puerta de entrada

Cuando ejecutás java MiClase, la JVM:

  1. Carga la clase MiClase en memoria.
  2. Busca un método public static void main(String[] args).
  3. Si lo encuentra, lo ejecuta. Si no, tira un error.
Error: Main method not found in class MiClase

¿Por qué tiene que ser static? Porque la JVM necesita llamar al método sin crear un objeto de la clase. Si no fuera static, tendría que hacer new MiClase().main(), pero no sabe cómo construir el objeto.

¿Y las otras clases?

Las clases que no tienen main son como plantillas o componentes. No se pueden ejecutar por sí solas porque la JVM no sabe qué hacer con ellas.

  • • Estudiante → define qué es un estudiante, pero no "hace" nada por sí mismo.
  • • Calculadora → tiene métodos para sumar, pero no se ejecuta sola.
  • • Main → usa a Estudiante y Calculadora para orquestar el programa.
// Main.java — el director de orquesta
public class Main {
    public static void main(String[] a) {
        Estudiante e = new Estudiante("Ana");
        System.out.println(e.getNombre());
    }
}

Analogía: El main es como el chef ejecutivo en una cocina. Las otras clases son los ingredientes y recetas. El chef las usa para preparar el plato (el programa). Sin chef, los ingredientes no se cocinan solos.

Genéricos (Generics)

Escribí código que funcione con cualquier tipo de dato.

¿Por qué existen?

Antes de Java 5 (2004), no había genéricos. Si querías una lista que guardara Integer, tenías que hacer casting explícito cada vez que sacabas un elemento[reference:2]. 

// Sin genéricos (Java 4 y anteriores)
List lista = new ArrayList();
lista.add(5);
Integer num = (Integer) lista.get(0); // ← casting obligatorio

Problemas: el casting es propenso a errores y el compilador no podía verificar que el tipo fuera correcto[reference:3].

La solución: Genéricos

Los genéricos te permiten parametrizar clases, interfaces y métodos con un tipo que se define al usarlos[reference:4]. 

// Con genéricos (Java 5+ )
List<Integer> lista = new ArrayList<>();
lista.add(5);
Integer num = lista.get(0); // ← sin casting, el compilador sabe que es Integer
  • • Seguridad en tiempo de compilación → menos errores en runtime[reference:5].
  • • Código más legible → el tipo queda explícito.
  • • Reutilización → una misma clase sirve para varios tipos.

Clases y métodos genéricos

Creá tus propias plantillas reutilizables.

Clase Genérica 
public class Caja<T> {  // T = tipo parametrizado
    private T contenido;

    public void poner(T algo) {
        this.contenido = algo;
    }

    public T sacar() {
        return contenido;
    }
}

// Uso:
Caja<String> cajaTexto = new Caja<>();
cajaTexto.poner("Hola");
String s = cajaTexto.sacar(); // ← sin casting

Caja<Integer> cajaNum = new Caja<>();
cajaNum.poner(42);
Integer n = cajaNum.sacar();

T es un placeholder. Podés usar cualquier nombre: T, E, K, V, etc.

Método Genérico 
public class Utilidades {
    // Método genérico: el tipo T se define en la llamada
    public static <T> T obtenerPrimero(List<T> lista) {
        if (lista.isEmpty()) return null;
        return lista.get(0);
    }
}

// Uso:
List<String> nombres = List.of("Ana", "Carlos");
String primero = Utilidades.obtenerPrimero(nombres);

List<Integer> nums = List.of(1, 2, 3);
Integer primeroNum = Utilidades.obtenerPrimero(nums);

El <T> antes del tipo de retorno indica que es un método genérico[reference:6].

Analogía: Una clase genérica es como un molde para galletas. El molde es el mismo, pero podés usarlo con diferentes masas (tipos). El resultado siempre tiene la misma forma, pero con distinto sabor.

Expresiones Lambda

Funciones anónimas que podés pasar como si fueran datos.

¿Qué es una lambda?

Una expresión lambda es un bloque de código que se puede pasar como parámetro a un método[reference:7]. Es como una función sin nombre que podés escribir en el lugar donde la necesitás[reference:8].

(parámetros) -> expresión
(parámetros) -> { código }

Ejemplo clásico: (x, y) -> x + y → toma dos números y devuelve la suma.

Ejemplo: forEach con lambda 

ArrayList<Integer> nums = new ArrayList<>();
nums.add(1); nums.add(2); nums.add(3);

// Con foreach tradicional
for (Integer n : nums) {
    System.out.println(n);
}

// Con lambda (Java 8+)
nums.forEach(n -> System.out.println(n));

// Con lambda y bloque de código
nums.forEach(n -> {
    int cuadrado = n * n;
    System.out.println(n + "² = " + cuadrado);
});

El método forEach() recibe una lambda y la ejecuta para cada elemento[reference:9].

Analogía: Una lambda es como una receta que le das al chef. No le decís "hacé esto, después esto, después esto" (código tradicional). Le decís "tomá esta receta (lambda) y aplicala a cada ingrediente".

Sintaxis de Lambdas

Variaciones según la cantidad de parámetros y complejidad.

1 parámetro, 1 expresión

n -> n * 2

El resultado se devuelve automáticamente.

Varios parámetros

(a, b) -> a + b

Paréntesis obligatorios con más de 1 parámetro.

Bloque de código

(x, y) -> {
  int z = x + y;
  return z;
}

Usá return si hay varias líneas[reference:10].

Ejemplo: ordenar una lista con lambda

List<String> nombres = List.of("Carlos", "Ana", "Luis");

// Ordenar por longitud (lambda)
Collections.sort(nombres, (a, b) -> a.length() - b.length());

// Imprimir con lambda
nombres.forEach(n -> System.out.println(n));

El método sort() recibe un Comparator que definimos con una lambda.

Stream API

Procesá colecciones como si fueran un flujo de datos.

¿Qué es un Stream?

Un Stream es una secuencia de elementos que soporta operaciones funcionales (como filter, map, reduce)[reference:11]. No almacena datos, solo los procesa.

  • • Declarativo: decís qué querés hacer, no cómo hacerlo[reference:12].
  • • Lazy: las operaciones intermedias no se ejecutan hasta que hay una operación terminal.
  • • Encadenable: podés encadenar operaciones como filter().map().collect().

Ejemplo: filtrar y transformar 

List<Integer> nums = List.of(1, 2, 3, 4, 5, 6);

// Imperativo (for + if)
List<Integer> pares = new ArrayList<>();
for (Integer n : nums) {
    if (n % 2 == 0) {
        pares.add(n * n);
    }
}

// Con Stream (declarativo)
List<Integer> paresCuadrado = nums.stream()
    .filter(n -> n % 2 == 0)    // solo pares
    .map(n -> n * n)            // elevar al cuadrado
    .collect(Collectors.toList()); // recolectar en lista

El código con Stream es más legible y expresa intención, no implementación.

Operaciones comunes con Streams

Las herramientas que más vas a usar.

filter

Selecciona elementos que cumplen una condición.

.filter(n -> n > 5)

map

Transforma cada elemento en otro valor.

.map(n -> n * 2)

collect

Recolecta el resultado en una lista, set, etc.

.collect(Collectors.toList())

forEach

Ejecuta una acción para cada elemento (terminal).

.forEach(n -> System.out.println(n))

sorted

Ordena los elementos.

.sorted()

reduce

Reduce a un solo valor (suma, producto, etc.).

.reduce(0, (a, b) -> a + b)

Ejemplo completo: filtrar, ordenar, transformar y recolectar

List<String> nombres = List.of("Ana", "Carlos", "Luis", "María");

List<String> resultado = nombres.stream()
    .filter(n -> n.length() > 3)          // solo nombres largos
    .map(String::toUpperCase)           // a mayúsculas
    .sorted()                          // orden alfabético
    .collect(Collectors.toList());

System.out.println(resultado); // [CARLOS, MARÍA]

Nota: String::toUpperCase es una referencia a método, una forma abreviada de lambda.

Novedades de Java 8 → 21

El lenguaje ha evolucionado mucho. Estas son las versiones LTS (soporte a largo plazo).

Java 8 (2014)

  • • Lambdas y Stream API [reference:13]
  • • Optional para evitar NullPointerException
  • • Nueva API de fechas: LocalDate, LocalTime
  • • Métodos default en interfaces

Java 11 (2018) — LTS

  • • var para inferencia de tipos locales[reference:14]
  • • Nuevo HTTP Client (más moderno)
  • • Métodos útiles en String: isBlank(), lines()
  • • Optional mejorado

Java 17 (2021) — LTS

  • • Records → clases de datos inmutables (menos boilerplate)[reference:15]
  • • Sealed classes → control de herencia
  • • Pattern Matching para instanceof
  • • Switch expresiones mejoradas

Java 21 (2023) — LTS

  • • Virtual Threads → concurrencia más ligera[reference:16]
  • • Pattern Matching para switch
  • • Sequenced Collections → colecciones con orden
  • • String templates (preview)
  • • main puede ser void main() sin static (clases implícitas)

¿Cuál usar? En producción, lo más común es Java 11 o 17 (LTS). Java 21 es el futuro. En este curso usamos Java 17+ para aprovechar las mejoras.
