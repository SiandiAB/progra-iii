Laboratorio 5a — Taquilla de Cine

Arquitectura de 3 Capas y Eventos GUI

Programación III — Semana 5: Aplicaciones Dirigidas por Eventos (Práctica Guiada)

IntelliJ GUI Designer Modelo-Vista-Servicio ArrayList ActionListener KeyAdapter & MouseAdapter
Duración estimada: 1 hora  ·  Individual / Parejas

Introducción

En este laboratorio construiremos una aplicación de escritorio para una taquilla de cine usando Java Swing. Aplicaremos la arquitectura de 3 capas (Modelo, Servicio, Vista) y utilizaremos eventos para manejar las interacciones del usuario: clics en botones, teclado (Enter) y ratón (hover).

Trabajaremos con IntelliJ IDEA y su GUI Designer para crear el formulario visualmente, y aprenderemos a cargar imágenes desde el classpath.

Objetivo: Al finalizar, serás capaz de:
  • Diseñar una interfaz gráfica usando el GUI Designer de IntelliJ.
  • Implementar la separación de responsabilidades en 3 capas.
  • Manejar eventos de acción (ActionListener), teclado (KeyAdapter) y ratón (MouseAdapter).
  • Validar entradas del usuario con try-catch y JOptionPane.
  • Cargar imágenes desde el classpath para mostrar logos.

Paso 1: Crear el Proyecto y Estructura de Paquetes

1.1 Crear un nuevo proyecto Java en IntelliJ
  1. Abrir IntelliJ IDEA y seleccionar New Project.
  2. Elegir Java con el JDK instalado (versión 11 o superior).
  3. Nombre del proyecto: TaquillaCine.
  4. Crear el proyecto.
1.2 Crear la carpeta src y marcarla como Sources Root
  1. En el panel de proyecto, hacer clic derecho sobre la carpeta raíz del proyecto.
  2. Seleccionar New → Directory y escribir src.
  3. Hacer clic derecho sobre src → Mark Directory as → Sources Root.
La carpeta src quedará de color azul, indicando que es la raíz del código fuente.
¿Por qué "Sources Root"?

Al marcar la carpeta como Sources Root, estamos diciendo a IntelliJ: "Aquí empieza mi código Java". El IDE usará esta carpeta como punto de partida para buscar clases, lo que permite que los nombres de los paquetes se resuelvan correctamente.

1.3 Crear los paquetes modelo, servicio y vista
  1. Hacer clic derecho sobre src → New → Package.
  2. Escribir modelo y presionar Enter.
  3. Repetir para crear servicio y vista.
¡Atención! ¿Carpeta (Directory) o Paquete (Package)?

Esta es la confusión más común: como los paquetes se ven como carpetas en el explorador de archivos, muchas veces intentamos hacer clic en New → Directory.
Regla de oro: Si estás creando una carpeta dentro de src (que es azul), siempre debes usar New → Package. Java necesita que se definan como paquetes para poder organizar las clases. La opción Directory se usa para carpetas que no contienen código Java (por ejemplo, las imágenes y archivos de configuración que veremos en el siguiente paso).

¿Por qué separamos en paquetes?

Para mantener la arquitectura de 3 capas: los datos (modelo), la lógica de negocio (servicio) y la interfaz de usuario (vista). Esto evita el código espagueti y facilita el mantenimiento.

1.4 Crear la carpeta resources para imágenes
  1. Hacer clic derecho sobre la raíz del proyecto → New → Directory → resources. Aquí sí usamos Directory.
  2. Hacer clic derecho sobre resources → Mark Directory as → Resources Root.
  3. Dentro de resources, crear la carpeta img.

Descargar una imagen de logo de cine (o usar la de la UNA) y colocarla dentro de resources/img/ con el nombre logo.png.

¿Por qué en resources usamos Directory?

La carpeta resources contiene archivos estáticos (imágenes, textos, configuraciones). No son clases de Java, por lo tanto no necesitan ser tratados como paquetes. Aquí, la opción Directory es la correcta para no confundir al compilador.

Paso 2: Crear la Capa de Modelo (Boleto.java)

2.1 Crear la clase Boleto en el paquete modelo
  1. Clic derecho sobre modelo → New → Java Class.
  2. Escribir Boleto y presionar Enter.
2.2 Escribir el código de la clase
// Paquete modelo package modelo; // Clase que representa un boleto de cine public class Boleto { private String pelicula; private String sala; private double precio; // Constructor public Boleto(String pelicula, String sala, double precio) { this.pelicula = pelicula; this.sala = sala; this.precio = precio; } // Getters public String getPelicula() { return pelicula; } public String getSala() { return sala; } public double getPrecio() { return precio; } @Override public String toString() { return pelicula + " - Sala " + sala + " - ¢" + precio; } }
¿Qué contiene la clase Boleto?

Es un POJO que representa los datos de un boleto. No tiene lógica de negocio, solo almacena información.

Paso 3: Crear la Capa de Servicio (TaquillaService.java)

3.1 Crear la clase TaquillaService en el paquete servicio
  1. Clic derecho sobre servicio → New → Java Class.
  2. Escribir TaquillaService.
3.2 Implementar la lógica de negocio
package servicio; import modelo.Boleto; import java.util.ArrayList; public class TaquillaService { private ArrayList<Boleto> boletos; public TaquillaService() { boletos = new ArrayList<>(); } // Agregar boleto a la lista public void venderBoleto(Boleto boleto) { boletos.add(boleto); } // Calcular el total de ingresos public double calcularTotal() { double total = 0; for (Boleto b : boletos) { total += b.getPrecio(); } return total; } // Obtener la cantidad de boletos vendidos public int contarBoletos() { return boletos.size(); } }
¿Qué hace TaquillaService?

Esta clase gestiona la colección de boletos en un ArrayList. Proporciona métodos para agregar boletos, calcular el total de ingresos y contar cuántos boletos se han vendido. Es la lógica de negocio.

Paso 4: Crear la Vista con IntelliJ GUI Designer

4.1 Crear un GUI Form
  1. Clic derecho sobre el paquete vista → New → GUI Form.
  2. Nombre: FormTaquilla.
  3. Aceptar. Se crearán dos archivos: FormTaquilla.form y FormTaquilla.java.
Acoplamiento: El archivo .form contiene el diseño en XML, y el .java contiene el código de la clase. IntelliJ inyecta el código de creación en tiempo de compilación.
4.2 Diseñar el formulario

En la pestaña de diseño (Design), arrastra los siguientes componentes desde la paleta:

  • JPanel como contenedor principal (puedes usar el que viene por defecto).
  • JLabel para el título: "Taquilla de Cine".
  • JLabel para el logo: coloca un JLabel y en la propiedad icon selecciona Classpath y elige la imagen logo.png.
  • JLabel y JTextField para "Película": txtPelicula.
  • JLabel y JTextField para "Sala": txtSala.
  • JLabel y JTextField para "Precio": txtPrecio.
  • JButton "Vender Boleto": btnVender.
  • JButton "Mostrar Total": btnTotal.
  • JButton "Limpiar Campos": btnLimpiar.
  • JLabel para mostrar mensajes o totales: lblMensaje.

Organiza los componentes con un GridLayout o BorderLayout según prefieras. Asegúrate de asignar nombres a las variables (field name) usando notación húngara.

¿Cómo asignar nombres a los componentes y qué es la notación húngara?

Selecciona el componente en el diseño, ve al Inspector de propiedades y en field name escribe el nombre de la variable.
Usamos notación húngara (poner un prefijo al nombre) para identificar rápidamente el tipo de componente en el código:

  • txt para JTextField (ej: txtPelicula)
  • btn para JButton (ej: btnVender)
  • lbl para JLabel (ej: lblMensaje)
Esto hará que el código sea mucho más fácil de leer.

4.3 Configurar la ventana

En el código FormTaquilla.java, agrega el siguiente constructor y configuración:

public FormTaquilla() { // Inicializa los componentes del formulario (generado por IntelliJ) $$$setupUI$$$(); // Configuración de la ventana setTitle("Taquilla de Cine"); setSize(500, 400); setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); setLocationRelativeTo(null); setContentPane(panelPrincipal); // panelPrincipal es el JPanel principal del formulario }

Nota: El método $$$setupUI$$$() es generado automáticamente por IntelliJ; no lo modifiques. El panel principal se llama panelPrincipal por defecto, pero puedes cambiarle el nombre en el Inspector.

Paso 5: Conectar los Eventos

Ahora vamos a darle funcionalidad a los botones y campos. Trabajaremos en el archivo FormTaquilla.java.

5.1 Declarar el servicio como atributo
private TaquillaService servicio;

En el constructor, instanciar el servicio:

servicio = new TaquillaService();
5.2 Evento de clic en "Vender Boleto" (ActionListener)

Usaremos una expresión lambda para el ActionListener.

btnVender.addActionListener(e -> { try { String pelicula = txtPelicula.getText().trim(); String sala = txtSala.getText().trim(); String precioStr = txtPrecio.getText().trim(); // Validar campos vacíos if (pelicula.isEmpty() || sala.isEmpty() || precioStr.isEmpty()) { JOptionPane.showMessageDialog(this, "Todos los campos son obligatorios.", "Error", JOptionPane.WARNING_MESSAGE); return; } // Convertir precio double precio = Double.parseDouble(precioStr); if (precio <= 0) { JOptionPane.showMessageDialog(this, "El precio debe ser mayor que 0.", "Error", JOptionPane.WARNING_MESSAGE); return; } // Crear boleto y registrarlo Boleto boleto = new Boleto(pelicula, sala, precio); servicio.venderBoleto(boleto); // Mostrar mensaje de éxito JOptionPane.showMessageDialog(this, "¡Boleto vendido!\n" + boleto.toString(), "Éxito", JOptionPane.INFORMATION_MESSAGE); // Actualizar el contador en la interfaz (opcional) lblMensaje.setText("Boletos vendidos: " + servicio.contarBoletos()); } catch (NumberFormatException ex) { JOptionPane.showMessageDialog(this, "El precio debe ser un número válido.", "Error de Formato", JOptionPane.ERROR_MESSAGE); } });
¿Qué hace el try-catch? ¿Por qué usar JOptionPane?

El try-catch captura la excepción NumberFormatException si el usuario escribe un precio no numérico (letras o símbolos), evitando que la aplicación se estrelle.
Usamos JOptionPane.showMessageDialog en lugar de imprimir en la consola (System.out), porque el usuario está viendo la ventana de la aplicación y no tiene acceso a la consola del programador. ¡El mensaje debe aparecer en la pantalla!

5.3 Evento "Mostrar Total"
btnTotal.addActionListener(e -> { double total = servicio.calcularTotal(); JOptionPane.showMessageDialog(this, "Total de ingresos: ¢" + total, "Resumen", JOptionPane.INFORMATION_MESSAGE); });
5.4 Evento "Limpiar Campos"
btnLimpiar.addActionListener(e -> { txtPelicula.setText(""); txtSala.setText(""); txtPrecio.setText(""); lblMensaje.setText("Campos limpiados"); });
5.5 Evento de teclado: KeyAdapter para presionar Enter

Agregaremos un KeyAdapter al campo de precio para que al presionar Enter se dispare el botón "Vender Boleto". Esto mejora la experiencia del usuario al permitirle trabajar solo con el teclado.

txtPrecio.addKeyListener(new KeyAdapter() { @Override public void keyPressed(KeyEvent e) { if (e.getKeyCode() == KeyEvent.VK_ENTER) { btnVender.doClick(); } } });
¿Qué hace doClick()?

doClick() simula un clic en el botón de forma programática. Si presionamos Enter en el campo de precio, el programa entiende que queremos que se ejecute la misma acción que si le diéramos clic al botón de vender. Esta técnica evita tener que repetir todo el código de la venta.

5.6 Evento de ratón: MouseAdapter para efecto hover

Cambiar el color de fondo del botón "Vender Boleto" cuando el mouse pase por encima. Esto hace que la aplicación parezca más interactiva y moderna.

btnVender.addMouseListener(new MouseAdapter() { @Override public void mouseEntered(MouseEvent e) { btnVender.setBackground(Color.CYAN); } @Override public void mouseExited(MouseEvent e) { btnVender.setBackground(null); // Restaurar color por defecto } });

Paso 6: Crear la Clase Main y Ejecutar

6.1 Crear la clase Main en el lugar correcto
  1. Haz clic derecho sobre src → New → Java Class. No la crees dentro de modelo, servicio o vista.
  2. Nombre: Main (O puedes ponerle App o AplicacionTaquilla).
¿Dónde va la clase Main?

No debe ir dentro de los paquetes modelo, vista ni servicio.
Porque cada paquete tiene una responsabilidad específica:

  • modelo = Datos.
  • servicio = Reglas de negocio.
  • vista = Interfaz gráfica.
La clase Main es el punto de entrada de la aplicación. Su única tarea es inicializar el programa y mostrar la ventana al usuario.
Lo más limpio es ponerla justo dentro de la carpeta src (que se verá como el paquete por defecto), o crear un paquete llamado app o main al mismo nivel que los otros tres.

6.2 Escribir el método main con SwingUtilities.invokeLater
package taquilla; // opcional, si creaste un paquete en la raíz llamado 'taquilla'. import vista.FormTaquilla; import javax.swing.SwingUtilities; public class Main { public static void main(String[] args) { SwingUtilities.invokeLater(() -> { FormTaquilla ventana = new FormTaquilla(); ventana.setVisible(true); }); } }
¿Por qué usar SwingUtilities.invokeLater?

Para asegurar que la creación y manipulación de la GUI se realice en el EDT (Event Dispatch Thread). Si no lo usáramos, la interfaz gráfica podría aparecer a medias, congelarse o tener errores de concurrencia. Es el estándar de "buenas prácticas" en Swing.

6.3 Ejecutar la aplicación
  1. Abrir Main.java.
  2. Hacer clic en el triángulo verde junto al main.
  3. Seleccionar Run 'Main.main()'.

Prueba la aplicación: ingresa datos, presiona Enter en el campo de precio, verifica el cambio de color del botón, etc.
