Introducción al Laboratorio

En este laboratorio autoguiado, aprenderá paso a paso a construir la primera fase de una aplicación de mensajería (Mini-Discord). El objetivo principal es abandonar el código monolítico y estructurar el proyecto utilizando la Arquitectura de N-Capas y el Patrón MVC.

Se desarrollará una interfaz gráfica que se actualiza reactivamente mediante una ObservableList (Patrón Observer), aislando estrictamente la lógica de validación de mensajes en una capa de servicios independiente.

Enfoque Pedagógico: Este manual está diseñado para guiarle desde la creación del proyecto en IntelliJ IDEA, estructurando correctamente los paquetes, hasta comprender cómo la Vista delega responsabilidades al Controlador y este a su vez interactúa con el Modelo.

Paso 1: Creación del Proyecto en IntelliJ IDEA

1.1 Configurar los parámetros iniciales del asistente
  1. Abra IntelliJ IDEA y seleccione File → New → Project.
  2. En el panel izquierdo, seleccione JavaFX.
  3. En el selector de Build system, elija obligatoriamente Maven.
  4. En el campo JDK, asegúrese de tener seleccionado Java 21 (o superior compatible).
1.2 Explicación de los campos de relleno (Artifact, Group y Package)

Al configurar el proyecto, el asistente solicitará rellenar los identificadores clave:

  • GroupId: cr.ac.una.est → Representa la organización. Define el espacio de nombres raíz para Maven.
  • ArtifactId: minidiscord → Es el nombre único de la aplicación.
  • Package name: cr.ac.una.est.minidiscord → La ruta lógica en disco dentro de la cual residirán todos los archivos de código fuente.
Verificación de ubicación: Para comprobar que las carpetas se crearon correctamente, despliegue el árbol de directorios en el panel izquierdo de IntelliJ. Si contrae la carpeta java y el paquete raíz se oculta correctamente dentro de ella, la jerarquía es coherente.

Paso 2: Configuración del pom.xml

2.1 Configuración de dependencias

Abra el archivo pom.xml en la raíz del proyecto y asegúrese de que contenga la siguiente estructura adaptada a Java 21 y JavaFX 21.0.6:

pom.xml 
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>cr.ac.una.est</groupId>
    <artifactId>minidiscord</artifactId>
    <version>1.0-SNAPSHOT</version>

    <!-- Definición de las librerías gráficas necesarias para compilar -->
    <dependencies>
        <dependency>
            <groupId>org.openjfx</groupId>
            <artifactId>javafx-controls</artifactId>
            <version>21.0.6</version>
        </dependency>
        <dependency>
            <groupId>org.openjfx</groupId>
            <artifactId>javafx-fxml</artifactId>
            <version>21.0.6</version>
        </dependency>
    </dependencies>

    <!-- Configuración para forzar al compilador a utilizar Java 21 -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
                <configuration>
                    <source>21</source>
                    <target>21</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
Ver explicación del código línea por línea.

<dependencies>: Enlista los paquetes externos. Se incluyen javafx-controls (botones, listas) y javafx-fxml (procesador de interfaces visuales), indispensables para el entorno gráfico.

<plugin>: Indica al compilador de Maven que debe utilizar estrictamente el JDK de Java en su versión 21 mediante las etiquetas <source> y <target>.

2.2 Recargar Maven

Cada vez que modifique el pom.xml, haga clic en el icono flotante de actualización de Maven (una 'M' azul o símbolo de recarga) situado en la esquina superior derecha del editor. Si no aparece, haga clic derecho al archivo en el explorador de proyectos y seleccione Maven → Reload project.

3.2 Configuración del archivo module-info.java

JavaFX utiliza el sistema modular de Java (JPMS). Asegúrese de colocar este archivo en la raíz de la carpeta java, fuera de los subpaquetes. Ajuste las directivas de acceso:

module-info.java 
module cr.ac.una.est.minidiscord {
    // Permite a la aplicación instanciar elementos gráficos de las librerías nativas
    requires javafx.controls;
    requires javafx.fxml;

    // Autoriza al cargador FXML a acceder al controlador por reflexión para inyectar los @FXML
    opens cr.ac.una.est.minidiscord.presentation.controller to javafx.fxml;

    // Exporta los paquetes para que JavaFX y la JVM puedan ver e instanciar las clases públicas
    exports cr.ac.una.est.minidiscord;
    exports cr.ac.una.est.minidiscord.presentation.controller;
}
Ver explicación del código línea por línea.

requires javafx.controls;: Solicita acceso a los módulos internos de JavaFX. Sin esta línea, no se pueden usar elementos gráficos.

opens ... to javafx.fxml;: Abre el paquete presentation.controller al motor FXML. JavaFX utiliza "Reflexión" para leer las etiquetas @FXML e inyectar dinámicamente los componentes visuales en las variables de la clase.

exports ...;: A diferencia de opens (que da acceso a elementos privados), exports hace que las clases públicas del paquete sean visibles para otros módulos. Exportar el controlador es obligatorio para que el motor de JavaFX pueda instanciar la clase ChatViewController sin arrojar un error IllegalAccessException.

Paso 4: Capa de Negocio (Model y Service)

4.1 Entidades del Modelo

En el paquete business.model, cree la clase User.java:

User.java 
package cr.ac.una.est.minidiscord.business.model;

import java.io.Serializable;

// Se implementa Serializable para poder convertir la instancia en bytes y almacenarla en disco a futuro.
public class User implements Serializable {
    
    // La propiedad 'final' garantiza inmutabilidad: el username no cambiará tras ser instanciado.
    private final String username;

    public User(String username) {
        this.username = username;
    }

    public String getUsername() { return username; }
}
Ver explicación del código línea por línea.

implements Serializable: Habilita la clase para ser convertida en bytes. Es indispensable para que en la próxima sesión podamos guardar los usuarios en un archivo del disco duro de forma automática mediante la Capa de Datos.

private final: Se utiliza final para indicar que el nombre de usuario no puede ser modificado (inmutabilidad) una vez que el objeto ha nacido en la memoria.

A continuación, cree la clase Message.java en el mismo paquete. Esta clase encapsula el texto del mensaje y al usuario responsable del mismo.

Message.java 
package cr.ac.una.est.minidiscord.business.model;

import java.io.Serializable;

// Como Message contiene un atributo de tipo 'User', la clase 'User' también debió 
// implementar Serializable de manera obligatoria para evitar un colapso estructural.
public class Message implements Serializable {
    private final User author;
    private final String content;

    public Message(User author, String content) {
        this.author = author;
        this.content = content;
    }

    // Se sobrescribe el comportamiento natural para que la vista gráfica 
    // sepa exactamente qué formato usar al pintar este objeto en la lista.
    @Override
    public String toString() {
        return author.getUsername() + ": " + content;
    }
}
Ver explicación del código línea por línea.

@Override public String toString(): Se sobrescribe el comportamiento por defecto de la clase original Object de Java. Al enviar el objeto a la lista gráfica, este método instruye para que se imprima el nombre del autor seguido de dos puntos y el contenido del mensaje.

4.2 Lógica de Negocio (Service)

Cree la clase ChatService.java en el paquete business.service. Esta clase aísla las reglas de validación y de formato, garantizando que la Capa de Presentación se mantenga ligera e independiente.

ChatService.java 
package cr.ac.una.est.minidiscord.business.service;

import cr.ac.una.est.minidiscord.business.model.Message;
import cr.ac.una.est.minidiscord.business.model.User;

public class ChatService {
    
    public Message processMessage(User sender, String text) {
        
        // La validación de negocio rechaza textos vacíos lanzando una excepción lógica.
        // La capa de negocio NUNCA debe invocar ni modificar componentes de la vista directamente.
        if (text == null || text.trim().isEmpty()) {
            throw new IllegalArgumentException("El mensaje no puede estar vacío.");
        }
        
        // La regla de formato establece que los espacios sobrantes se eliminan al construir.
        return new Message(sender, text.trim());
    }
}
Ver explicación del código línea por línea.

throw new IllegalArgumentException(...): Si se detecta un texto vacío, el servicio no invoca una ventana visual de error (la capa de Negocio tiene terminantemente prohibido acceder a la interfaz gráfica). En su lugar, interrumpe el proceso lanzando una excepción lógica que el Controlador deberá capturar y gestionar adecuadamente.

text.trim(): Se aplica la regla de negocio que formatea el texto, removiendo los espacios en blanco accidentales al inicio y al final antes de empaquetarlo en el nuevo mensaje.

Paso 5: Capa de Presentación (View y Controller)

5.1 El Diseño FXML (La Vista)

Cree el archivo chat-view.fxml navegando estrictamente por la jerarquía de la carpeta de recursos: src/main/resources/cr/ac/una/est/minidiscord/presentation/view/.

chat-view.fxml 
<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.geometry.Insets?>
<?import javafx.scene.control.*?>
<?import javafx.scene.layout.*?>

<!-- VBox es el contenedor raíz. fx:controller enlaza este diseño visual con la clase Java responsable -->
<VBox spacing="10.0" xmlns:fx="http://javafx.com/fxml" 
      fx:controller="cr.ac.una.est.minidiscord.presentation.controller.ChatViewController">
    <padding>
        <Insets bottom="15.0" left="15.0" right="15.0" top="15.0"/>
    </padding>
    
    <!-- Atributo fx:id le otorga un nombre identificable para ser manipulado desde el controlador -->
    <ListView fx:id="messageListView" VBox.vgrow="ALWAYS"/>
    
    <HBox spacing="10.0">
        <!-- onAction delega el comportamiento a una estrategia definida en el archivo Java -->
        <TextField fx:id="messageInputField" HBox.hgrow="ALWAYS" onAction="#handleSendMessage"/>
        <Button text="Enviar" onAction="#handleSendMessage"/>
    </HBox>
</VBox>
Ver explicación del código línea por línea.

<VBox fx:controller="...">: Establece el nodo raíz de la interfaz (un contenedor que apila verticalmente). El atributo fx:controller enruta de forma absoluta todos los eventos al archivo Java correspondiente.

<ListView fx:id="messageListView"/>: Componente visual que renderiza listas. Se le asigna un identificador único (fx:id) para ser inyectado y manipulado desde el controlador.

onAction="#handleSendMessage": Declara qué método del controlador debe invocarse al presionar el botón o al dar "Enter" dentro de la caja de texto. Evidencia el Patrón Strategy, delegando el comportamiento a una función externa.

5.2 El Controlador y el Patrón Observer

Cree la clase ChatViewController.java en el paquete de código fuente presentation.controller. Aquí radica el núcleo de la coordinación: el controlador une los eventos visuales con la validación de la capa de servicios.

ChatViewController.java 
package cr.ac.una.est.minidiscord.presentation.controller;

import cr.ac.una.est.minidiscord.business.model.Message;
import cr.ac.una.est.minidiscord.business.model.User;
import cr.ac.una.est.minidiscord.business.service.ChatService;
import javafx.collections.FXCollections;
import javafx.collections.ObservableList;
import javafx.fxml.FXML;
import javafx.scene.control.ListView;
import javafx.scene.control.TextField;

public class ChatViewController {

    // La anotación @FXML inyecta los elementos visuales creados en el archivo XML
    @FXML private ListView<String> messageListView;
    @FXML private TextField messageInputField;

    // Instancia de los servicios y creación de un usuario local en memoria
    private final ChatService chatService = new ChatService();
    private final User currentUser = new User("EstudianteUNA");
    
    // Colección observable (Implementación nativa del Patrón Observer en JavaFX)
    private final ObservableList<String> messages = FXCollections.observableArrayList();

    @FXML
    public void initialize() {
        // Se suscribe formalmente la vista gráfica al modelo de datos observable
        messageListView.setItems(messages);
    }

    @FXML
    private void handleSendMessage() {
        try {
            // Delegación total de la lógica de validación a la capa de Negocio (Service)
            Message nuevoMsg = chatService.processMessage(currentUser, messageInputField.getText());
            
            // La colección notifica automáticamente a la ListView para repintarse en pantalla
            messages.add(nuevoMsg.toString());
            messageInputField.clear();
            
        } catch (IllegalArgumentException e) {
            // Captura el rechazo del servicio e informa en consola (Futura implementación: Alerta Visual)
            System.out.println("Aviso de Validación: " + e.getMessage());
        }
    }
}
Ver explicación del código línea por línea.

private final ObservableList<String> messages: A diferencia de un ArrayList convencional de Java, esta colección especializada notifica inmediatamente cualquier inserción, eliminación o actualización a todos sus observadores (en este caso, el componente gráfico ListView).

messageListView.setItems(messages);: Dentro del método de inicialización, se vincula formalmente el componente de Interfaz de Usuario con los datos en memoria, estableciendo la suscripción del Patrón Observer.

try { ... } catch (IllegalArgumentException e): El controlador intenta que la capa de negocio construya el mensaje. Si el servicio detecta un error de regla (como enviar espacios en blanco) y lanza la excepción, el bloque catch la captura y evita el colapso repentino de la aplicación gráfica.

Comentario Analítico:

Preste especial atención a que el método handleSendMessage no contiene validaciones de cadenas vacías ni utiliza operadores condicionales. Su función es estrictamente recolectar el texto de la pantalla, transportarlo hacia el ChatService y administrar la respuesta. Esta limpieza asegura un alto grado de cohesión estructural y facilita futuras pruebas de validación.

Paso 6: Lanzador Principal (App.java)

6.1 Clase de arranque

Finalmente, cree la clase App en la raíz del paquete principal (cr.ac.una.est.minidiscord) para ensamblar y desplegar el entorno gráfico en la pantalla del sistema operativo.

App.java 
package cr.ac.una.est.minidiscord;

import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Scene;
import javafx.stage.Stage;
import java.io.IOException;

// Extender de Application indica a la JVM que esta clase arranca el entorno gráfico nativo
public class App extends Application {
    
    @Override
    public void start(Stage stage) throws IOException {
        // FXMLLoader es el encargado de leer el XML e inyectarlo en memoria
        FXMLLoader fxmlLoader = new FXMLLoader(App.class.getResource("/cr/ac/una/est/minidiscord/presentation/view/chat-view.fxml"));
        
        // Se coloca la estructura compilada dentro de un lienzo o "Escena" general
        Scene scene = new Scene(fxmlLoader.load(), 600, 400);
        
        // Stage representa el marco físico de la ventana brindado por el Sistema Operativo
        stage.setTitle("Mini-Discord UNA");
        stage.setScene(scene);
        stage.show();
    }

    public static void main(String[] args) {
        launch();
    }
}
Ver explicación del código línea por línea.

extends Application: Requisito fundamental para que la máquina virtual de Java reconozca la clase como un contenedor especializado de JavaFX y asigne los procesos de renderizado de interfaz gráfica correspondientes.

FXMLLoader fxmlLoader = new FXMLLoader(...): Define la ubicación estática del archivo FXML dentro de la carpeta resources e inicializa el proceso de inyección hacia el controlador.

stage.setScene(scene);: Se introduce la escena completa (ya cargada y compilada en memoria) dentro de la ventana proporcionada por el sistema operativo (Stage) para presentarla visualmente al usuario.

¡Ejecución del Laboratorio! Proceda a compilar y ejecutar la clase App. Intente enviar mensajes vacíos y mensajes con texto para comprobar el correcto funcionamiento de las reglas de negocio aisladas en el servicio. Observe que la lista visual se actualiza automáticamente gracias a su naturaleza observable.

¿Dónde ocurre la magia reactiva?

Una vez que ChatService devuelve el Message construido, el ChatViewController simplemente lo inyecta en la ObservableList. Gracias al Patrón Observer, la colección notifica internamente al archivo chat-view.fxml y la lista se repinta en pantalla sin necesidad de métodos gráficos adicionales.

Glosario de Términos Clave

  • MVC: Modelo-Vista-Controlador. Patrón arquitectónico que separa datos, interfaz y lógica de control.
  • DAO (Data Access Object): Objeto que encapsula el acceso a la fuente de datos (archivo, base de datos).
  • DTO (Data Transfer Object): Objeto simple que transporta datos entre capas sin exponer la lógica interna.
  • Serialización: Proceso de convertir un objeto en una secuencia de bytes para almacenarlo de forma persistente.
  • Observer: Patrón que permite que un objeto notifique a otros de forma desvinculada sobre cambios en su estado.
  • Strategy: Patrón que permite seleccionar un algoritmo o respuesta en tiempo de ejecución.
  • Composite: Patrón que trata objetos individuales y estructuras jerárquicas (árboles) de manera uniforme.
  • N-Layers: División lógica del código en paquetes según su responsabilidad dentro de un mismo programa.
  • N-Tiers: División física de la aplicación ejecutándose en diferentes equipos de cómputo en una red.
