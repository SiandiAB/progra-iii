Sistema Interactivo de Registro de Productos con Eventos

Programación III — Semana 5: Aplicaciones Dirigidas por Eventos

KeyAdapter & e.consume() FocusAdapter & Validación MouseAdapter & Hover WindowAdapter & Cierre Patrón de Delegación
Duración estimada: 1 hora 15 minutos  ·  Trabajo Individual

Introducción al Reto Individual

En la primera parte de la sesión construimos juntos un sistema aplicando el ciclo de eventos, el modelo de delegación y las clases adaptadoras de Swing.

Ahora pondrás a prueba tus conocimientos de forma individual creando un Sistema de Registro de Productos de Cafetería. Siguiendo exactamente la misma arquitectura y los patrones vistos en el live coding, deberás construir el modelo, el servicio y la interfaz gráfica que valide entradas del teclado, detecte el foco, proporcione retroalimentación visual al mouse e intercepte el cierre de la ventana.

Objetivo: Demostrar dominio práctico en:
  • Validar restricciones de teclado con KeyListener / KeyAdapter y el método e.consume().
  • Manejar eventos de foco con FocusListener / FocusAdapter para alertas visuales de campos requeridos.
  • Generar interactividad visual de mouse con MouseListener / MouseAdapter (efecto hover).
  • Interceptar el evento de sistema de salida con WindowListener / WindowAdapter y confirmar con JOptionPane.
  • Mantener la separación estricta entre Modelo, Servicio y Vista.

Paso 1: Configurar el Repositorio y Paquetes

1.1 Crear el repositorio en GitHub y clonarlo

Crea en GitHub un repositorio para el laboratorio, clónalo en tu computadora con GitHub Desktop y ábrelo en IntelliJ IDEA asegurando la carpeta src como Sources Root.

1.2 Estructura de paquetes requerida

Dentro de src crea la siguiente estructura:

src/ ├── modelo/ // Clase Producto ├── servicio/ // Clase InventarioServicio ├── vista/ // Clase VentanaProducto └── Main.java // Lanzador seguro en EDT

Paso 2: Crear el Modelo Producto.java

2.1 Requisitos de la clase

En el paquete modelo, crea la clase Producto con los siguientes miembros:

  • Atributos privados: private String codigo, private String nombre, private double precio, private int stock.
  • Constructor completo que inicialice todos los atributos.
  • Métodos Getters y Setters para cada atributo.
  • Sobrescritura del método toString() devolviendo una cadena con el formato:
    [COD] Nombre - $Precio (Stock: N).

Paso 3: Crear el Servicio InventarioServicio.java

3.1 Requisitos del servicio

En el paquete servicio, crea la clase InventarioServicio:

  • Atributo privado: private List<Producto> listaProductos = new ArrayList<>();.
  • Método public void registrarProducto(Producto p) que valide que el código no esté repetido (usando Streams o bucle) y lo agregue a la lista. Si está repetido, lanzar IllegalArgumentException("El código ya existe").
  • Método public List<Producto> getProductos() que retorne una copia de la lista.
  • Método public int getTotalStock() que calcule la sumatoria de stock de todos los productos registrados.

Paso 4: Construir la Interfaz y Eventos en VentanaProducto.java

En el paquete vista, crea VentanaProducto extends JFrame.

4.1 Componentes de la interfaz
  • Cajas de texto: txtCodigo, txtNombre, txtPrecio, txtStock.
  • Etiqueta de estado/contador: lblContadorCodigo (para mostrar ej: "4/4 dígitos").
  • Etiqueta de resumen inferior: lblResumenInventario.
  • Botones: btnRegistrar, btnLimpiar.
4.2 Requisitos Obligatorios de Eventos a Implementar:
  1. Validación de Teclado con KeyAdapter en txtCodigo:
    Debe admitir únicamente dígitos y un máximo estricto de 4 caracteres. Usar e.consume() si se presiona un caracter no numérico o si la longitud supera 4. En keyReleased, actualizar lblContadorCodigo.
  2. Validación de Teclado con KeyAdapter en txtStock:
    Debe admitir únicamente dígitos numéricos enteros usando Character.isDigit() y e.consume().
  3. Validación de Foco con FocusAdapter en txtPrecio:
    En focusLost, verificar si lo ingresado es un número decimal válido (Double.parseDouble). Si falla o está vacío, pintar el fondo de la caja en color rojo claro (new Color(255, 220, 220)); si es válido, restaurar a blanco.
  4. Efecto Hover con MouseAdapter en btnRegistrar:
    En mouseEntered, cambiar el fondo del botón a verde y el cursor a Cursor.HAND_CURSOR. En mouseExited, restaurar los colores por defecto.
  5. Evento del Botón Registrar (ActionListener con Lambda):
    Extraer los textos, validar que no existan campos vacíos, llamar a servicio.registrarProducto(...), mostrar mensaje con JOptionPane.showMessageDialog y actualizar el resumen de inventario.
  6. Interceptación de Salida con WindowAdapter en la ventana:
    Configurar setDefaultCloseOperation(DO_NOTHING_ON_CLOSE). En windowClosing, preguntar con JOptionPane.showConfirmDialog: "¿Está seguro de que desea salir del sistema?". Cerrar con dispose() solo si responde afirmativamente.

Paso 5: Punto de Entrada Main.java

5.1 Inicialización segura

En Main, instanciar InventarioServicio, inyectarlo a VentanaProducto y desplegarla usando SwingUtilities.invokeLater(() -> { ... }).

Preguntas de Reflexión

  1. ¿Por qué es necesario usar e.consume() en lugar de simplemente no hacer nada dentro del keyTyped?
  2. ¿Qué diferencia técnica existe entre una clase que implementa KeyListener directamente y una que extiende de KeyAdapter?
  3. ¿Por qué debemos establecer DO_NOTHING_ON_CLOSE al interceptar el cierre de una ventana con WindowListener?
  4. Si un cálculo tomara 10 segundos, ¿por qué NO debemos programarlo directamente dentro del actionPerformed de un botón?
