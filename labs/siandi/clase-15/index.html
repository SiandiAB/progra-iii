Introducción al Laboratorio

Hasta la Semana 13, Mini-Discord es una aplicación de una sola persona: la ventana guarda y lee los mensajes directamente en la base de datos de su propia computadora. En este laboratorio la van a convertir en un chat entre computadoras: un servidor que espera conexiones y reparte los mensajes, y varias ventanas cliente que se conectan a él.

Lo van a lograr con lo que vieron en la teoría: un hilo por cliente en el servidor, un hilo oyente en el cliente, una Task para conectar sin congelar la ventana, y Platform.runLater para mostrar los mensajes que llegan por la red.

Enfoque pedagógico: cada paso trae una caja morada "¿Cómo se llega a esta decisión?" con el razonamiento, y un desplegable "Ver explicación del código, línea por línea". Peguen el código tal como está y después lean la explicación: así avanzan sin errores y aprenden qué hace cada pieza.

Antes de empezar: qué necesitan y qué NO necesitan

Sí necesitan

  • IntelliJ IDEA instalado.
  • Java 21 o superior (el proyecto usa Java 21). Para comprobar cuál tienen, abran una terminal y escriban java --version.
  • Internet la primera vez, porque Maven descarga las librerías del proyecto (JavaFX y el driver de MySQL).
  • El proyecto Mini-Discord de la semana 13, en su versión más reciente. El Paso 1 les dice cómo descargarlo.

NO necesitan

  • MySQL ni MySQL Workbench. En este laboratorio el servidor guarda los mensajes en memoria. No necesitan crear ninguna base de datos ni ningún usuario.
  • El archivo config.properties. La ventana ya no se conecta a la base de datos: habla con el servidor.
  • Dos computadoras, si trabajan solos. Pueden probar todo en una sola, abriendo dos ventanas. Si tienen una segunda computadora en la misma red, el último paso les muestra cómo usarla.
Importante: no usen el proyecto que ya tenían con cambios propios. Descarguen uno nuevo en el Paso 1, así todos parten exactamente del mismo código y nada falla por diferencias.

Paso 3: El protocolo: ChatProtocol

Un protocolo son las reglas de la conversación entre dos programas. Cliente y servidor tienen que escribir y leer los mensajes exactamente igual. Por eso esa regla vive en un solo lugar.

Dónde se crea: en el paquete network.
  1. Clic derecho sobre el paquete network.
  2. New → Java Class. Escriban ChatProtocol y presionen Enter.
  3. Con el archivo abierto, Ctrl+A y Delete para dejarlo vacío.
  4. Copien el código de abajo con el botón Copiar y péguenlo con Ctrl+V. Incluye la línea package del principio.
network/ChatProtocol.java
package cr.ac.una.est.minidiscord.network;

import cr.ac.una.est.minidiscord.business.model.Message;
import cr.ac.una.est.minidiscord.business.model.User;
import java.time.LocalDateTime;

// Las reglas de la conversación (el protocolo): cada mensaje es una línea de texto.
//   cliente -> servidor:  HELLO|usuario     MSG|texto
//   servidor -> cliente:  MSG|usuario|fecha|texto     ERR|motivo
public final class ChatProtocol {

    public static final int PUERTO = 5050;

    private ChatProtocol() { }

    public static String codificar(Message mensaje) {
        return "MSG|" + mensaje.getAuthor().getUsername() + "|" + mensaje.getSentAt() + "|" + mensaje.getContent();
    }

    // El 4 en split hace que el texto del mensaje pueda llevar el carácter | sin romperse.
    public static Message decodificar(String linea) {
        String[] partes = linea.split("\\|", 4);
        if (partes.length < 4 || !partes[0].equals("MSG")) {
            throw new IllegalArgumentException("Línea inválida: " + linea);
        }
        return new Message(new User(partes[1]), partes[3], LocalDateTime.parse(partes[2]));
    }
}
Ver explicación del código, línea por línea.

public final class ChatProtocol { private ChatProtocol() { } } Una clase que solo tiene cosas estáticas. final impide heredarla y el constructor private impide crear objetos. Se usa así: ChatProtocol.PUERTO.

public static final int PUERTO = 5050; El puerto vive en un solo lugar. El servidor y el cliente leen el mismo número, así que no pueden quedar desacordados.

codificar(Message mensaje) Convierte un Message en una línea de texto con cuatro partes separadas por la barra vertical: MSG|usuario|fecha|texto. Se manda texto y no el objeto, porque reconstruir objetos que llegan por la red es un riesgo de seguridad conocido.

linea.split("\\|", 4) Parte la línea por cada barra vertical. Se escribe con dos barras invertidas porque la barra vertical es un carácter especial en las expresiones regulares. El 4 significa "a lo sumo cuatro pedazos": así, si el texto del mensaje trae barras, todo lo que sigue a la tercera se queda junto y no se rompe.

throw new IllegalArgumentException(...) Si la línea no tiene el formato esperado, se rechaza. Nunca hay que confiar en lo que llega por la red.

new Message(new User(partes[1]), partes[3], LocalDateTime.parse(partes[2])) Reconstruye el mensaje con el constructor que recibe la fecha, el mismo que se usa al leer de la base de datos, para conservar el momento en que se escribió.

Es normal que, hasta crear las demás clases, IntelliJ no muestre errores aquí: esta clase solo usa Message y User, que ya existen.

Paso 4: Un repositorio en memoria: InMemoryMessageRepository

El servidor necesita un lugar donde guardar los mensajes. Para este laboratorio los guarda en una lista en memoria, así no hace falta MySQL.

Dónde se crea: en el paquete cr.ac.una.est.minidiscord.data.dao, no en network. Está junto a MessageRepository.

  2. New → Java Class. Escriban InMemoryMessageRepository y Enter.
  3. Ctrl+A y Delete para vaciar el archivo.
  4. Copien el código de abajo y péguenlo con Ctrl+V.
data/dao/InMemoryMessageRepository.java
package cr.ac.una.est.minidiscord.data.dao;

import cr.ac.una.est.minidiscord.business.model.Message;
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;

// Guarda los mensajes en memoria, sin base de datos. Sirve para probar el servidor
// sin MySQL: como implementa la misma interfaz, el resto del programa no cambia.
public class InMemoryMessageRepository implements MessageRepository {

    private final List<Message> mensajes = new CopyOnWriteArrayList<>();

    @Override
    public void guardar(Message mensaje) {
        mensajes.add(mensaje);
    }

    @Override
    public List<Message> obtenerTodos() {
        return List.copyOf(mensajes);
    }
}
Ver explicación del código, línea por línea.

implements MessageRepository Cumple el mismo contrato que JdbcMessageRepository: guardar y obtener todos. Por eso el servidor puede usar cualquiera de las dos sin enterarse de cuál es.

private final List<Message> mensajes = new CopyOnWriteArrayList<>(); La lista donde se guardan. Es una colección concurrente porque los hilos de todos los clientes guardan a la vez. Una ArrayList normal podría fallar.

return List.copyOf(mensajes); Devuelve una copia de la lista, una foto del momento. Así quien la reciba puede recorrerla tranquilo aunque otros hilos sigan agregando mensajes.

¿Cómo se llega a esta decisión?

Esto es posible porque MessageRepository es una interfaz. Cambiar de MySQL a la memoria no toca nada más: es la prueba de que separar el contrato de la implementación vale la pena.

network/ClientHandler.java
package cr.ac.una.est.minidiscord.network;

import cr.ac.una.est.minidiscord.business.model.User;
import cr.ac.una.est.minidiscord.business.service.ChatService;
import cr.ac.una.est.minidiscord.data.dao.DataAccessException;
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

// Atiende a un solo cliente. El servidor crea un hilo con una de estas por cada conexión.
class ClientHandler implements Runnable {

    private final Socket conexion;
    private final ChatServer servidor;
    private final ChatService servicio = new ChatService();
    private PrintWriter salida;
    private String usuario = "?";

    ClientHandler(Socket conexion, ChatServer servidor) {
        this.conexion = conexion;
        this.servidor = servidor;
    }

    String getUsuario() {
        return usuario;
    }

    @Override
    public void run() {
        try (conexion;
             BufferedReader entrada = new BufferedReader(new InputStreamReader(conexion.getInputStream()));
             PrintWriter out = new PrintWriter(conexion.getOutputStream(), true)) {

            salida = out;
            if (!saludar(entrada.readLine())) {
                return;
            }
            try {
                servidor.registrar(this);   // lee el historial en la base
            } catch (DataAccessException e) {
                enviar("ERR|" + e.getMessage());
                return;
            }

            String linea;
            while ((linea = entrada.readLine()) != null) {   // null = el cliente se desconectó
                if (linea.startsWith("MSG|")) {
                    recibir(linea.substring(4));
                }
            }
        } catch (IOException e) {
            System.out.println(usuario + ": conexión terminada (" + e.getMessage() + ")");
        } finally {
            servidor.quitar(this);
        }
    }

    // La primera línea debe ser HELLO|usuario. Se valida con el mismo ChatService de siempre.
    private boolean saludar(String linea) {
        try {
            if (linea == null || !linea.startsWith("HELLO|")) {
                throw new IllegalArgumentException("Se esperaba HELLO|usuario.");
            }
            String nombre = linea.substring(6);
            if (nombre.contains("|")) {
                throw new IllegalArgumentException("El nombre no puede llevar el carácter |.");
            }
            usuario = servicio.createUser(nombre).getUsername();
            return true;
        } catch (IllegalArgumentException e) {
            enviar("ERR|" + e.getMessage());
            return false;
        }
    }

    private void recibir(String texto) {
        try {
            servidor.publicar(servicio.processMessage(new User(usuario), texto));
        } catch (IllegalArgumentException | DataAccessException e) {
            enviar("ERR|" + e.getMessage());
        }
    }

    // synchronized: varios hilos pueden mandarle líneas a este cliente al mismo tiempo.
    synchronized void enviar(String linea) {
        if (salida != null) {
            salida.println(linea);
        }
    }
}
Es normal: IntelliJ va a subrayar en rojo ChatServer y algunos métodos, porque esa clase todavía no existe. Se arregla sola en el Paso 6. No se preocupen.
Ver explicación del código, línea por línea.

class ClientHandler implements Runnable Es la tarea de un hilo. Runnable tiene un único método, run(), que es lo que el hilo ejecuta. El servidor crea un hilo por cada cliente y le entrega uno de estos.

private final ChatService servicio = new ChatService(); La misma capa de negocio que usa la ventana. El servidor valida el nombre y el texto con las mismas reglas.

try (conexion; BufferedReader entrada ...; PrintWriter out ...) Abre los canales para leer y escribirle a ese cliente, y los cierra solos al terminar. El true del PrintWriter activa el autoflush: cada línea se envía de inmediato.

if (!saludar(entrada.readLine())) { return; } La primera línea tiene que ser HELLO|nombre. Si no sirve, se termina.

servidor.registrar(this); Le entrega este cliente al servidor, que le manda el historial y lo agrega a la lista de conectados.

while ((linea = entrada.readLine()) != null) readLine() espera hasta que llegue una línea. Devuelve null solo cuando el cliente se desconectó, y esa es la señal de que se fue.

if (linea.startsWith("MSG|")) { recibir(linea.substring(4)); } Solo se atienden las líneas del tipo MSG. substring(4) quita esos cuatro caracteres y deja el texto.

} finally { servidor.quitar(this); } Pase lo que pase, el cliente sale de la lista de conectados.

saludar Revisa el saludo y que el nombre no lleve el carácter |, porque rompería el formato. Usa servicio.createUser, el mismo método que valida el nombre en la ventana.

recibir Valida el texto con servicio.processMessage. Si es válido, se lo da al servidor para guardarlo y repartirlo. Si no, le devuelve al cliente una línea ERR|motivo.

synchronized void enviar(String linea) Manda una línea a este cliente. synchronized hace que, si dos hilos le escriben a la vez, entren de uno en uno.

Para pensar: ¿Por qué hace falta un hilo por cliente? ¿Qué pasaría con un solo hilo?

Ver respuesta

Porque accept() y readLine() esperan, y mientras un hilo está esperando no puede hacer otra cosa. Con un solo hilo, mientras el servidor espera a que el cliente 1 escriba, no puede atender al cliente 2 ni aceptar uno nuevo.

Paso 6: El servidor: ChatServer

Es el programa que se queda esperando conexiones. Por cada cliente que llega crea un ClientHandler en su propio hilo, guarda cada mensaje y lo reparte a todos.

Dónde se crea: en el paquete network.
  1. En el panel de la izquierda (Project), hagan clic derecho sobre el paquete network.
  2. Escojan New y después Java Class.
  3. Escriban exactamente ChatServer y presionen Enter. Se abre el archivo ChatServer.java.
  4. Hagan clic dentro del archivo, presionen Ctrl+A para seleccionar todo y Delete para borrarlo. El archivo debe quedar completamente vacío.
  5. Presionen el botón Copiar del código de abajo y péguenlo en el archivo con Ctrl+V. Incluye la primera línea, que empieza con package: no la borren.
network/ChatServer.java
package cr.ac.una.est.minidiscord.network;

import cr.ac.una.est.minidiscord.business.model.Message;
import cr.ac.una.est.minidiscord.data.dao.InMemoryMessageRepository;
import cr.ac.una.est.minidiscord.data.dao.JdbcMessageRepository;
import cr.ac.una.est.minidiscord.data.dao.MessageRepository;
import java.io.IOException;
import java.net.ServerSocket;
import java.net.Socket;
import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;

// El servidor guarda los mensajes (en la base) y los reparte a todos los clientes conectados.
public class ChatServer {

    private final MessageRepository repositorio;

    // Varios hilos la modifican a la vez (entra y sale gente): por eso es una lista concurrente.
    private final List<ClientHandler> clientes = new CopyOnWriteArrayList<>();

    public ChatServer(MessageRepository repositorio) {
        this.repositorio = repositorio;
    }

    public void iniciar() throws IOException {
        try (ServerSocket servidor = new ServerSocket(ChatProtocol.PUERTO)) {
            System.out.println("Servidor escuchando en el puerto " + ChatProtocol.PUERTO);
            while (true) {
                Socket conexion = servidor.accept();   // se bloquea hasta que llega un cliente
                ClientHandler atencion = new ClientHandler(conexion, this);
                new Thread(atencion, "cliente-" + conexion.getPort()).start();   // un hilo por cliente
            }
        }
    }

    // Al entrar, el cliente recibe el historial y después queda en la lista.
    void registrar(ClientHandler cliente) {
        for (Message m : repositorio.obtenerTodos()) {
            cliente.enviar(ChatProtocol.codificar(m));
        }
        clientes.add(cliente);
        System.out.println(cliente.getUsuario() + " entró. Conectados: " + clientes.size());
    }

    void quitar(ClientHandler cliente) {
        if (clientes.remove(cliente)) {
            System.out.println(cliente.getUsuario() + " salió. Conectados: " + clientes.size());
        }
    }

    // Guarda y reenvía a todos, incluido quien lo escribió.
    void publicar(Message mensaje) {
        repositorio.guardar(mensaje);
        String linea = ChatProtocol.codificar(mensaje);
        for (ClientHandler cliente : clientes) {
            cliente.enviar(linea);
        }
    }

    public static void main(String[] args) throws IOException {
        // Por defecto guarda en memoria y no hace falta MySQL. Con el argumento "mysql" usa la base.
        boolean conMySql = args.length > 0 && args[0].equals("mysql");
        MessageRepository repositorio = conMySql ? new JdbcMessageRepository() : new InMemoryMessageRepository();
        System.out.println(conMySql ? "Guardando los mensajes en MySQL" : "Guardando los mensajes en memoria (sin MySQL)");
        new ChatServer(repositorio).iniciar();
    }
}

Al terminar de pegar, los subrayados rojos de ClientHandler deben desaparecer. Si quedan rojos, revisen que el archivo ChatServer.java esté dentro del paquete network y que la primera línea diga package cr.ac.una.est.minidiscord.network;.

Ver explicación del código, línea por línea.

private final List<ClientHandler> clientes = new CopyOnWriteArrayList<>(); La lista de todos los clientes conectados. Varios hilos la modifican a la vez (entra y sale gente), por eso es una colección concurrente.

new ServerSocket(ChatProtocol.PUERTO) Reserva el puerto 5050 en esta computadora. Si otro programa ya lo usa, falla con BindException: Address already in use.

Socket conexion = servidor.accept(); Espera hasta que llegue un cliente, y devuelve un Socket nuevo: la línea directa con él.

new Thread(atencion, "cliente-" + conexion.getPort()).start(); Un hilo nuevo se encarga de ese cliente, y el hilo principal vuelve de inmediato a esperar al siguiente. Con start() se crea el hilo; con run() no.

registrar Le manda al cliente nuevo el historial de mensajes y después lo agrega a la lista, para que reciba lo que se escriba desde ese momento.

publicar Guarda el mensaje y lo reparte a todos los clientes, incluido el que lo escribió. Si guardar falla, no se reparte nada.

boolean conMySql = args.length > 0 && args[0].equals("mysql"); Por defecto el servidor guarda en memoria. Solo si se le pasa el argumento mysql usaría la base de datos. Ustedes no necesitan hacer nada: se ejecuta tal cual.

ChatClient es la parte de red de la ventana: se conecta al servidor, escucha en un hilo de fondo y envía lo que escribe la persona. No sabe nada de ventanas: recibe dos funciones, una para lo que llega y otra para los errores, y quien lo use decide qué hacer.

  2. Escojan New y después Java Class.
  3. Escriban exactamente ChatClient y presionen Enter. Se abre el archivo ChatClient.java.

network/ChatClient.java
package cr.ac.una.est.minidiscord.network;

import cr.ac.una.est.minidiscord.business.model.Message;
import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.InetSocketAddress;
import java.net.Socket;
import java.util.function.Consumer;

// Del lado del cliente: se conecta al servidor y escucha en un hilo de fondo.
// Esta clase no conoce JavaFX; quien la use decide cómo mostrar lo que llega.
public class ChatClient {

    private static final int ESPERA_CONEXION_MS = 3000;

    private Socket conexion;
    // volatile: la asigna el hilo de fondo y la lee el hilo de la interfaz.
    private volatile PrintWriter salida;

    // Bloquea hasta conectar: hay que llamarlo desde un hilo de fondo, no desde el de la interfaz.
    public void conectar(String host, String usuario,
                         Consumer<Message> alRecibir, Consumer<String> alError) throws IOException {
        conexion = new Socket();
        conexion.connect(new InetSocketAddress(host, ChatProtocol.PUERTO), ESPERA_CONEXION_MS);
        salida = new PrintWriter(conexion.getOutputStream(), true);
        BufferedReader entrada = new BufferedReader(new InputStreamReader(conexion.getInputStream()));

        salida.println("HELLO|" + usuario);

        Thread oyente = new Thread(() -> escuchar(entrada, alRecibir, alError), "oyente-servidor");
        oyente.setDaemon(true);
        oyente.start();
    }

    // Corre en el hilo "oyente": readLine bloquea hasta que el servidor manda algo.
    private void escuchar(BufferedReader entrada, Consumer<Message> alRecibir, Consumer<String> alError) {
        boolean huboError = false;
        try {
            String linea;
            while ((linea = entrada.readLine()) != null) {
                if (linea.startsWith("ERR|")) {
                    huboError = true;
                    alError.accept(linea.substring(4));
                } else {
                    alRecibir.accept(ChatProtocol.decodificar(linea));
                }
            }
            if (!huboError) {
                alError.accept("El servidor cerró la conexión.");
            }
        } catch (IOException e) {
            alError.accept("Se perdió la conexión: " + e.getMessage());
        }
    }

    public void enviar(String texto) {
        if (salida == null) {
            throw new IllegalStateException("Todavía no hay conexión con el servidor.");
        }
        salida.println("MSG|" + texto);
    }

    public void cerrar() {
        try {
            if (conexion != null) {
                conexion.close();
            }
        } catch (IOException e) {
            // ya se está cerrando; no hay nada más que hacer
        }
    }
}
Ver explicación del código, línea por línea.

private static final int ESPERA_CONEXION_MS = 3000; Tiempo máximo para conectarse: tres segundos. Sin esto, si la IP está mal, la persona cree que todo se congeló.

private volatile PrintWriter salida; volatile es necesario porque este campo lo escribe un hilo (el que conecta) y lo lee otro (el de la ventana, al enviar). volatile garantiza que el cambio que hace uno lo vea el otro de inmediato.

Consumer<Message> alRecibir, Consumer<String> alError Un Consumer es una función que recibe un dato y no devuelve nada. ChatClient no sabe qué hacer con un mensaje que llega: se lo deja a quien lo use. Así no depende de JavaFX.

conexion.connect(new InetSocketAddress(host, ChatProtocol.PUERTO), ESPERA_CONEXION_MS); Se conecta al servidor con un tiempo máximo. Si se vence, lanza SocketTimeoutException.

salida.println("HELLO|" + usuario); El saludo: lo primero que el servidor espera.

Thread oyente = new Thread(() -> escuchar(entrada, alRecibir, alError), "oyente-servidor"); El hilo oyente: se pasa la vida esperando al servidor. setDaemon(true) lo marca de fondo, para que no mantenga vivo el programa al cerrar la ventana.

escuchar Se ejecuta en el hilo oyente. Si la línea empieza con ERR| es un error del servidor; si no, es un mensaje, y ChatProtocol.decodificar lo convierte en un Message.

enviar Manda MSG| seguido del texto. Si todavía no hay conexión, lanza un error con un texto claro.

presentation/controller/ChatViewController.java
package cr.ac.una.est.minidiscord.presentation.controller;

import cr.ac.una.est.minidiscord.business.model.Message;
import cr.ac.una.est.minidiscord.business.model.User;
import cr.ac.una.est.minidiscord.business.service.ChatService;
import cr.ac.una.est.minidiscord.network.ChatClient;
import cr.ac.una.est.minidiscord.presentation.component.Avatars;
import cr.ac.una.est.minidiscord.presentation.component.MessageCell;
import javafx.application.Platform;
import javafx.collections.FXCollections;
import javafx.collections.ObservableList;
import javafx.concurrent.Task;
import javafx.fxml.FXML;
import javafx.scene.control.Label;
import javafx.scene.control.ListView;
import javafx.scene.control.TextField;
import javafx.scene.layout.StackPane;

public class ChatViewController {

    // @FXML conecta estos campos con los elementos del archivo FXML
    @FXML private ListView<Message> messageListView;
    @FXML private TextField messageInputField;
    @FXML private Label statusLabel;
    @FXML private Label userNameLabel;
    @FXML private StackPane userAvatarHolder;

    private final ChatService chatService = new ChatService();

    // Lista observable (patrón Observer): cuando se agrega un Message,
    // el ListView se actualiza solo.
    private final ObservableList<Message> messages = FXCollections.observableArrayList();

    // La ventana ya no habla con la base: habla con el servidor.
    private final ChatClient chatClient = new ChatClient();

    // Lo asigna App después de pedir el nombre.
    private User currentUser;

    @FXML
    public void initialize() {
        messageListView.setItems(messages);

        // El cell factory dice cómo dibujar cada fila.
        messageListView.setCellFactory(lista -> new MessageCell());

        // La franja roja solo ocupa espacio mientras tenga texto.
        statusLabel.visibleProperty().bind(statusLabel.textProperty().isNotEmpty());
        statusLabel.managedProperty().bind(statusLabel.visibleProperty());
    }

    public void setCurrentUser(User user) {
        this.currentUser = user;
        userNameLabel.setText(user.getUsername());
        userAvatarHolder.getChildren().setAll(Avatars.create(user.getUsername(), 16));
    }

    // Conectar bloquea hasta que el servidor responde, así que se hace en una Task.
    public void conectar(String host) {
        Task<Void> tarea = new Task<>() {
            @Override
            protected Void call() throws Exception {
                // Estas dos funciones las llama el hilo oyente: por eso usan runLater.
                chatClient.conectar(host, currentUser.getUsername(),
                        mensaje -> Platform.runLater(() -> mostrar(mensaje)),
                        error -> Platform.runLater(() -> statusLabel.setText(error)));
                return null;
            }
        };
        tarea.setOnFailed(e -> statusLabel.setText("No se pudo conectar: " + tarea.getException().getMessage()));

        Thread hilo = new Thread(tarea, "conectar");
        hilo.setDaemon(true);
        hilo.start();
    }

    @FXML
    private void handleSendMessage() {
        try {
            // Se valida aquí con el mismo ChatService; el servidor lo valida otra vez.
            Message nuevoMsg = chatService.processMessage(currentUser, messageInputField.getText());
            chatClient.enviar(nuevoMsg.getContent());
            messageInputField.clear();
            statusLabel.setText("");
        } catch (IllegalArgumentException | IllegalStateException e) {
            statusLabel.setText(e.getMessage());
        }
    }

    // Siempre corre en el hilo de la interfaz.
    private void mostrar(Message mensaje) {
        messages.add(mensaje);
        scrollToEnd();
    }

    private void scrollToEnd() {
        if (!messages.isEmpty()) {
            messageListView.scrollTo(messages.size() - 1);
        }
    }
}
Ver explicación del código, línea por línea.

private final ChatClient chatClient = new ChatClient(); Reemplaza al repositorio. La ventana habla con el servidor, no con la base de datos.

Task<Void> tarea = new Task<>() { ... } Conectar puede tardar y bloquea. Si se hiciera en el hilo de la ventana, la ventana se congelaría. Por eso se hace en una Task: call() corre en un hilo de fondo.

mensaje -> Platform.runLater(() -> mostrar(mensaje)) La línea más importante. La función que se le pasa a ChatClient la llama el hilo oyente, no el hilo de la ventana. Pero mostrar cambia la ventana, y eso solo se puede hacer desde el hilo de la interfaz. Platform.runLater le pide a ese hilo que lo haga cuando pueda. Sin esto, JavaFX lanza Not on FX application thread.

error -> Platform.runLater(() -> statusLabel.setText(error)) Lo mismo para los errores: se muestran en la franja roja, pero desde el hilo correcto.

tarea.setOnFailed(e -> statusLabel.setText("No se pudo conectar: " + ...)); Si conectar falla (por ejemplo, Connection refused), este manejador corre en el hilo de la interfaz, así que sí puede tocar la franja roja directamente.

new Thread(tarea, "conectar") Una Task es un Runnable: se le entrega a un hilo. Se marca daemon para que cerrar la ventana cierre el programa.

chatClient.enviar(nuevoMsg.getContent()); Al presionar Enter, se valida con ChatService como siempre y se envía el texto al servidor. El mensaje aparece en la lista cuando el servidor lo devuelve, igual que le aparece a todos los demás: así hay una sola fuente de verdad.

private void mostrar(Message mensaje) Agrega el mensaje a la lista observable. Siempre corre en el hilo de la interfaz, porque se llama dentro de un runLater.

Para pensar: ¿Por qué conectar se hace dentro de una Task y no directamente?

Ver respuesta

Porque conectar bloquea hasta que el servidor responde. Si se hiciera en el hilo de la interfaz, la ventana se congelaría mientras tanto. La regla es: nada lento en el hilo de la interfaz.

package cr.ac.una.est.minidiscord;

import cr.ac.una.est.minidiscord.business.model.User;
import cr.ac.una.est.minidiscord.business.service.ChatService;
import cr.ac.una.est.minidiscord.presentation.controller.ChatViewController;
import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Scene;
import javafx.scene.control.TextInputDialog;
import javafx.stage.Stage;
import java.io.IOException;
import java.util.Optional;

// App hereda de Application: así JavaFX sabe cómo arrancarla
public class App extends Application {

    private static final String HOJA_ESTILOS = "/cr/ac/una/est/minidiscord/presentation/view/discord.css";

    @Override
    public void start(Stage stage) throws IOException {
        // Primero se pregunta quién es el usuario.
        User usuario = pedirUsuario();
        if (usuario == null) {
            return; // la persona canceló el cuadro: no se abre la ventana
        }

        String servidor = pedirServidor();
        if (servidor == null) {
            return;
        }

        // El FXMLLoader lee el archivo FXML y arma la ventana
        FXMLLoader fxmlLoader = new FXMLLoader(App.class.getResource("/cr/ac/una/est/minidiscord/presentation/view/chat-view.fxml"));

        // La escena contiene todo lo que se ve dentro de la ventana
        Scene scene = new Scene(fxmlLoader.load(), 960, 600);

        // El CSS se aplica a toda la escena
        scene.getStylesheets().add(App.class.getResource(HOJA_ESTILOS).toExternalForm());

        // load() ya creó el controller; aquí se le pasa el usuario
        ChatViewController controller = fxmlLoader.getController();
        controller.setCurrentUser(usuario);

        // El Stage es la ventana del sistema operativo
        stage.setTitle("Mini-Discord UNA");
        stage.setMinWidth(640);
        stage.setMinHeight(400);
        stage.setScene(scene);
        stage.show();
    }

    // Repite la pregunta hasta que el nombre sirva; devuelve null si cancelan.
    private User pedirUsuario() {
        ChatService servicio = new ChatService();

        TextInputDialog dialogo = new TextInputDialog();
        dialogo.setTitle("Mini-Discord UNA");
        dialogo.setHeaderText("Elija su nombre de usuario");
        dialogo.setContentText("Usuario:");
        dialogo.getDialogPane().getStylesheets().add(App.class.getResource(HOJA_ESTILOS).toExternalForm());

        while (true) {
            Optional<String> respuesta = dialogo.showAndWait();
            if (respuesta.isEmpty()) {
                return null;
            }
            try {
                return servicio.createUser(respuesta.get());
            } catch (IllegalArgumentException e) {
                dialogo.setHeaderText(e.getMessage());
            }
        }
    }

    // Pregunta en qué computadora corre el servidor. localhost es esta misma computadora.
    private String pedirServidor() {
        TextInputDialog dialogo = new TextInputDialog("localhost");
        dialogo.setTitle("Mini-Discord UNA");
        dialogo.setHeaderText("Dirección del servidor");
        dialogo.setContentText("IP o nombre:");
        dialogo.getDialogPane().getStylesheets().add(App.class.getResource(HOJA_ESTILOS).toExternalForm());
        return dialogo.showAndWait().map(String::trim).filter(t -> !t.isEmpty()).orElse(null);
    }

    public static void main(String[] args) {
        launch();
    }
}
Ver explicación del código, línea por línea.

private String pedirServidor() Muestra un cuadro que pregunta en qué computadora está el servidor. El valor que aparece escrito es localhost, que significa "esta misma computadora", y sirve para probar solos. Si la persona cancela, devuelve null.

dialogo.showAndWait().map(String::trim).filter(t -> !t.isEmpty()).orElse(null) La respuesta viene en un Optional (una caja que puede tener texto o estar vacía). map le quita los espacios, filter descarta el texto vacío, y orElse(null) devuelve null si no quedó nada.

controller.conectar(servidor); Después de darle el usuario a la ventana, se le pide que se conecte. Eso inicia la Task del paso anterior.

Paso 12: Ver con sus ojos el error más común

Este paso es opcional, pero es el mejor ejemplo de por qué existe Platform.runLater. Van a quitarlo a propósito para ver el error, y después lo devuelven.

Si algo falla

Busquen aquí el mensaje que ven. Son los errores que sí pueden aparecer.

El código aparece en rojo en IntelliJ

Pasen el mouse sobre el subrayado rojo: IntelliJ explica qué falta. Las causas más comunes:

  • Cannot resolve symbol sobre el nombre de una clase: esa clase todavía no existe o se creó en el paquete equivocado. Revisen que ChatProtocol, ClientHandler, ChatServer y ChatClient estén en network, y que InMemoryMessageRepository esté en data.dao.
  • Package name does not correspond to the file path: el archivo está en una carpeta que no corresponde a su línea package. Arrástrenlo con el mouse a la carpeta correcta, o bórrenlo y créenlo de nuevo desde el paquete correcto.
  • Quedó algo del código anterior mezclado con el nuevo: al pegar, el archivo no estaba completamente vacío. Hagan Ctrl+A, Delete y peguen de nuevo.
  • Se copió solo una parte del código. Usen siempre el botón Copiar del bloque, que copia todo.
"release version 21 not supported" o "invalid target release"

El Java del proyecto es menor a 21. Vayan a File → Project Structure → Project y escojan en SDK un Java de versión 21 o superior (Paso 1.3).

El archivo pom.xml aparece en rojo, o no se descargan las librerías

Maven no terminó de cargar. Abran la pestaña Maven (a la derecha) y pulsen el botón de Reload All Maven Projects (dos flechas circulares). Comprueben que tienen internet.

BindException: Address already in use

Ya hay un servidor encendido en el puerto 5050. Busquen su pestaña en la ventana Run y pulsen el cuadrado rojo. Si no la encuentran, cierren IntelliJ y vuelvan a abrirlo.

"ChatServer is not allowed to run in parallel"

No es un error: significa que el servidor ya está encendido. Pulsen Cancel.

La ventana abre pero dice "No se pudo conectar: Connection refused"

El servidor no está encendido (Paso 7), o la dirección que escribieron no es la del servidor. Encienda el servidor y vuelvan a ejecutar App.

"Not on FX application thread"

Falta el Platform.runLater en ChatViewController. Compárenlo con el código del Paso 9 (Paso 12 explica este error).

No puedo abrir dos ventanas de App

Falta activar Allow multiple instances en Edit Configurations → App → Modify options (Paso 11.2).

El mensaje de otro usuario no me llega, pero el mío sí

Revisen que las dos ventanas se hayan conectado al mismo servidor (la misma IP) y que el servidor siga encendido. En la pestaña ChatServer deben verse las dos entradas.

Retos para quien termine primero

Estos retos son opcionales. No tienen código dado: tienen que pensarlos.

  1. Hilos virtuales. En ChatServer, la línea que crea el hilo de cada cliente usa new Thread(...). Investiguen Thread.ofVirtual() (Java 21) y cámbienla. Comprueben que el chat sigue funcionando y expliquen qué cambió y qué no.
  2. La brecha del historial. En el método registrar de ChatServer hay un instante en que un mensaje nuevo se puede perder: entre mandar el historial y agregar al cliente a la lista. Identifíquenlo y propongan cómo arreglarlo con synchronized.
  3. Quién está conectado. Agreguen una línea nueva al protocolo, por ejemplo USERS, que haga que el servidor responda con los nombres de los conectados. Antes de programar, escriban qué archivos tendrían que cambiar y cuáles no.
