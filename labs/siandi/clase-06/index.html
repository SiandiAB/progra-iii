Introducción al Laboratorio

En este laboratorio autoguiado aprenderás paso a paso a construir una aplicación completa de escritorio en Java utilizando JavaFX, Maven y la Arquitectura de 3 Capas (Presentación, Negocio y Entidades). El proyecto consiste en un sistema inteligente de validación de registro de usuarios que evalúa en tiempo real la fortaleza de una contraseña utilizando expresiones regulares (Pattern), actualiza dinámicamente una barra de progreso y permite alternar la visibilidad de los caracteres escritos.

Enfoque Pedagógico: Este manual está diseñado para guiarte desde la creación de cero del proyecto en IntelliJ IDEA hasta la estructuración de paquetes, la escritura de código limpio y la comprensión profunda de cómo la capa de Presentación se comunica con la capa de Negocio.

Paso 1: Creación del Proyecto en IntelliJ IDEA

1.1 Configurar los parámetros iniciales del asistente
  1. Abre IntelliJ IDEA y selecciona File → New → Project.
  2. En el panel izquierdo, selecciona JavaFX. Si no aparece directamente, búscalo en los generadores o selecciona tipo Maven con arquetipo JavaFX.
  3. En el selector de Build system, elige obligatoriamente Maven.
  4. En el campo JDK, asegúrate de tener seleccionado Java 21 (o superior compatible).
1.2 Explicación de los campos de relleno (Artifact, Group y Package)

Al configurar el proyecto, el asistente te pedirá rellenar identificadores clave de Maven y Java:

  • GroupId: cr.ac.una.est → Representa la organización o dominio invertido (en este caso, Universidad Nacional, Estudiantes). Define el espacio de nombres raíz para Maven.
  • ArtifactId: registrousuariosfx → Es el nombre único que tendrá tu archivo empaquetado (.jar) y la carpeta principal del proyecto compilado.
  • Package name / Paquete Base: cr.ac.una.est.registrousuariosfx → La ruta lógica en disco dentro de la cual residirán todos tus archivos de código fuente Java.
Verificación de ubicación: Para comprobar que tus carpetas se crearon bien, despliega el árbol de directorios en el panel izquierdo de IntelliJ (Project). Si cierras la carpeta java y el paquete raíz se oculta correctamente dentro de ella, significa que la jerarquía es coherente. Si un archivo queda "flotando" fuera de la estructura de carpetas al contraerla, no está bien ubicado.

Paso 2: Configuración del pom.xml

2.1 ¿Para qué sirve el pom.xml?

El archivo pom.xml (Project Object Model) es el corazón de Maven. En él se especifican las dependencias externas que tu proyecto necesita (como los módulos de JavaFX) y los plugins de compilación, evitando que tengas que descargar archivos .jar manualmente de internet.

Abre tu archivo pom.xml en la raíz del proyecto y asegúrate de que contenga la siguiente estructura adaptada a Java 21 y JavaFX 21.0.6:

<?xml version="1.0" encoding="UTF-8"?> <project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd"> <modelVersion>4.0.0</modelVersion> <groupId>cr.ac.una.est</groupId> <artifactId>registrousuariosfx</artifactId> <version>1.0-SNAPSHOT</version> <name>RegistroUsuariosFX</name> <properties> <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding> <junit.version>5.12.1</junit.version> </properties> <dependencies> <dependency> <groupId>org.openjfx</groupId> <artifactId>javafx-controls</artifactId> <version>21.0.6</version> </dependency> <dependency> <groupId>org.openjfx</groupId> <artifactId>javafx-fxml</artifactId> <version>21.0.6</version> </dependency> <dependency> <groupId>org.junit.jupiter</groupId> <artifactId>junit-jupiter-api</artifactId> <version>${junit.version}</version> <scope>test</scope> </dependency> </dependencies> <build> <plugins> <plugin> <groupId>org.apache.maven.plugins</groupId> <artifactId>maven-compiler-plugin</artifactId> <version>3.13.0</version> <configuration> <source>21</source> <target>21</target> </configuration> </plugin> </plugins> </build> </project>
Ver explicación del código línea por línea.

<project> y <modelVersion>: Es la etiqueta raíz que envuelve todo el archivo. El modelo 4.0.0 es el estándar actual de Maven.

<groupId>, <artifactId>, <version>: Son las "coordenadas" de tu proyecto. Definen quién eres, cómo se llama tu proyecto y en qué etapa está (SNAPSHOT = desarrollo activo).

<properties>: Bloque de variables globales. Aquí le indicamos a Maven que todo el texto usará UTF-8 (para soportar tildes y eñes).

<dependencies>: Aquí enlistamos los "paquetes externos" que necesitamos. Las dependencias javafx-controls (botones, barras) y javafx-fxml (leer el diseño visual) son indispensables para JavaFX. Maven las descargará automáticamente.

<build> y <plugins>: Configuran cómo se va a compilar el proyecto. Le indicamos explícitamente a Java (con <source> y <target>) que utilice estrictamente la versión 21.

2.2 Recargar Maven

Cada vez que modifiques el pom.xml, aparecerá un icono flotante con el logotipo de Maven (un pequeño elefante o símbolo de actualización) en la esquina superior derecha del editor, o en la pestaña lateral Maven. Haz clic en Reload All Maven Projects para descargar e indexar las librerías.

Paso 3: Estructuración de Paquetes (Arquitectura de 3 Capas)

3.1 Limpieza de archivos por defecto y creación de paquetes

Los asistentes de IntelliJ suelen crear clases de ejemplo (como HelloApplication). Elimínalas para mantener el espacio de trabajo limpio. Luego, dentro de la ruta src/main/java/cr/ac/una/est/registrousuariosfx, crea los siguientes subpaquetes haciendo clic derecho → New → Package. Cada uno representará una capa física de nuestra arquitectura:

  • model → Capa de Entidades / Datos: Almacenará las clases que representan los objetos del dominio y estructuras de datos puros (ej. Usuario.java).
  • service → Capa de Negocio: Contendrá la lógica y reglas algorítmicas de la aplicación, como la evaluación de contraseñas y uso de expresiones regulares (ej. RegistroService.java).
  • view → Capa de Presentación: Agrupará las interfaces gráficas y los controladores Java que interactúan directamente con la pantalla (ej. RegistroFXVista.java).
¿Cómo saber si el paquete está bien ubicado? Si contraes (cierras) la carpeta registrousuariosfx en el panel lateral y los paquetes model, service y view desaparecen de la vista por estar anidados dentro de ella, sabrás que están correctamente estructurados como subdirectorios lógicos.
3.2 Configuración del archivo module-info.java

JavaFX utiliza el sistema modular de Java (JPMS). En la raíz de src/main/java/cr/ac/una/est/registrousuariosfx, verifica o crea el archivo module-info.java:

module cr.ac.una.est.registrousuariosfx { requires javafx.controls; requires javafx.fxml; // Permite que el cargador FXML acceda por reflexión al controlador de la vista opens cr.ac.una.est.registrousuariosfx.view to javafx.fxml; exports cr.ac.una.est.registrousuariosfx; exports cr.ac.una.est.registrousuariosfx.model; exports cr.ac.una.est.registrousuariosfx.service; exports cr.ac.una.est.registrousuariosfx.view; }
Ver explicación del código línea por línea.

module cr.ac.una.est...: Esta línea le dice a Java: "Este proyecto es un módulo independiente y este es su nombre oficial".

requires javafx.controls; y requires javafx.fxml;: Declaramos explícitamente de qué otros módulos dependemos. Sin esto, Java bloqueará por seguridad nuestro intento de usar botones o cargar el FXML.

opens cr.ac...view to javafx.fxml;: ¡Esta línea es vital! JavaFX necesita usar una técnica llamada Reflexión para leer tu archivo FXML y conectarlo con tu controlador Java. Con opens abrimos una "puerta de seguridad" exclusivamente para que el motor de JavaFX pueda "ver" nuestro paquete de la vista.

exports ...: Al revés que requires, aquí le decimos al sistema modular de Java cuáles de nuestros paquetes están disponibles para ser ejecutados desde el exterior al arrancar.

Paso 4: Capa de Entidades (Model) y Capa de Negocio (Service)

4.1 Creando la clase Usuario.java (Capa de Entidades)

Esta clase representa la entidad pura de usuario. No sabe nada de contraseñas visuales, solo almacena datos. Créala dentro de tu paquete model:

package cr.ac.una.est.registrousuariosfx.model; public class Usuario { private String contrasena; private int nivelSeguridad; public Usuario(String contrasena, int nivelSeguridad) { this.contrasena = contrasena; this.nivelSeguridad = nivelSeguridad; } public String getContrasena() { return contrasena; } public void setContrasena(String contrasena) { this.contrasena = contrasena; } public int getNivelSeguridad() { return nivelSeguridad; } public void setNivelSeguridad(int nivelSeguridad) { this.nivelSeguridad = nivelSeguridad; } }
Ver explicación del código línea por línea.

package cr.ac...model;: Declara formalmente a qué carpeta lógica pertenece este archivo.

public class Usuario: Define el "molde" o plantilla. A partir de aquí se crearán los objetos usuario en memoria.

private String contrasena; y private int nivelSeguridad;: Son los atributos del molde. Utilizamos private por el principio de Encapsulamiento: evitamos que otra clase modifique estos valores directamente sin permiso.

public Usuario(String contrasena, int nivelSeguridad): Es el Constructor. Se ejecuta obligatoriamente en el instante en que alguien escribe new Usuario(...) para inyectarle los valores iniciales al objeto en el momento de su nacimiento.

this.contrasena = contrasena;: La palabra reservada this hace referencia a "los atributos de esta clase". Como el parámetro se llama igual, usamos this para diferenciarlos.

get... y set...: Dado que los atributos son privados, creamos métodos públicos para consultarlos (Getters) o modificarlos (Setters) de forma controlada.

4.2 Creando la clase RegistroService.java (Capa de Negocio)

Crea este archivo dentro de tu paquete service. Contiene la lógica algorítmica para evaluar contraseñas utilizando Expresiones Regulares (Regex). Fíjate que aquí no hay botones ni etiquetas visuales; esta clase solo recibe strings, aplica reglas matemáticas o de negocio y devuelve resultados.

package cr.ac.una.est.registrousuariosfx.service; import cr.ac.una.est.registrousuariosfx.model.Usuario; import java.util.regex.Pattern; public class RegistroService { private static final Pattern TIENE_MAYUSCULA = Pattern.compile(".*[A-Z].*"); private static final Pattern TIENE_MINUSCULA = Pattern.compile(".*[a-z].*"); private static final Pattern TIENE_NUMERO = Pattern.compile(".*[0-9].*"); private static final Pattern TIENE_CARACTER_ESPECIAL = Pattern.compile(".*[^a-zA-Z0-9].*"); public Usuario evaluarFortaleza(String contrasena) { int puntos = 0; if (contrasena != null && !contrasena.isEmpty()) { if (contrasena.length() >= 8) puntos++; if (TIENE_MAYUSCULA.matcher(contrasena).matches()) puntos++; if (TIENE_MINUSCULA.matcher(contrasena).matches()) puntos++; if (TIENE_NUMERO.matcher(contrasena).matches()) puntos++; if (TIENE_CARACTER_ESPECIAL.matcher(contrasena).matches()) puntos++; } return new Usuario(contrasena, puntos); } public String obtenerDescripcionNivel(int nivelSeguridad) { switch (nivelSeguridad) { case 0: case 1: return "Muy débil"; case 2: return "Débil"; case 3: return "Media"; case 4: return "Fuerte"; case 5: return "Muy fuerte"; default: return "Desconocido"; } } public boolean confirmarCoincidencia(String contrasena, String confirmacion) { if (contrasena == null || confirmacion == null) return false; return contrasena.equals(confirmacion); } }
Ver explicación del código línea por línea.

private static final Pattern TIENE_MAYUSCULA = Pattern.compile(".*[A-Z].*");: Las expresiones regulares (regex) son fórmulas de texto para buscar patrones. Aquí le decimos a Java: "Busca cualquier cosa (.*), luego una letra de la A a la Z en mayúscula, y luego cualquier cosa (.*)". Lo declaramos static (se guarda en memoria una sola vez) y final (no puede modificarse). Pattern.compile traduce esa fórmula a lenguaje máquina.

public Usuario evaluarFortaleza(String contrasena): Este método recibe una cadena de texto y promete devolver un objeto completo de tipo Usuario como respuesta.

int puntos = 0;: Iniciamos un contador local en cero. Este contador sumará un máximo de 5 puntos.

if (contrasena != null && !contrasena.isEmpty()): Si el texto es "nulo" o está vacío, nos saltamos toda la evaluación para evitar un colapso.

if (contrasena.length() >= 8) puntos++;: Valida la longitud. Si tiene 8 o más caracteres, suma un punto.

TIENE_MAYUSCULA.matcher(contrasena).matches(): Enfrentamos el patrón contra la contraseña. .matcher() analiza el texto y .matches() responde true si lo encontró o false si no. Lo mismo ocurre para caracteres especiales (donde [^a-zA-Z0-9] significa "lo que NO sea letra o número").

Nota Pedagógica de Arquitectura:
return new Usuario(contrasena, puntos);
Una duda muy común aquí es: "¿Por qué usamos new Usuario? ¿Eso no sobreescribe un usuario que ya existía?".
La respuesta es No. En este laboratorio no tenemos una base de datos ni una lista global donde "guardemos" al usuario. Lo que estamos haciendo aquí es usar la clase Usuario como un simple contenedor (un DTO o Data Transfer Object). Estamos creando un objeto nuevo y temporal en la memoria RAM que empaqueta dos datos: la contraseña y su calificación. Cada vez que la persona teclea una letra nueva, el programa desecha el cálculo anterior, vuelve a evaluar de cero, crea una nueva "caja" con la nueva nota, y se la entrega a la vista para que actualice la barra de colores. ¡El objeto viaja, informa y luego se descarta de la memoria!

public String obtenerDescripcionNivel(int nivelSeguridad): Un traductor. Recibe el número del 0 al 5, y usando switch retorna una palabra en español que la vista pueda imprimir en pantalla.

public boolean confirmarCoincidencia(String contrasena, String confirmacion): Usa el método oficial de Java .equals() para verificar que ambas cadenas sean exactamente iguales carácter por carácter.

Paso 5: Capa de Presentación (View y FXML)

5.1 La separación dentro de la Capa de Presentación

En la arquitectura de 3 capas, la Capa de Presentación se encarga exclusivamente de la interfaz de usuario. En JavaFX, esta capa suele dividirse físicamente en dos archivos para mayor limpieza: la Vista (el archivo FXML) que define la disposición visual usando XML, y el Controlador (la clase Java en el paquete view) que enlaza los componentes y maneja los eventos del usuario (clics, escritura). Toda la validación matemática se delega a la Capa de Negocio (RegistroService).

5.2 Creando el archivo visual registro-view.fxml

Debes crear este archivo haciendo clic derecho exactamente en src/main/resources/cr/ac/una/est/registrousuariosfx/ → New → File, (asegúrate de que esté en la carpeta resources y no dentro de java), o directamente utilizando la herramienta visual Scene Builder.

<?xml version="1.0" encoding="UTF-8"?> <?import javafx.scene.control.*?> <?import javafx.scene.layout.*?> <AnchorPane prefHeight="400.0" prefWidth="400.0" xmlns="http://javafx.com/javafx/17.0.12" xmlns:fx="http://javafx.com/fxml/1" fx:controller="cr.ac.una.est.registrousuariosfx.view.RegistroFXVista"> <children> <Label layoutX="35.0" layoutY="20.0" style="-fx-font-weight: bold; -fx-font-size: 14px;" text="Validador de Registro de Usuario" /> <Label layoutX="35.0" layoutY="60.0" text="Contraseña:" /> <PasswordField fx:id="txtContrasena" layoutX="35.0" layoutY="80.0" prefHeight="26.0" prefWidth="250.0" /> <TextField fx:id="txtContrasenaVisible" layoutX="35.0" layoutY="80.0" managed="false" prefHeight="26.0" prefWidth="250.0" visible="false" /> <CheckBox fx:id="chkMostrar" layoutX="35.0" layoutY="115.0" mnemonicParsing="false" text="Mostrar contraseña" /> <Label fx:id="lblFortaleza" layoutX="35.0" layoutY="150.0" text="Fortaleza: " /> <ProgressBar fx:id="barraFortaleza" layoutX="35.0" layoutY="170.0" prefWidth="330.0" progress="0.0" /> <Label layoutX="35.0" layoutY="210.0" text="Confirmar contraseña:" /> <PasswordField fx:id="txtConfirmarContrasena" layoutX="35.0" layoutY="230.0" prefWidth="250.0" /> <Button fx:id="btnRegistrar" layoutX="35.0" layoutY="283.0" onAction="#onRegistrarButtonClick" text="Registrar" /> <Label fx:id="lblResultado" layoutX="35.0" layoutY="330.0" text="" /> </children> </AnchorPane>
Ver explicación del código línea por línea.

<?xml... ?> y <?import... ?>: Etiquetas iniciales necesarias para que la máquina sepa que estamos usando el lenguaje XML y para "importar" de la librería de JavaFX los controles visuales.

<AnchorPane prefHeight="400" ... fx:controller="cr.ac...view.RegistroFXVista">: AnchorPane es el lienzo principal que permite ubicar elementos usando coordenadas X e Y. El atributo clave es fx:controller, el cual enlaza mágicamente este diseño visual con la clase Java responsable de la lógica.

<children>: Etiqueta estructural. Indica que todos los botones y textos que van adentro son "hijos" del lienzo principal.

<PasswordField fx:id="txtContrasena" layoutX="35.0" layoutY="80.0" />: Dibuja una caja de texto que oculta los caracteres con puntitos. El atributo fx:id es su "número de cédula": gracias a ese ID, el controlador Java podrá encontrar esta caja específica.

<TextField fx:id="txtContrasenaVisible" ... managed="false" visible="false" />: Dibuja una caja de texto normal. La colocamos exactamente encima de la otra, pero le ponemos visible="false" (invisible) y managed="false" (el sistema ignora su espacio). Esto es un "truco": cuando el usuario marque la casilla "Mostrar contraseña", haremos invisible el PasswordField y haremos visible este TextField.

<Button fx:id="btnRegistrar" ... onAction="#onRegistrarButtonClick" text="Registrar" />: Crea el botón final. El atributo onAction le dice a la interfaz: "Cuando te hagan clic, busca inmediatamente en el controlador Java un método que se llame 'onRegistrarButtonClick' y ejecútalo".

5.3 Creando el controlador de UI RegistroFXVista.java (en el paquete view)

Crea este archivo en src/main/java/cr/ac/una/est/registrousuariosfx/view/. Esta clase es el "cerebro de la ventana". Recoge los clics del FXML, extrae la información, y le pide ayuda al Servicio (Capa de Negocio) para tomar decisiones:

package cr.ac.una.est.registrousuariosfx.view; import cr.ac.una.est.registrousuariosfx.model.Usuario; import cr.ac.una.est.registrousuariosfx.service.RegistroService; import javafx.fxml.FXML; import javafx.scene.control.*; public class RegistroFXVista { @FXML private PasswordField txtContrasena; @FXML private TextField txtContrasenaVisible; @FXML private CheckBox chkMostrar; @FXML private PasswordField txtConfirmarContrasena; @FXML private Button btnRegistrar; @FXML private Label lblFortaleza; @FXML private ProgressBar barraFortaleza; @FXML private Label lblResultado; // La capa de presentación se comunica con la capa de negocio instanciando el servicio private final RegistroService registroService = new RegistroService(); @FXML public void initialize() { txtContrasenaVisible.textProperty().bindBidirectional(txtContrasena.textProperty()); chkMostrar.setOnAction(event -> { boolean mostrar = chkMostrar.isSelected(); txtContrasenaVisible.setVisible(mostrar); txtContrasenaVisible.setManaged(mostrar); txtContrasena.setVisible(!mostrar); txtContrasena.setManaged(!mostrar); }); txtContrasena.textProperty().addListener((observable, valorAnterior, valorNuevo) -> { Usuario evaluacion = registroService.evaluarFortaleza(valorNuevo); lblFortaleza.setText("Fortaleza: " + registroService.obtenerDescripcionNivel(evaluacion.getNivelSeguridad())); barraFortaleza.setProgress(evaluacion.getNivelSeguridad() / 5.0); }); } @FXML protected void onRegistrarButtonClick() { String contrasena = txtContrasena.getText(); String confirmacion = txtConfirmarContrasena.getText(); if (contrasena.isBlank() || confirmacion.isBlank()) { lblResultado.setText("Error: Todos los campos son obligatorios."); lblResultado.setStyle("-fx-text-fill: red;"); return; } if (!registroService.confirmarCoincidencia(contrasena, confirmacion)) { lblResultado.setText("Error: Las contraseñas no coinciden."); lblResultado.setStyle("-fx-text-fill: crimson;"); return; } Usuario usuario = registroService.evaluarFortaleza(contrasena); if (usuario.getNivelSeguridad() < 3) { lblResultado.setText("Coincide, pero es demasiado débil."); lblResultado.setStyle("-fx-text-fill: darkorange;"); return; } lblResultado.setText("Registro exitoso!"); lblResultado.setStyle("-fx-text-fill: green;"); } }
Ver explicación del código línea por línea.

@FXML private PasswordField txtContrasena;: La anotación @FXML vincula cada variable Java con un elemento visual en tu archivo FXML (buscando coincidencia con el fx:id). JavaFX inicializa esto por ti, por eso no llevan un new al lado.

private final RegistroService registroService = new RegistroService();: Regla de oro de 3 capas. La Vista no hace cálculos matemáticos. La Vista instancia al servicio y le delega el trabajo pesado.

public void initialize(): Es un método especial en JavaFX que se dispara de forma automática apenas la ventana termina de cargar los gráficos. Lo usamos para preparar los eventos interactivos.

txtContrasenaVisible.textProperty().bindBidirectional(txtContrasena.textProperty());: Función poderosa de Binding Bidireccional. Sincroniza ambas cajas. Lo que teclees en la oculta aparecerá en la visible, y viceversa.

chkMostrar.setOnAction(event -> { ... });: Asignamos un "escuchador". Cuando el CheckBox reciba un clic, lee si está marcado (true o false) y enciende/apaga la caja visible e invisible alterando .setVisible() y .setManaged().

txtContrasena.textProperty().addListener((observable, valorAnterior, valorNuevo) -> { ... });: Este es el motor en tiempo real. Le "pegamos una oreja" a la caja de texto. Cada vez que el usuario presiona una tecla o borra algo, se activa. Nos interesan las letras que acaban de entrar, representadas en la variable valorNuevo.

Usuario evaluacion = registroService.evaluarFortaleza(valorNuevo);: Inmediatamente le pasamos ese nuevo texto al Servicio para que lo califique.

lblFortaleza.setText(...); y barraFortaleza.setProgress(evaluacion.getNivelSeguridad() / 5.0);: Actualizamos el texto de pantalla con el nombre de la fortaleza. Luego, llenamos la barra. Como la barra de JavaFX solo acepta valores de 0.0 a 1.0 (0% a 100%), dividimos los puntos sobre 5.0 para obtener la fracción correcta.

protected void onRegistrarButtonClick(): Este es el código vinculado al clic del botón "Registrar".

if (contrasena.isBlank() || confirmacion.isBlank()) { ... return; }: Si las cajas están en blanco, lanza un error rojo y ejecuta un return temprano. El return hace que el método aborte ahí mismo, evitando anidar demasiados else if.

if (!registroService.confirmarCoincidencia(...)): Le pide al servicio validar usando .equals() si son diferentes. Si no coinciden, aborta con otro texto rojo.

Si pasó los filtros, se vuelve a calcular la fortaleza. Si la nota es menor a 3, tiramos una alerta naranja. Si también superó esto, modificamos el texto y lo pintamos de verde con setStyle("-fx-text-fill: green;").

Paso 6: Lanzador Principal (RegistroApp.java)

6.1 Creando la clase de arranque

En la raíz del paquete cr.ac.una.est.registrousuariosfx, crea la clase RegistroApp que extiende Application. Esta es la llave de ignición del proyecto:

package cr.ac.una.est.registrousuariosfx; import javafx.application.Application; import javafx.fxml.FXMLLoader; import javafx.scene.Scene; import javafx.stage.Stage; import java.io.IOException; public class RegistroApp extends Application { @Override public void start(Stage stage) throws IOException { FXMLLoader fxmlLoader = new FXMLLoader(RegistroApp.class.getResource("/cr/ac/una/est/registrousuariosfx/registro-view.fxml")); Scene scene = new Scene(fxmlLoader.load()); stage.setTitle("Sistema UNA - Registro"); stage.setScene(scene); stage.show(); } public static void main(String[] args) { launch(); } }
Ver explicación del código línea por línea.

public class RegistroApp extends Application: Para que Java entienda que este programa es una aplicación visual de JavaFX y no un programa normal de consola, es absolutamente obligatorio hacer que la clase herede de Application.

@Override public void start(Stage stage): Al heredar, estamos obligados a sobrescribir este método. Es la "puerta de entrada" del mundo gráfico. La variable stage (Escenario) es el marco principal de la ventana que nos otorga el Sistema Operativo (la que tiene la X para cerrar, etc).

FXMLLoader fxmlLoader = new FXMLLoader(...): Creamos un "Cargador". Le pasamos la ruta estática donde se ubica nuestro dibujo XML. El cargador se encargará de leer el archivo, crear los botones en memoria e inyectarlos en la clase Controlador.

Scene scene = new Scene(fxmlLoader.load());: Un Stage (Marco) no puede mostrar los botones directamente. Necesita de una Scene (Escena). Aquí llamamos al .load() para compilar la vista y meterla dentro de una escena.

stage.setTitle(...): Cambia el texto que aparecerá en la barra superior de la ventana.

stage.setScene(scene); y stage.show();: Finalmente, colocamos la escena o lienzo dentro de la ventana de Windows/Mac, y ordenamos que la ventana se haga visible en la pantalla.

public static void main(String[] args) { launch(); }: Este es el método main de toda la vida de Java. La única línea que lleva adentro es launch(), un método heredado que arranca los motores internos de gráficos y termina llamando automáticamente al método start.

¡Listo para ejecutar! Haz clic en el botón verde de ejecución (Run) al lado del método main en RegistroApp y tu sistema gráfico de validación de contraseñas se desplegará exitosamente.
