¿De dónde viene Java?

Una breve historia antes de entrar en código.

El equipo

James Gosling, Mike Sheridan y Patrick Naughton iniciaron el proyecto en 1991 en Sun Microsystems.

"The Green Team"

Así se llamaba el grupo original.

¿Por qué lo crearon?

Querían un lenguaje para electrodomésticos inteligentes (TVs, microondas, controles remotos). Algo que corriera en cualquier dispositivo sin recompilar.

"Write Once, Run Anywhere"

Esa fue la visión desde el día 1.

El nombre

Primero se llamó Oak (roble), por un árbol que Gosling veía desde su oficina. Luego cambió a Java en 1995, por el café de la isla de Java.

Oak → Java

De un roble a una taza de café.

1991 Inicio del proyecto
1995 Java 1.0 — el mundo lo conoce
2010 Oracle compra Sun
Hoy Top 3 lenguajes del mundo

"Write Once, Run Anywhere"

"Escribir una vez, ejecutar en cualquier lugar."

El superpoder de la portabilidad en Java: compilás una vez, ejecutás en Windows, Mac y Linux sin cambios.

C++ Compilación Nativa

Código.cpp Compilador .exe

Atado a Windows. Necesita recompilarse para cada SO.

Compilación Híbrida

Código.java javac .class (Bytecode) JVM Win/Mac/Linux

El mismo .class corre en cualquier SO que tenga JVM.

Bytecode

"El idioma universal de Java." Es un código intermedio que ni es fuente ni es máquina. Lo entiende cualquier JVM.

JVM (Java Virtual Machine)

"El traductor que habla con cada sistema operativo." Lee bytecode y lo convierte en instrucciones nativas.

Garbage Collector (Recolector de Basura)

Java administra la memoria por ti. Comparémoslo con C++.

C++ Memoria Manual
memoria.cpp 
#include <iostream>
using namespace std;

int main() {
    // Reserva memoria
    int* p = new int(42);
    cout << *p << endl;

    // ¡Obligatorio liberar!
    delete p;
    return 0;
}
Memoria Automática
Memoria.java 
public class Memoria {
    public static void main(String[] args) {
        // Reserva memoria en el Montón (Heap)
        Integer num = new Integer(42);
        System.out.println(num);

        // ¡No necesitas delete!
        // El GC lo limpia solo.
    }
}
new delete Heap (Montón) GC Memory Leak

Advertencia: No es perfecto: si guardas referencias innecesarias, el GC no puede actuar y podés provocar una fuga de memoria (Memory Leak).

Tipos Elementales (Primitivos)

Los 8 tipos básicos de Java — rápidos y eficientes, viven en la Pila (Stack).

Tipo Tamaño Rango / Valores Ejemplo
byte 8 bits -128 a 127 byte edad = 25;
short 16 bits -32,768 a 32,767 short año = 2026;
int 32 bits -231 a 231-1 (±2.1 mil millones) int count = 100;
long 64 bits -263 a 263-1 long pop = 8_000_000_000L;
float 32 bits ±3.4×1038 (6-7 dígitos) float pi = 3.14f;
double 64 bits ±1.8×10308 (15 dígitos) double price = 99.99;
boolean 1 bit* true o false boolean ok = true;
char 16 bits '\u0000' a '\uFFFF' (Unicode) char letra = 'A';

Viven en la Pila (Stack)

Memoria LIFO: el último en entrar es el primero en salir. Rápida y ordenada. Las variables se borran solas al terminar el método.

int x = 42; // Directo en la Pila (Stack)

¿Por qué usar primitivos?

  • Más rápidos que los objetos (Wrappers).
  • No consumen memoria del Montón (Heap).
  • Ideales para bucles y cálculos intensivos.
  • No requieren new para crearse.

Wrapper Classes

"Envolturas" que convierten tipos primitivos en objetos — viven en el Montón (Heap).

Primitivo Wrapper Class Método útil de ejemplo
byte Byte Byte.parseByte("127")
short Short Short.parseShort("100")
int Integer Integer.parseInt("123")
long Long Long.parseLong("999")
float Float Float.parseFloat("3.14")
double Double Double.parseDouble("99.9")
boolean Boolean Boolean.parseBoolean("true")
char Character Character.isDigit('5')

¿Para qué necesitamos Wrappers?

1

Colecciones: ArrayList<int> → ArrayList<Integer>
Las colecciones solo guardan objetos, no tipos primitivos.

2

Métodos de conversión: Integer.parseInt("123")
Convierten texto a número, comparan, validan formatos.

3

Valores nulos: Integer x = null;
Un primitivo no puede ser null. Un Wrapper sí.

Autoboxing y Unboxing (auto-empaquetado / auto-desempaquetado)

Java convierte automáticamente entre primitivo y Wrapper desde Java 5. Boxing = primitivo → objeto. Unboxing = objeto → primitivo.

Integer x = 5; // Autoboxing: int → Integer
Java convierte automáticamente
int y = x; // Unboxing: Integer → int

Cuidado con los bucles: cada autoboxing crea un objeto nuevo en el Montón (Heap). Usá int para rendimiento, Integer solo cuando necesités colecciones u objetos.

static

Un solo valor compartido por todas las instancias de una clase.

Atributo de INSTANCIA (sin static)

color: "rojo"
color: "azul"
color: "negro"

Cada carro tiene su propio color. Si uno cambia, los otros no se enteran.

Atributo ESTÁTICO (con static)

Carro #1
Carro #2
Carro #3
totalCarros = 3

El contador es uno solo para todos. Cada new Carro() lo aumenta.

Carro.java 
public class Carro {
    // Atributo de INSTANCIA
    private String color;

    // Atributo ESTÁTICO (compartido)
    private static int totalCarros = 0;

    public Carro(String color) {
        this.color = color;
        totalCarros++;  // Aumenta el contador
    }

    public static int getTotalCarros() {
        return totalCarros;
    }
}

// Se usa sin crear objeto:
int t = Carro.getTotalCarros();  // → 3

static en la práctica

Tres situaciones donde sí o sí necesitás usar static.

Constantes globales

Math.PI

Valores que nunca cambian y son idénticos para todo el programa. No necesitás crear new Math() para usar PI.

Métodos de utilería

Integer.parseInt("123")

Funciones que no dependen de un objeto. Convertís texto a número sin crear un Integer antes.

Punto de entrada

public static void main(String[] args)

La JVM arranca llamando a main antes de que exista ningún objeto. Por eso debe ser static.

Regla de oro

Dato de CADA objeto → sin static

private String color;

El color es distinto en cada carro. Si uno se pinta de rojo, los demás no cambian.

Dato de TODA la clase → con static

private static int totalCarros;

El contador es compartido. Cada new Carro() aumenta el mismo número para todos.

Preguntate: "¿este valor debería ser igual para todos los objetos?" Si la respuesta es sí → static.

Retos extra (si terminás antes)

¿Qué es la recursividad?

En palabras simples:

Es cuando una función se llama a sí misma para resolver un problema. Como una muñeca rusa (matrioshka): cada una contiene una versión más pequeña de sí misma, hasta llegar a la más chiquita que ya no contiene a ninguna.

Ejemplo: factorial de 5

factorial(5) = 5 × factorial(4)
             = 5 × 4 × factorial(3)
             = 5 × 4 × 3 × factorial(2)
             = 5 × 4 × 3 × 2 × factorial(1)
             = 5 × 4 × 3 × 2 × 1
             = 120

Veamos el código completo:

public static int factorial(int n) {
    if (n <= 1) return 1; // ← CASO BASE
    return n * factorial(n - 1); // ← CASO RECURSIVO
}

Caso base: la salida

if (n <= 1) return 1;

¿Qué hace? Cuando n llega a 1 (o menos), la función NO se vuelve a llamar. Simplemente retorna 1.

¿Por qué 1? Porque el factorial de 1 es 1. Es el problema más simple y ya sabemos la respuesta sin calcular nada más.

¿Qué pasa si lo quito? La función se llamaría para siempre: factorial(5) → factorial(4) → factorial(3) → ... → -∞ hasta que la computadora colapsa (Stack Overflow).

Caso recursivo: la reducción

return n * factorial(n - 1);

¿Qué hace? Multiplica n por el factorial del número anterior (n - 1).

¿Cómo avanza? Cada llamada reduce n en 1, acercándose al caso base. Sin esta reducción, nunca llegaría a 1.

Ejemplo: factorial(5) necesita factorial(4), que necesita factorial(3)... hasta factorial(1) = 1.

Para recordar

Si no ponés un caso base, la función se llama infinitamente hasta que la computadora se queda sin memoria.
Eso se llama stack overflow (desbordamiento de pila).
