Anatomía de un Proyecto en IntelliJ IDEA

Comprenda la estructura física del sistema de archivos antes de codificar

Desde cero: Piense en un proyecto IntelliJ como un archivador de oficina. La carpeta src/ es el cajón donde guarda sus documentos originales (código .java). La carpeta out/ es donde el asistente coloca las fotocopias para distribución (código compilado .class). La carpeta .idea/ son las notas adhesivas que el asistente pega en el archivador para recordar cómo le gusta trabajar — son personales y no se las lleva cuando manda el archivador a otra oficina (Git).

Carpetas del Entorno de Desarrollo

  • .idea/ (Configuración del IDE): Almacena preferencias locales (historial, ventanas, base de datos). Regla: jamás se modifica manualmente ni se sube al repositorio Git.
  • src/ (Source Root sagrado): Es la carpeta raíz donde vive exclusivamente el código fuente Java. Todos los paquetes y clases deben nacer dentro de este directorio.
  • out/ o target/: Directorio generado automáticamente donde la máquina virtual (JVM) coloca el código compilado (bytecode .class).
  • External Libraries/: Sección que lista el JDK instalado (ejemplo: JDK 25) y las bibliotecas externas de soporte.

Representación Visual del Árbol 

Proyecto-Streaming/
├── .idea/                 <-- Configuración interna del IDE
├── src/                   <-- RAÍZ DE CÓDIGO FUENTE (.java)
│   └── seguridad/
│       └── streaming/
│           ├── model/     <-- Paquetes lógicos de Java
│           └── Main.java
├── out/                   <-- Archivos compilados (.class)
└── External Libraries/    <-- JDK 25 y librerías externas
Consejo profesional: Nunca cree archivos .java fuera de src/. Si lo hace, el compilador no podrá resolver los paquetes y mostrará errores de compilación.

Directory vs. Package (Directorio vs. Paquete)

Diferencie una carpeta común del sistema de nombres lógico de Java

Desde cero: Un directorio es la carpeta que ve en el explorador de archivos de Windows. Un paquete es una etiqueta que Java lee dentro del archivo (la línea package seguridad.streaming.model;). IntelliJ los mantiene sincronizados automáticamente, pero son conceptos distintos: si usted crea una carpeta con el explorador y mete un .java sin la línea package, Java no sabrá a qué paquete pertenece y el compilador marcará error. Regla fácil: siempre use New → Package en IntelliJ, nunca New → Directory para código Java.

Criterio Directory (Directorio) Package (Paquete)
¿Qué representa? Una carpeta física genérica del sistema operativo. Un namespace (espacio de nombres) que agrupa clases de Java coherentes.
Contenido típico Recursos no compilables (imágenes, scripts .sql, .properties). Exclusivamente archivos de código fuente Java (.java).
Notación y creación Se separa por barras: src/recursos/assets/ Se separa por puntos: seguridad.streaming.model
Declaración en archivo No requiere ninguna declaración interna. Exige la primera línea: package seguridad.streaming.model;
Prevención de choques No evita colisiones de nombres para el compilador. Permite tener clases homónimas en paquetes distintos sin colisión.

Regla de creación en IntelliJ IDEA: Al hacer clic derecho en src, seleccione siempre New → Package para sus clases de Java. Al escribir puntos (por ejemplo, seguridad.streaming), IntelliJ crea automáticamente la jerarquía de subcarpetas en su disco duro.

Estructuración de Carpetas para Arquitectura MVC

Prepárese para el diseño industrial dividiendo su aplicación en capas

Capas del Patrón MVC en Backend

  • model/ (Modelo): Contiene las entidades, reglas de negocio y portadores de datos (ejemplo: Cuenta, LogSesion, PlanStreaming).
  • view/ (Vista): Representa la interfaz de usuario, menús en consola o vistas gráficas que presentan la información al cliente.
  • controller/ (Controlador): Orquesta el flujo: recibe la solicitud de la Vista, valida credenciales con el Modelo y retorna el resultado.
  • util/ (Utilerías): Paquete de soporte para clases auxiliares (encriptación de claves, formato de fechas, validadores).

Analogía en 1 Minuto: El Restaurante

El Modelo es la alacena y los ingredientes: Representan la materia prima y el estado real de los alimentos. No toman órdenes de las mesas.

La Vista es el menú y el plato servido: Exclusivamente muestra las opciones al cliente y presenta el producto terminado.

El Controlador es el chef y el mesero: Toma la orden de la Vista, busca los datos al Modelo, aplica las reglas de cocinarse y entrega la respuesta final.

Primitivos, Wrappers y Memoria en Streaming

Comprenda por qué un dato opcional requiere una clase envoltura (Wrapper Class)

Desde cero: Java divide la memoria en dos zonas. La Pila (Stack) es como notas adhesivas en su escritorio: rápidas, pequeñas, y se botan al terminar el método. Aquí viven los primitivos: int, boolean, double, char. El Montón (Heap) es como un archivador grande: más lento pero con capacidad para objetos complejos. Aquí vive todo lo creado con new: String, Integer, ArrayList, sus propias clases. La diferencia clave: un primitivo nunca puede ser null (siempre tiene un valor por defecto, como 0). Un Wrapper como Integer sí puede ser null, lo que permite representar "no hay dato".

PIN Infantil: Primitivo vs. Wrapper

En una plataforma de Streaming, el PIN de control parental es opcional. Si el usuario no lo activa, la base de datos remota almacena el valor SQL NULL. 

public class Cuenta {
    private int intentosFallidos; // Primitivo en Stack: es obligatorio
    private Integer pinControlParental; // Wrapper en Heap: tolera null
    
    public boolean tienePinActivo() {
        return pinControlParental != null;
    }
}

Peligro: Si declarara int pin; y el usuario no tuviere PIN (NULL), Java asignaría 0, bloqueando la cuenta con el PIN "0000".

Aliasing: Dos Dispositivos, Una Cuenta

El aliasing ocurre al asignar una referencia a otra: ambas apuntan al único objeto en el Heap. 

Cuenta sesionTV = new Cuenta("usuario@mail.com");
// ALIASING: No clona la cuenta, comparte la referencia en memoria
Cuenta sesionMovil = sesionTV;

sesionMovil.bloquearCuenta();
// sesionTV.isBloqueada() ahora es true en ambos dispositivos

Regla práctica: Los tipos primitivos se guardan rápidamente en la Pila (Stack). Los objetos y Wrappers viven en el Montón (Heap) y son administrados automáticamente por el Garbage Collector.

Miembros Estáticos (static) en Streaming

Diferencie los datos individuales del usuario frente a las estadísticas del servidor global

Desde cero: En Java hay dos mundos que conviven en una misma clase. El mundo de instancia (sin static): cada objeto creado con new tiene su propia copia del atributo — como cada televisor tiene su propio control remoto. El mundo estático (con static): una sola copia compartida por todos los objetos de esa clase — como la señal de satélite que llega a todas las casas. Si usted cambia un atributo de instancia, solo afecta a ESE objeto. Si cambia un atributo estático, afecta a TODOS los objetos automáticamente. Los métodos estáticos se llaman con Clase.metodo(), sin necesidad de crear un objeto.

Instancia vs. Estático (Servidor)

Lo que no lleva static pertenece a un usuario individual. Lo que lleva static pertenece a la clase entera y se comparte. 

public class Cuenta {
    // INSTANCIA: Intentos fallidos individuales de cada cuenta
    private int intentosFallidos = 0;
    
    // ESTÁTICO: Servidor Global (cuántas personas ven cine ahora)
    private static int totalSesionesActivas = 0;
    
    public void registrarLoginExitoso() {
        this.intentosFallidos = 0;      // Solo para ESTA cuenta
        Cuenta.totalSesionesActivas++;  // Sube en el servidor GLOBAL
    }
}

Constantes de Seguridad del Sistema

Las constantes public static final definen reglas inmutables de seguridad para todos. 

public class Cuenta {
    // Límite inmutable para toda la plataforma
    public static final int MAX_INTENTOS = 3;
    
    public void validarIntento() {
        this.intentosFallidos++;
        if (this.intentosFallidos >= MAX_INTENTOS) {
            this.bloquearCuenta();
        }
    }
}
Analogía: El atributo de instancia es su televisor particular. El atributo static es la central de servidores de Netflix que monitorea a todos los usuarios del país al mismo tiempo.

Programación Genérica en Java (Generics / <T>)

Garantice la seguridad de tipos (Type Safety) eliminando conversiones manuales en tiempo de ejecución

Desde cero: Imagine que tiene cajas de cartón para guardar cosas. Sin genéricos, todas las cajas son iguales: usted mete lo que sea y cuando saca algo, debe adivinar qué es (y a veces se equivoca y el programa colapsa). Con genéricos (<T>), cada caja tiene una etiqueta: "esta caja SOLO acepta Cuentas". El compilador revisa las etiquetas mientras usted escribe código y le avisa al instante si intenta meter algo incorrecto. La letra T es solo un comodín: se reemplaza por el tipo real cuando usted usa la clase (ejemplo: ArrayList<Cuenta> reemplaza T por Cuenta).

El Problema Histórico (Sin Genéricos)

Antes de Java 5, las estructuras almacenaban cualquier objeto (Object). Esto exigía castings manuales propensos a fallar en producción con un ClassCastException. 

// ANTES DE JAVA 5: Cajas sin etiqueta
ArrayList lista = new ArrayList();
lista.add(new Cuenta("user@mail.com"));
lista.add("texto accidental"); // El compilador no advierte

// En tiempo de ejecución ocurre el colapso:
Cuenta c = (Cuenta) lista.get(1); // ClassCastException!

La Solución: Seguridad de Tipos

Los parámetros de tipo <T> actúan como etiquetas estrictas. El compilador inspecciona y rechaza datos incompatibles mientras usted programa. 

// JAVA MODERNO: Cajas tipadas y seguras
ArrayList<Cuenta> cuentas = new ArrayList<>();
cuentas.add(new Cuenta("user@mail.com"));

// cuentas.add("texto"); // IntelliJ lo subraya en rojo al instante
Cuenta c = cuentas.get(0); // Sin casting, 100% seguro

Aplicación en Streaming: Contenedor Genérico de Servidor 

// Una sola clase que transporta con seguridad cualquier tipo de respuesta (<T>)
public class RespuestaServidor<T> {
    private boolean exito;
    private String mensaje;
    private T datos; // T puede ser una Cuenta, un LogSesion o una Lista
    
    public RespuestaServidor(boolean exito, String mensaje, T datos) {
        this.exito = exito; this.mensaje = mensaje; this.datos = datos;
    }
    public T getDatos() { return datos; }
}
// Uso seguro: RespuestaServidor<Cuenta> r1 = new RespuestaServidor<>(true, "OK", miCuenta);

Records Inmutables y Herencia (Java 17/21)

Auditoría infalible para conexiones de streaming y especialización de cuentas VIP

Desde cero: Un record (Java 14+) es la versión "exprés" de una clase: en una sola línea define datos inmutables y Java genera automáticamente constructor, getters, equals(), hashCode() y toString(). Una clase tradicional de ~40 líneas se reduce a 1 línea. Es ideal para datos que no deben cambiar después de crearse, como un registro de auditoría. La herencia (extends) es otra herramienta: cuando una clase "es" otra (CuentaVIP ES una Cuenta), hereda automáticamente todos sus métodos y atributos, y usted solo agrega lo nuevo (como el PIN parental).

1 Línea: Record de Auditoría

Un record es inmutable tras crearse, garantizando el no repudio (nadie puede alterar un evento de login). 

// Define un registro de sesión inmutable en 1 línea
public record LogSesion(String usuario, String dispositivo, long timestamp) {
    public LogSesion {
        if (usuario == null || usuario.isBlank()) {
            throw new IllegalArgumentException("Usuario requerido");
        }
    }
}

Especialización: CuentaVIP extends Cuenta

Con extends, la cuenta VIP hereda el login estándar y suma beneficios de plataforma. 

public class CuentaVIP extends Cuenta {
    private int pantallasSimultaneas = 4;
    
    public CuentaVIP(String usuario, String pass) {
        super(usuario, pass);
    }
    
    public void reiniciarIntentosSoporte() {
        this.intentosFallidos = 0; // Herencia controlada
    }
}

Regla de Oro (Composición sobre Herencia): Use extends únicamente cuando exista una relación clara "es-un" (una CuentaVIP ES una Cuenta). Si necesita compartir capacidades sin heredar estado, diseñe contratos con interface.

Parte B · Pasos 2-3 de 3

Constructor y iniciarSesion()

La lógica de bloqueo tras 3 intentos fallidos

¿Por qué este paso? El constructor garantiza que toda cuenta nueva nazca en un estado válido y predecible (intentosFallidos=0, bloqueada=false). El método iniciarSesion() implementa la misma lógica de bloqueo que usan plataformas reales como Netflix o Spotify: 3 intentos fallidos = cuenta bloqueada. Así entiende cómo se construye una regla de negocio real con condicionales (if/else).

Paso 2 — Constructor

Cree un constructor público que reciba usuario y password, e inicialice intentosFallidos en 0 y bloqueada en false.

El constructor se llama siempre igual que la clase y no lleva tipo de retorno (ni siquiera void). Se ejecuta automáticamente al usar new Cuenta(...).

Paso 3 — Método iniciarSesion

Si la cuenta está bloqueada, rechace de inmediato. Si la clave coincide, reinicie intentos y sume la sesión global. Si no coincide, sume un intento fallido y bloquee al llegar a MAX_INTENTOS.

Note que totalSesionesActivas++ no lleva this. porque es static. Los atributos estáticos pertenecen a la clase, no a la instancia.

public Cuenta(String usuario, String password) {
    this.usuario = usuario;
    this.password = password;
    this.intentosFallidos = 0;
    this.bloqueada = false;
}

public boolean iniciarSesion(String intentoPass) {
    if (this.bloqueada) {
        System.out.println("ALERTA: Cuenta [" + this.usuario + "] bloqueada.");
        return false;
    }
    if (this.password.equals(intentoPass)) {
        this.intentosFallidos = 0;
        totalSesionesActivas++;
        return true;
    } else {
        this.intentosFallidos++;
        if (this.intentosFallidos >= MAX_INTENTOS) {
            this.bloqueada = true;
        }
        return false;
    }
}

public static int getTotalSesionesActivas() {
    return totalSesionesActivas;
}

Punto de control: en Main.java, cree dos objetos Cuenta y falle la clave de uno 3 veces. Verifique que el segundo objeto sigue sin bloquearse (independencia de instancia).

Parte C · Paso 1 de 2

Crear el Record LogSesion

Auditoría inmutable en un paquete nuevo

¿Por qué este paso? Un record es la herramienta ideal para datos que no deben cambiar después de crearse. En un sistema real, los registros de auditoría (quién inició sesión, desde qué dispositivo, a qué hora) son evidencia legal: nadie debe poder alterarlos. Al crear el paquete audit separado de model, aplicamos el principio de separación de responsabilidades: cada capa tiene un propósito claro.

  1. Clic derecho sobre src → New → Package → escriba "seguridad.streaming.audit". Separar la auditoría en su propio paquete mantiene el código organizado cuando el proyecto crezca.
  2. Clic derecho sobre audit → New → Java Class.
  3. Escriba "LogSesion" y, en la lista de tipos, seleccione Record (no Class). Si selecciona Class por error, el compilador no generará equals(), hashCode() ni toString() automáticamente.
  4. Agregue los componentes entre paréntesis: (String usuario, String dispositivo, long timestamp). Estos se llaman "componentes" del record. Java genera automáticamente un getter para cada uno (ej: .usuario()).
package seguridad.streaming.audit;

public record LogSesion(String usuario, String dispositivo, long timestamp) {
    public LogSesion {
        if (usuario == null || usuario.isBlank()) {
            throw new IllegalArgumentException("Usuario requerido");
        }
    }
}

Punto de control: intente crear un LogSesion con usuario vacío desde Main.java. Debe lanzarse IllegalArgumentException.

Parte C · Paso 2 de 2

Crear CuentaVIP extends Cuenta

Herencia y un PIN opcional con Wrapper

¿Por qué este paso? La herencia (extends) permite reutilizar todo el código de Cuenta sin copiarlo. CuentaVIP automáticamente tiene usuario, password, intentosFallidos, bloqueada y el método iniciarSesion(). Solo agregamos lo nuevo: el PIN parental. Usamos Integer (no int) porque el PIN es opcional: null = "no configurado". Si usáramos int, valdría 0 por defecto y el sistema creería que el PIN es "0000".

  1. Clic derecho sobre el paquete model → New → Java Class → escriba "CuentaVIP".
  2. Escriba extends Cuenta junto al nombre de la clase. Esto establece la relación "CuentaVIP ES una Cuenta" y hereda todos sus atributos y métodos.
  3. Agregue el atributo Integer pinControlParental (Wrapper, no int). Integer puede ser null = "sin PIN". int siempre vale 0 y falsearía el control parental.
  4. Cree un constructor que llame a super(usuario, password). super() invoca el constructor de Cuenta. Debe ser la PRIMERA línea del constructor de la subclase.
  5. Implemente verificarPin(int intento) validando primero si el PIN es null. Si pinControlParental == null, no hay restricción: retorna true directamente.
package seguridad.streaming.model;

public class CuentaVIP extends Cuenta {
    private Integer pinControlParental; // null = no configurado

    public CuentaVIP(String usuario, String password) {
        super(usuario, password);
        this.pinControlParental = null;
    }

    public boolean verificarPin(int intento) {
        if (this.pinControlParental == null) return true;
        return this.pinControlParental == intento;
    }
}

Punto de control: cree una CuentaVIP sin fijar PIN y llame verificarPin(). No debe lanzarse NullPointerException.

Verificación Conceptual (Haga Clic)

¿Por qué crear carpetas dentro de 'src' y no en la raíz?

Porque la carpeta src es el Source Root. La JVM solo compila archivos ubicados en esta estructura. Un archivo fuera no es reconocido como clase del paquete Java.

¿Qué ventaja ofrece Integer pin sobre int pin?

El primitivo int no admite nulos y asigna 0 por defecto. Integer (Wrapper) puede valer null, reflejando fielmente que el usuario no configuró PIN parental sin falsos ceros.

¿Por qué los registros de auditoría usan record?

Para garantizar inmutabilidad y no repudio. Una vez instanciado, nadie puede alterar los campos de un record, asegurando el historial original.
