Duración estimada: 1 hora 30 minutos  ·  Trabajo Individual

Introducción al Reto Individual

En la sesión de hoy construimos en conjunto un sistema robusto aplicando Herencia Polimórfica, Clases e Interfaces Genéricas, Switch Expressions, Optional, una arquitectura por capas (servicio + repositorio) y Control de Eventos con GUI Form de Swing.

Ahora deberás demostrar tu autonomía aplicando exactamente los mismos principios arquitectónicos en un nuevo dominio: AeroUNA (Sistema de Control de Vuelos y Reservas de Pasajes). Construirás una solución por capas que gestione vuelos comerciales regulares y vuelos chárter privados, permitiendo la reserva de asientos con control de aforo, búsqueda segura por código y promociones aplicadas desde la capa de servicio.

No partas de cero: este laboratorio replica exactamente la misma estructura que construiste en el NovaCinema. Tus paquetes y la mayor parte del código son idénticos: solo cambia el dominio y los datos de los métodos. Usa la tabla de equivalencias del siguiente panel.

Objetivos Técnicos Obligatorios:
  • Diseñar una jerarquía de modelo desacoplada utilizando una interfaz genérica (Identificable<K>) y una clase abstracta genérica (ServicioVuelo<K>).
  • Implementar el cálculo polimórfico de tarifas de pasajes mediante Switch Expressions según el tipo de clase (TipoClase) o el tipo de chárter (TipoCharter).
  • Reutilizar la capa de lógica mediante un repositorio genérico acotado (Repositorio<T extends Identificable<?>>) con búsqueda segura mediante Optional<T>.
  • Encapsular las operaciones de negocio (registro, reserva, promociones) en una capa de servicio (AeroServicio), igual que CineServicio en el livecoding.
  • Construir la vista con GUI Form de IntelliJ usando JTabbedPane (una pestaña por tipo de vuelo), ActionListener con lambdas y despacho seguro en el EDT.

Paso 1: Configurar el Repositorio y Paquetes

1.1 Crear el repositorio en GitHub y clonarlo

Crea en GitHub un repositorio público llamado Laboratorio4-AeroUNA, clónalo en tu computadora con GitHub Desktop y ábrelo en IntelliJ IDEA asegurando la carpeta src como Sources Root.

1.2 Estructura modular de paquetes requerida

Igual que en el livecoding, crea los paquetes directamente dentro de src:

src/ ├── modelo/ // Identificable<K>, ServicioVuelo<K>, VueloComercial, VueloCharter, Enums ├── servicio/ // Repositorio<T extends Identificable<?>>, AeroServicio ├── vista/ // VentanaVuelos.form, VentanaVuelos.java └── Main.java // Lanzador seguro en Event Dispatch Thread (EDT)

Paso 2: Construir el Modelo Polimórfico y Genérico

2.1 Enums de Categoría y Contrato Genérico

En el paquete modelo, crea:

  • TipoClase.java: Enum con valores ECONOMICA, EJECUTIVA, PRIMERA_CLASE (equivale a TipoFormato).
  • TipoCharter.java: Enum con valores TURISMO, EMPRESARIAL, MEDICO (equivale a TipoProducto).
  • Identificable<K>.java: Interfaz genérica con los métodos String getCodigo(), String getDestino(), K getCategoria(), double calcularPrecio() y String getDetalle().
2.2 Superclase Abstracta Genérica: ServicioVuelo<K>.java
  • Declara public abstract class ServicioVuelo<K> implements Identificable<K>.
  • Atributos protegidos: protected String codigo, protected String destino, protected K categoria, protected double tarifaBase.
  • Constructor completo para inicializar los atributos y sus respectivos Getters.
2.3 Subclases Concretas: VueloComercial y VueloCharter
  • VueloComercial.java: Hereda de ServicioVuelo<TipoClase>. Contiene int capacidadAsientos, int asientosOcupados y el getter getAsientosDisponibles() (capacidad − ocupados), igual que FuncionPelicula.
    Implementa public boolean reservarAsientos(int cantidad) que verifique disponibilidad antes de sumar a los ocupados (espejo de venderBoletos).
    Sobrescribe calcularPrecio() utilizando un Switch Expression:
    @Override public double calcularPrecio() { return switch (categoria) { case ECONOMICA -> tarifaBase; case EJECUTIVA -> tarifaBase + 25000; case PRIMERA_CLASE -> tarifaBase + 60000; }; }

    Sobrescribe también getDetalle() para mostrar el vuelo en la consola:
    @Override public String getDetalle() { return String.format("Código: %s\n Vuelo: %s\n Clase: %s\n Asientos: %d / %d\n Precio: ₡%.2f", codigo, destino, categoria, getAsientosDisponibles(), capacidadAsientos, calcularPrecio()); }

    Ejemplo de salida esperada:

    Código: AV-101 Vuelo: Madrid Clase: EJECUTIVA Asientos: 180 / 200 Precio: ₡95000.00
  • VueloCharter.java: Hereda de ServicioVuelo<TipoCharter>. Contiene int duracionHoras y boolean incluyeTripulacionVIP.
    Sobrescribe calcularPrecio() sumando un costo fijo de ₡80,000 si incluye tripulación VIP (espejo de ProductoDulceria):
    @Override public double calcularPrecio() { if (incluyeTripulacionVIP) { return tarifaBase + 80000; } return tarifaBase; }

    Sobrescribe también getDetalle():
    @Override public String getDetalle() { return String.format("Código: %s\n Chárter: %s\n Tipo: %s\n Duración: %d horas\n Tripulación VIP: %s\n Precio: ₡%.2f", codigo, destino, categoria, duracionHoras, (incluyeTripulacionVIP ? "Sí" : "No"), calcularPrecio()); }

    Ejemplo de salida esperada:

    Código: CH-202 Chárter: Isla del Coco Tipo: MEDICO Duración: 5 horas Tripulación VIP: Sí Precio: ₡380000.00

Paso 3: Capa de Servicio Genérico con Optional

3.1 Repositorio Genérico Acotado: Repositorio<T extends Identificable<?>>.java

En el paquete servicio, copia tal cual tu Repositorio del livecoding (no cambia nada):

  • Declara public class Repositorio<T extends Identificable<?>> (el genérico acotado exige que todo elemento sea identificable por código).
  • private List<T> items = new ArrayList<>();
  • public void agregar(T item)
  • public List<T> obtenerTodos()
  • public Optional<T> buscarPorCodigo(String codigo): recorre la lista comparando con item.getCodigo().equalsIgnoreCase(codigo) y devuelve Optional.of(item) o Optional.empty() (búsqueda segura).
3.2 Capa de Servicio de Negocio: AeroServicio.java

Igual que CineServicio en el livecoding, crea AeroServicio para encapsular la lógica y desacoplar la vista del repositorio:

  • Dos repositorios privados: Repositorio<VueloComercial> repoVuelos y Repositorio<VueloCharter> repoCharters.
  • Para vuelos: registrarVuelo(VueloComercial), obtenerVuelos(), buscarVuelo(String codigo) (devuelve Optional<VueloComercial>).
  • venderBoletos(String codigo, int cantidad): busca el vuelo; si no existe devuelve null; si no hay aforo devuelve null; si la reserva es exitosa devuelve vuelo.calcularPrecio() * cantidad.
  • aplicarDescuentoVuelo(VueloComercial vuelo): devuelve vuelo.calcularPrecio() * 0.85 (promoción del 15%).
  • Equivalentes para chárter: registrarCharter(...), obtenerCharters(), buscarCharter(...) y aplicarDescuentoCharter(...).

Paso 4: GUI Form con JTabbedPane y Control de Eventos

4.1 Formulario con IntelliJ GUI Designer (VentanaVuelos.form)

Diseña un formulario visual en vista.VentanaVuelos (el equivalente a tu VentanaCine) con un JTabbedPane y dos pestañas, igual que en el livecoding:

  • Pestaña 1 — "Vuelos Comerciales":
    • Campos de texto: txtCodigo, txtDestino, txtCapacidad, txtTarifa.
    • ComboBox tipado: cbxTipoClase (cargado con new DefaultComboBoxModel<>(TipoClase.values()), igual que cbxFormato).
    • Botones: btnRegistrarVuelo, btnVenderBoleto, btnMostrarVuelos, btnPromoMillon.
    • Área de salida: txaVuelos (dentro de un JScrollPane).
  • Pestaña 2 — "Vuelos Chárter":
    • Campos de texto: txtCodCharter, txtDestCharter, txtDuracionCharter, txtTarifaCharter.
    • ComboBox tipado: cbxTipoCharter (cargado con TipoCharter.values()).
    • Botones: btnRegistrarCharter, btnMostrarCharters, btnPromoCharter.
    • Área de salida: txaCharters (dentro de un JScrollPane).
4.2 Requisitos Obligatorios de Eventos a Programar (ActionListener con Lambdas):
  1. Registro de Vuelo (btnRegistrarVuelo):
    Dentro de un try/catch por NumberFormatException, parsear los campos (Integer.parseInt, Double.parseDouble), crear el VueloComercial, llamar a aeroServicio.registrarVuelo(...), actualizar la consola y limpiar los campos.
  2. Venta de Boletos y Control de Aforo (btnVenderBoleto):
    Pedir el código con JOptionPane.showInputDialog y buscar con aeroServicio.buscarVuelo(...). Si Optional.isEmpty(), mostrar advertencia. Si existe, pedir la cantidad y usar aeroServicio.venderBoletos(...): si devuelve null avisar que no se pudo realizar; si no, mostrar el total con String.format y actualizar la consola.
  3. Mostrar Vuelos (btnMostrarVuelos):
    Refrescar txaVuelos con el encabezado "════════════ VUELOS AEROUNA ════════════" y el getDetalle() de cada vuelo (igual que tu método actualizarCartelera).
  4. Promoción Millón (btnPromoMillon):
    Recorrer aeroServicio.obtenerVuelos() mostrando precio normal, aeroServicio.aplicarDescuentoVuelo(...) y el ahorro (igual que btnPromoEstudiante).
  5. Registro de Chárter (btnRegistrarCharter):
    Mismo patrón del punto 1 con VueloCharter y aeroServicio.registrarCharter(...).
  6. Mostrar Chárter (btnMostrarCharters):
    Refrescar txaCharters con el getDetalle() de cada chárter.
  7. Promoción Chárter (btnPromoCharter):
    Listar precios con aeroServicio.aplicarDescuentoCharter(...) (igual que btnPromoDulceria).

En el constructor carga los ComboBox con setModel(new DefaultComboBoxModel<>(TipoClase.values())) y usa (TipoClase) cbxTipoClase.getSelectedItem() al registrar, tal como hiciste con cbxFormato.

Paso 5: Punto de Entrada Main.java

5.1 Despacho en el Event Dispatch Thread (EDT)

En Main.java (en la raíz de src, sin paquete, igual que el livecoding), configura el Look and Feel del sistema operativo y lanza la ventana dentro de SwingUtilities.invokeLater(() -> { ... }) para garantizar seguridad concurrente en los componentes de Swing. En VentanaVuelos usa setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE), como en el livecoding.
