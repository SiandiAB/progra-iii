El paradigma secuencial

La Interfaz de Línea de Comandos (CLI).

El control absoluto del código

Hasta el momento, hemos desarrollado aplicaciones basadas en texto mediante una Interfaz de Línea de Comandos (CLI). En este paradigma, el código fuente posee el control absoluto y unidireccional sobre el flujo de ejecución del programa.

  • Ejecución Sincrónica: El programa ejecuta las instrucciones línea por línea de manera predecible.
  • Bloqueo del Hilo: Cuando se solicita información mediante la clase Scanner, el hilo de ejecución principal se suspende indefinidamente hasta que el usuario ingresa un valor y presiona la tecla Enter.
  • Rigidez: El usuario no puede alterar el orden de los pasos establecidos por el programador. Debe proporcionar los datos requeridos exactamente en la secuencia solicitada.

Así se ve al ejecutarse:

Bienvenido al sistema de registro.
> Ingrese su nombre: Kristel Duarte
> Ingrese su edad: _ (El programa se detiene y espera aquí obligatoriamente)

¿Qué es la clase Scanner?

Scanner pertenece a la biblioteca java.util y permite leer los datos que el usuario escribe en el teclado. Al instanciarla con System.in, el programa puede capturar texto o números. Su método nextLine() suspende la ejecución hasta recibir la tecla Enter.

El código que lo enseña:

import java.util.Scanner;

public class Registro {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);

        System.out.print("Ingrese su nombre: ");
        String nombre = teclado.nextLine(); // BLOQUEA aquí

        System.out.print("Ingrese su edad: ");
        int edad = teclado.nextInt();

        System.out.println("Hola " + nombre);
    }
}

Cada llamada a nextLine() o nextInt() mantiene el control en el código: el usuario solo puede responder en el orden exacto que el programador definió.

El paradigma visual

La Interfaz Gráfica de Usuario (GUI).

El usuario toma el control

La Interfaz Gráfica de Usuario (GUI) transforma la manera en que el software se diseña y se utiliza. Se fundamenta en el estándar de diseño de interacción conocido como WIMP. En este entorno, el control del flujo de ejecución se transfiere del código fuente hacia el usuario final.

  • Representación Visual: Los datos y las acciones disponibles se representan mediante componentes gráficos interactivos en lugar de simples cadenas de texto.
  • No Linealidad: El usuario posee la libertad de navegar por la interfaz, interactuar con múltiples campos, abrir menús o cerrar la ventana en el orden que considere oportuno, sin restricciones secuenciales.

Comprendiendo el Flujo por Eventos

Asincronía y el patrón de delegación.

Programación Orientada a Eventos

Al perder el control lineal del código, la aplicación requiere una arquitectura basada en eventos. Un evento representa una transición de estado originada por una acción externa, tal como presionar una tecla, mover el puntero o efectuar un clic izquierdo.

El programa principal inicializa la interfaz y entra en un ciclo infinito de inactividad controlado por el Sistema Operativo, denominado Event Dispatch Thread (Hilo Despachador de Eventos).

El Mecanismo de Listeners

  • 1
    Suscripción: El desarrollador instancia objetos especializados llamados Listeners (Escuchadores) y los asocia a componentes específicos (como un botón).
  • 2
    Espera pasiva: El sistema permanece en estado de reposo, sin consumir ciclos de CPU procesando lógica, hasta que ocurre una interacción.
  • 3
    Interrupción: Al detectarse una acción del usuario, el sistema notifica inmediatamente al Listener suscrito, ejecutando el bloque de código asociado a dicho evento.

Bibliotecas GUI: Historia e Implementación (AWT)

Los cimientos gráficos del lenguaje Java.

AWT (Abstract Window Toolkit)

AWT fue la primera biblioteca gráfica nativa proporcionada en la versión 1.0 de Java (ubicada en el paquete java.awt). Su arquitectura se fundamentaba en una delegación directa al sistema operativo anfitrión.

Arquitectura Heavyweight

AWT utiliza componentes catalogados como Heavyweight. Cuando el desarrollador instancia un botón en Java, la Máquina Virtual realiza una llamada al sistema operativo subyacente (Windows, Linux o macOS) solicitando la creación de un control visual nativo equivalente.

Limitaciones Estructurales

Dado que la renderización dependía del sistema operativo, el diseño y las dimensiones de la interfaz variaban drásticamente entre plataformas. Un botón diseñado en Windows podía superponerse o recortarse al ejecutarse en macOS, comprometiendo gravemente el principio fundamental de portabilidad de Java.

VentanaAWT.java 
import java.awt.*; // componentes nativos

public class VentanaAWT {
    public static void main(String[] args) {
        // Cada clase delega en el S.O.: "heavyweight"
        Frame ventana = new Frame("AWT");
        Button boton = new Button("OK");

        ventana.add(boton);
        ventana.setSize(400, 300);
        ventana.setVisible(true);
        // Sin setDefaultCloseOperation: el cierre
        // depende del WindowListener nativo
    }
}

Las clases Frame y Button no llevan prefijo: son controles del sistema operativo.

Bibliotecas GUI: La evolución a Java Swing

El estándar maduro que otorga portabilidad real.

Java Swing

Introducida en Java 1.2, Swing (javax.swing) se diseñó como una solución directa a las inconsistencias de AWT. Emplea la API Java 2D para renderizar gráficamente sus elementos sin solicitar controles nativos al sistema operativo.

Arquitectura Lightweight

Utiliza componentes Lightweight. Los elementos se escriben completamente en Java. Por convención, todas las clases de esta biblioteca se identifican con el prefijo J (JButton, JLabel, JTextField).

Portabilidad y Consistencia

Swing garantiza la consistencia visual y dimensional en cualquier entorno (Pluggable Look and Feel). Una interfaz gráfica de usuario construida con Swing se mostrará con idéntica precisión geométrica en diversas arquitecturas, preservando la integridad del diseño original.

VentanaSwing.java 
import javax.swing.*; // 100% Java

public class VentanaSwing {
    public static void main(String[] args) {
        // Java dibuja los píxeles: "lightweight"
        JFrame ventana = new JFrame("Swing");
        JButton boton = new JButton("OK");

        ventana.add(boton);
        ventana.setSize(400, 300);
        ventana.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        ventana.setVisible(true);
    }
}

El prefijo J identifica cada componente dibujado por Java, sin depender del sistema operativo.

Estructura de la Interfaz: Contenedor Principal

La jerarquía obligatoria de los elementos visuales.

Contenedor de Alto Nivel

JFrame

La ventana física de la aplicación. Su decoración y tamaño dependen del gestor de ventanas del S.O.

La clase JFrame es la unidad raíz de cualquier aplicación de escritorio en Java Swing. Encapsula las funcionalidades necesarias para establecer una ventana física interactuando con el gestor de ventanas del sistema operativo.

Decoración completa: Proporciona la barra de título y los controles de estado (minimizar, maximizar, cerrar).

Dimensiones globales: Gestiona el ancho y alto de toda la ventana en píxeles.

Nodo superior: Un JFrame no puede ser encapsulado dentro de otros contenedores Swing; siempre es la raíz de la jerarquía.

Main.java 
import javax.swing.JFrame;

public class Main {
    public static void main(String[] args) {
        // 1. Instanciación del contenedor principal
        JFrame ventana = new JFrame("Sistema Administrativo");
        
        // 2. Configuración de dimensiones (Ancho x Alto)
        ventana.setSize(800, 600);
        
        // 3. Definición del comportamiento de finalización
        // Asegura que el hilo principal se destruya al cerrar
        ventana.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        
        // 4. Renderización del componente en pantalla
        ventana.setVisible(true);
    }
}

Estructura de la Interfaz: Contenedores Intermedios

Organización espacial y modularidad de componentes.

Agrupación Lógica

JPanel

El bloque constructivo para organizar el contenido de la ventana.

La inserción directa de componentes en un JFrame carece de estructura. Para implementar diseños complejos, se requiere la instanciación de Contenedores Intermedios.

Agrupación visual: Áreas rectangulares transparentes diseñadas para agrupar lógicamente otros componentes.

Anidamiento: Un JPanel puede contener otros JPanel, estructurando regiones como barras de navegación y áreas de contenido.

Layout Managers: Algoritmos de distribución geométrica que administran automáticamente el posicionamiento de los componentes hijos.

Main.java (continuación) 
// 5. Instanciación del contenedor intermedio
JPanel panelPrincipal = new JPanel();

// 6. Asignación del panel como contenido maestro de la ventana
// Este método establece que el panel cubrirá toda el área visible
ventana.setContentPane(panelPrincipal);

Implementación en Código: Contenedores y Componentes

La síntesis de la estructura jerárquica en código puro de Java.

Main.java 
import javax.swing.*;

public class Main {
    public static void main(String[] args) {
        // 1. Nivel Superior (Contenedor de Alto Nivel)
        JFrame ventana = new JFrame("Estructura Swing Pura");
        ventana.setSize(400, 300);
        ventana.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);

        // 2. Nivel Intermedio (Contenedor de Agrupación)
        JPanel panel = new JPanel();

        // 3. Nivel Inferior (Componentes Atómicos)
        JLabel etiqueta = new JLabel("Ejecución Exitosa.");
        JButton boton = new JButton("Procesar");

        // 4. Consolidación de la Jerarquía (Niveles inferiores hacia arriba)
        panel.add(etiqueta);        
        panel.add(boton);           
        ventana.setContentPane(panel); 

        // 5. Transición al estado visible
        ventana.setVisible(true);
    }
}

Estructuras y Patrones: El Peligro

El antipatrón del Código Espagueti y las Clases Monolíticas.

Riesgos Arquitectónicos

La simplicidad de los entornos de diseño visual frecuentemente conduce a deficiencias arquitectónicas. Resulta común integrar la totalidad de la lógica de negocio dentro de los métodos de gestión de eventos proporcionados por la interfaz gráfica.

  • El Antipatrón "Smart UI": Ocurre cuando un bloque de interfaz gráfica asume responsabilidades de cálculo financiero, procesamiento de cadenas de texto y manipulación directa de estructuras de datos (ej. ArrayList).
  • Consecuencia Técnica: La generación de clases monolíticas que imposibilitan el mantenimiento del software y violan los principios de diseño modular solicitados para los entregables de su proyecto.
Ejemplo de Práctica Deficiente (Monolítica) 
// Listener anidado en la clase visual
btnFacturar.addActionListener(e -> {

Separación Estricta de Responsabilidades

Los cimientos metodológicos para el patrón arquitectónico.

Aislamiento de la Interfaz Visual

Para asegurar la escabilidad del software, se debe imponer una restricción conceptual sobre la Interfaz Gráfica de Usuario (GUI): esta capa estructural debe limitarse estrictamente a renderizar el estado del sistema en la pantalla y capturar las señales emitidas por el hardware de entrada.

Capa de Presentación

Compuesta por las clases de Swing. Gestiona la geometría, el formato visual de los componentes, lee las cadenas de texto ingresadas y expone notificaciones visuales ante excepciones.

Capa de Lógica

Clases que actúan como intermediarias. Reciben los datos extraídos por la GUI, ejecutan los algoritmos matemáticos y formulan las conversiones de tipo requeridas.

Capa de Datos

Define la persistencia y estructura (ArrayList, HashMap, Entidades). Almacena el estado final de las transacciones verificadas.

El GUI Designer de IntelliJ

Automatizando el diseño de posicionamiento absoluto.

Diseño Visual Asistido

Programar explícitamente mediante coordenadas Cartesianas (X, Y) y longitudes en píxeles demanda un esfuerzo considerable y resulta ineficiente. El entorno IntelliJ proporciona un generador visual de interfaces capaz de estructurar el código subyacente automáticamente.

La Estructura de Archivos Vinculados

La creación de un GUI Form desencadena la instanciación simultánea de dos archivos estructuralmente acoplados:

Archivo .form

Un documento configurado bajo notación XML reservado para el IDE. En este repositorio de metadata se registran las matrices posicionales, las jerarquías de los paneles y las asignaciones de color.

Archivo .java

La declaración formal de la clase en Java. Es responsable de exponer los identificadores y proveer un entorno seguro para vincular los Listeners sin alterar el diseño visual.

Layout Managers: Distribución de Precisión

Los algoritmos que colocan cada componente con control total.

GridLayoutManager

¿Qué es? El layout por defecto del GUI Designer de IntelliJ. Divide el panel en una cuadrícula de filas y columnas que crece dinámicamente al arrastrar componentes.

¿Qué hace? Coloca cada componente en una celda y ajusta filas/columnas al tamaño del contenido.

Cuándo usarlo: siempre que diseñes formularios con el GUI Designer; es la opción predeterminada para arrastrar y soltar.

GridBagLayout

¿Qué es? El layout más flexible y potente de AWT/Swing. Organiza en una cuadrícula donde cada celda puede abarcar varias filas/columnas y definir pesos de crecimiento.

¿Qué hace? Calcula la posición exacta de cada componente mediante restricciones GridBagConstraints.

FlowLayout

¿Qué es? El más simple. Coloca los componentes uno tras otro en una línea horizontal y "fluye" a la siguiente cuando no caben.

Listeners Asistidos

Para que un botón reaccione al clic, requiere un ActionListener. IntelliJ puede generar la estructura del código base de manera inmediata:

  1. Haz Clic Derecho sobre el botón en el diseñador visual.
  2. Selecciona Create Listener → ActionListener.
  3. El IDE abrirá el archivo .java asociado.
  4. El bloque de código asíncrono será escrito automáticamente dentro del constructor, listo para recibir tus instrucciones lógicas.

Conectando el Puente Visual

La estructura fundamental para inicializar el contenedor gráfico de IntelliJ.

Encendiendo el Entorno

Un archivo .form parametrizado visualmente es inherentemente inactivo. La Máquina Virtual de Java precisa un punto de entrada ejecutable.

La integración se logra instanciando el marco base de nivel superior (JFrame) y suministrando al mismo el contenedor intermedio central (JPanel) generado en el paso anterior.

PantallaLogin.java 
public class PantallaLogin {
    // Referencias mapeadas automáticamente desde el .form
    private JPanel mainPanel;
    private JTextField txtUsuario;
    private JButton btnEntrar;

    public static void main(String[] args) {
        // 1. Construcción del Marco Estructural vacío
        JFrame frame = new JFrame("Acceso Institucional");
        
        // 2. Instanciación de la clase actual
        PantallaLogin pantalla = new PantallaLogin();
        
        // 3. Vinculación: Se inyecta el panel parametrizado
        frame.setContentPane(pantalla.mainPanel);
        
        // 4. Parámetros de ciclo de vida y renderización
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        frame.pack(); // Algoritmo de adaptación geométrica
        frame.setVisible(true);
    }
}
