Introducción

En este laboratorio vamos a construir un sistema de gestión universitaria que pondrá en práctica todos los conceptos vistos en la semana 3: herencia, interfaces, paquetes, genéricos y características modernas de Java como lambdas, streams, Optional y records.

El sistema permitirá gestionar personas (estudiantes y profesores), calcular promedios, filtrar listas, ordenar y realizar consultas avanzadas usando programación funcional.

Objetivo: Al finalizar este laboratorio, serás capaz de:
  • Diseñar una jerarquía de herencia con extends y super.
  • Implementar interfaces (implements) y usar polimorfismo.
  • Organizar el código en paquetes (package e import).
  • Crear clases y métodos genéricos con <T>.
  • Aplicar lambdas y streams para procesar colecciones de forma declarativa.
  • Usar Optional para manejar valores ausentes de forma segura.

Paso 2: Clase abstracta Persona

Vamos a crear una clase base abstracta que servirá como superclase para Estudiante y Profesor. Una clase abstracta no puede instanciarse directamente; solo sirve como plantilla.

2.1 Crear el archivo Persona.java

Dentro del paquete Lab02.modelo, crea una nueva clase llamada Persona.

Clic derecho en modelo → New → Java Class.

2.2 Agregar la declaración del paquete

Al inicio del archivo, asegúrese que se encuentre la línea que indica a qué paquete pertenece la clase:

package modelo;

Esto organiza la clase dentro del espacio de nombres (namespace) del paquete.

2.3 Importar Objects

Necesitamos la clase Objects para implementar equals() y hashCode() de forma segura. Agrega la importación:

import java.util.Objects;
¿Por qué Objects.equals()?

A diferencia de nombre.equals(otro.nombre), el método Objects.equals(a, b) maneja correctamente los valores null: si ambos son null retorna true, si solo uno es null retorna false. Esto evita el temido NullPointerException.

¿Por qué Objects.hash()?

Genera un código hash combinando varios atributos de forma segura (también tolera null). Es más legible y menos propenso a errores que calcular el hash manualmente.

¿Por qué necesitamos hashCode()?

Cuando sobrescribes equals(), siempre debes sobrescribir hashCode(). El contrato de Java exige que: si a.equals(b) es true, entonces a.hashCode() == b.hashCode(). Si no lo cumples, las colecciones basadas en hash (como HashSet o HashMap) tendrán comportamientos impredecibles: podrías agregar dos objetos "iguales" sin que se detecte la duplicidad.

2.4 Declarar la clase como abstract

Escribe la declaración de la clase. Recuerda que debe ser abstracta porque no tendrá sentido instanciar una "persona genérica".

public abstract class Persona {

El modificador abstract impide crear objetos de esta clase con new Persona(...).

2.5 Declarar los atributos (privados)

Dentro de la clase, declara los atributos comunes a todas las personas. Deben ser private para garantizar el encapsulamiento:

private String nombre; private int edad;

Recuerda: String con mayúscula, y usa private para que solo la clase pueda acceder directamente.

2.6 Escribir el constructor

El constructor recibe nombre y edad, y los asigna a los atributos:

public Persona(String nombre, int edad) { this.nombre = nombre; this.edad = edad; }

Nota: this.nombre = nombre; significa: "al atributo de la clase (this.nombre, declarado como private String nombre) asígnale el valor del parámetro del constructor (nombre, recibido en Persona(String nombre, int edad))". Sin this, Java no sabría a cuál de los dos te refieres, porque tienen el mismo nombre.

2.7 Agregar getters y setters

Para acceder a los atributos desde otras clases, debemos proporcionar getters (y setters si se necesita modificar). Escribe los métodos:

public String getNombre() { return nombre; } public void setNombre(String nombre) { this.nombre = nombre; } public int getEdad() { return edad; } public void setEdad(int edad) { this.edad = edad; }

Estos métodos permiten leer y modificar los atributos de forma controlada.

2.8 Declarar el método abstracto getDescripcion()

Este método será implementado por cada subclase para devolver una descripción específica. No tiene cuerpo (solo firma):

public abstract String getDescripcion();

¿Por qué abstracto? Porque cada tipo de persona (estudiante, profesor) tiene una forma distinta de presentarse. Al ser abstracto, obligamos a las subclases a implementarlo.

2.9 Sobrescribir toString()

Para mostrar información básica de la persona, sobrescribimos el método toString():

@Override public String toString() { return "Persona{nombre='" + nombre + "', edad=" + edad + "}"; }

La anotación @Override es opcional pero recomendada; le dice al compilador que estamos sobrescribiendo un método de la superclase.

2.10 Sobrescribir equals() y hashCode()

Para comparar personas por su contenido (nombre y edad), necesitamos estos métodos. Usamos Objects.equals() y Objects.hash():

// Indica que estamos sobrescribiendo un método de Object @Override public boolean equals(Object obj) { // 1. ¿Es el MISMO objeto en memoria? Si es la misma referencia, son iguales if (this == obj) return true; // 2. ¿Es null o es de otra clase? Si no es Persona, no pueden ser iguales if (obj == null || getClass() != obj.getClass()) return false; // 3. Convertimos (casteamos) el Object a Persona para comparar atributos Persona persona = (Persona) obj; // 4. Comparamos atributo por atributo: // edad == persona.edad → compara el int directamente (primitivo) // Objects.equals(nombre, persona.nombre) → compara Strings de forma segura (soporta null) return edad == persona.edad && Objects.equals(nombre, persona.nombre); } // Genera un código hash basado en los mismos atributos que usa equals() // Si dos objetos son iguales (equals=true), DEBEN tener el mismo hashCode @Override public int hashCode() { return Objects.hash(nombre, edad); }

Esto permite comparar personas por su estado (nombre y edad), no por su dirección en memoria. Sin estos métodos, persona1.equals(persona2) solo retornaría true si ambas variables apuntan al mismo objeto en memoria, aunque tengan los mismos datos.

¿Por qué es abstracta? Persona es abstracta porque no tiene sentido crear una "persona genérica" sin saber si es estudiante o profesor. Las subclases concretas (Estudiante, Profesor) implementarán el método getDescripcion().

Paso 3: Clase Estudiante

Estudiante hereda de Persona usando extends. Añade atributos específicos: carnet, carrera y lista de notas. También implementa la interfaz Comparable para poder ordenar estudiantes por promedio.

3.1 Crear Estudiante.java en modelo

Crea un nuevo archivo en el paquete Lab02.modelo con el nombre Estudiante.

Clic derecho en modelo → New → Java Class.

3.2 Agregar el paquete y las importaciones

El paquete es el mismo que el de Persona. Además, necesitamos importar ArrayList, List y Objects:

package modelo; // Para crear la lista dinámica de notas (new ArrayList<>()) import java.util.ArrayList; // Para declarar el tipo de la variable (List<Double> notas) import java.util.List; // Para equals() y hashCode() seguros (soporta null) import java.util.Objects;
¿Para qué sirve ArrayList?

Es la implementación concreta de lista que usamos (new ArrayList<>()). Es como un arreglo que puede crecer dinámicamente.

¿Para qué sirve List?

Es la interfaz que define qué operaciones tiene una lista. Declaramos List<Double> notas (la interfaz) en vez de ArrayList<Double> notas (la implementación) por buena práctica: así podemos cambiar a otra implementación después sin romper el código.

¿Para qué sirve Objects?

Ya la conocemos: provee Objects.equals() y Objects.hash() para comparar objetos de forma segura ante null.

3.3 Declarar la clase y la herencia

Estudiante extiende Persona e implementa la interfaz Comparable para poder ordenar:

public class Estudiante extends Persona implements Comparable<Estudiante> {

Comparable<Estudiante> define que los estudiantes pueden compararse entre sí (para ordenar).

¿Por qué implementamos Comparable?

Porque más adelante vamos a ordenar la lista de estudiantes por promedio (de mayor a menor). Comparable es una interfaz de Java que obliga a escribir el método compareTo(), donde tú defines la regla de orden. Una vez implementado, puedes usar Collections.sort(lista) o lista.sort(Comparator.naturalOrder()) y Java sabrá automáticamente cómo ordenar.

¿Cómo funciona compareTo()?

compareTo(Estudiante otro) debe retornar:

  • Negativo → si this va antes que otro.
  • Cero → si son iguales según tu criterio.
  • Positivo → si this va después que otro.

En nuestro caso (paso 3.11), escribiremos Double.compare(otro.getPromedio(), this.getPromedio()), que invierte el orden natural para que el promedio más alto aparezca primero (orden descendente).

3.4 Declarar los atributos específicos

Un estudiante tiene carnet (identificador único), carrera y una lista de notas:

private String carnet; private String carrera; private List<Double> notas;

Nota: Usamos List<Double> en lugar de un arreglo para que la lista sea dinámica.

3.5 Escribir el constructor principal

El constructor recibe nombre, edad, carnet y carrera. Llama al constructor de Persona con super(nombre, edad) e inicializa la lista de notas vacía:

public Estudiante(String nombre, int edad, String carnet, String carrera) { super(nombre, edad); this.carnet = carnet; this.carrera = carrera; this.notas = new ArrayList<>(); }

La llamada a super() siempre debe ser la primera instrucción en el constructor.

3.6 Constructor adicional con lista de notas

Para facilitar la creación, podemos tener un constructor que también reciba una lista inicial de notas:

public Estudiante(String nombre, int edad, String carnet, String carrera, List<Double> notas) { this(nombre, edad, carnet, carrera); this.notas = new ArrayList<>(notas); }

Aquí usamos this() para llamar al otro constructor y luego inicializamos la lista con una copia de la recibida.

¿Por qué dos constructores?

Es una cuestión de flexibilidad. No siempre tendrás las notas al momento de crear un estudiante:

  • Constructor sin notas: creas al estudiante y luego le vas agregando notas una por una con agregarNota(). Es útil cuando las notas se ingresan después o de forma gradual.
  • Constructor con notas: cuando YA tienes la lista completa de notas (por ejemplo, al cargar datos desde un archivo), puedes crear al estudiante con todo de una sola vez.

Esto se llama sobrecarga de constructores y es una práctica común en Java para darle al programador distintas formas de crear objetos, según la situación.

3.7 Getters y setters

Agrega los métodos de acceso para los atributos. Recuerda que para la lista de notas, el setter debe hacer una copia para evitar modificar la lista original desde fuera:

public String getCarnet() { return carnet; } public void setCarnet(String carnet) { this.carnet = carnet; } public String getCarrera() { return carrera; } public void setCarrera(String carrera) { this.carrera = carrera; } public List<Double> getNotas() { return notas; } public void setNotas(List<Double> notas) { this.notas = new ArrayList<>(notas); }
3.8 Método agregarNota()

Este método añade una nota a la lista después de validar que esté entre 0 y 100. Si no, lanza una excepción:

public void agregarNota(double nota) { if (nota < 0 || nota > 100) { throw new IllegalArgumentException("La nota debe estar entre 0 y 100"); } this.notas.add(nota); }

¿Por qué lanzar una excepción? Para evitar que el programa continúe con datos inválidos.

3.9 Método getPromedio() con Stream API

Este método calcula el promedio de las notas usando Streams (programación funcional):

public double getPromedio() { if (notas.isEmpty()) return 0.0; return notas.stream() .mapToDouble(Double::doubleValue) .average() .orElse(0.0); }

Explicación: stream() convierte la lista en un flujo de datos; mapToDouble() transforma cada Double en double primitivo; average() calcula el promedio; orElse(0.0) devuelve 0 si no hay elementos.

3.10 Implementar getDescripcion() (abstracto de Persona)

Este método devuelve una descripción completa del estudiante:

@Override public String getDescripcion() { return "Estudiante: " + getNombre() + " | Carnet: " + carnet + " | Carrera: " + carrera + " | Promedio: " + getPromedio(); }
3.11 Implementar compareTo() de Comparable

Para ordenar estudiantes por promedio de mayor a menor (descendente), escribimos:

@Override public int compareTo(Estudiante otro) { return Double.compare(otro.getPromedio(), this.getPromedio()); }

¿Por qué así? Double.compare(a, b) compara dos valores double. Si otro.getPromedio() es mayor que this.getPromedio(), retorna positivo, lo que coloca al otro antes (orden descendente).

3.12 Sobrescribir toString()

Para que al imprimir un estudiante se vea su descripción, llamamos a getDescripcion():

@Override public String toString() { return getDescripcion(); }
3.13 Sobrescribir equals() y hashCode()

Dos estudiantes son iguales si tienen el mismo carnet (además de los atributos de Persona). Usamos super.equals() para verificar la igualdad de la parte de Persona:

@Override public boolean equals(Object obj) { if (this == obj) return true; if (obj == null || getClass() != obj.getClass()) return false; if (!super.equals(obj)) return false; Estudiante that = (Estudiante) obj; return Objects.equals(carnet, that.carnet); } @Override public int hashCode() { return Objects.hash(super.hashCode(), carnet); }
¿Qué hace Comparable? Comparable es una interfaz que define el método compareTo(). Permite que los objetos se comparen entre sí para ser ordenados (por ejemplo, con Collections.sort()). Aquí ordenamos estudiantes por promedio, de mayor a menor.

Paso 5: Clase genérica Gestor<T>

Ahora vamos a crear una clase genérica que pueda gestionar cualquier tipo de objeto. Esta clase usará <T> como parámetro de tipo, permitiendo reutilizar el mismo código para estudiantes, profesores o cualquier otra entidad.

5.1 Crear Gestor.java en servicio

Dentro del paquete Lab02.servicio, crea la clase Gestor.

Clic derecho en servicio → New → Java Class.

5.2 Paquete e importaciones
package servicio; import java.util.*; import java.util.function.Predicate; import java.util.stream.Collectors;

Predicate es una interfaz funcional que usaremos para filtrar elementos.

¿Qué es java.util.*?

El asterisco (*) importa todas las clases del paquete java.util de una sola vez: ArrayList, List, Arrays, Optional, Comparator, etc. Es un atajo para no escribir 5 o 6 imports por separado.

¿Qué es Predicate?

Es una interfaz funcional que representa una condición (un filtro). Tiene un único método: boolean test(T t) — recibe un objeto y retorna true o false. La usamos en métodos como filtrar() y buscarPrimero() pasando una lambda, por ejemplo: e -> e.getPromedio() > 85.

¿Qué es Collectors?

Es una clase con métodos estáticos que nos ayudan a recolectar los resultados de un Stream en una estructura de datos. Por ejemplo:

  • Collectors.toList() — convierte el Stream en una List.
  • Collectors.groupingBy() — agrupa elementos por categoría (como contar estudiantes por carrera).
  • Collectors.counting() — cuenta cuántos elementos hay en cada grupo.

Sin Collectors, tendrías que llenar manualmente una lista con un bucle for para obtener el resultado.

5.3 Declarar la clase genérica
public class Gestor<T> {

La T es un parámetro de tipo; se sustituirá por el tipo real al crear un Gestor (ej. Gestor<Estudiante>).

5.4 Atributo: lista de elementos
private List<T> elementos;
5.5 Constructores

Uno vacío (inicializa ArrayList) y otro que recibe una lista inicial:

public Gestor() { this.elementos = new ArrayList<>(); } public Gestor(List<T> elementos) { this.elementos = new ArrayList<>(elementos); }
5.6 Método agregar()
public void agregar(T elemento) { elementos.add(elemento); }
5.7 Método agregarTodos() con varargs
@SafeVarargs public final void agregarTodos(T... elementos) { this.elementos.addAll(Arrays.asList(elementos)); }
¿Qué significa T... elementos y cómo funciona?

T... (varargs): Los tres puntitos significan "argumentos variables". Permiten pasar cualquier cantidad de elementos del tipo T separados por coma, como si fuera una lista suelta. Ejemplo con estudiantes:

gestor.agregarTodos(ana, carlos, maria, luis, laura); // 5 estudiantes gestor.agregarTodos(ana); // 1 estudiante gestor.agregarTodos(); // ninguno

Java internamente trata T... elementos como un arreglo (T[]), por eso usamos Arrays.asList(elementos) para convertirlo en una List que se pueda agregar con addAll().

@SafeVarargs: Es una anotación que le dice al compilador: "ya sé que mezclar genéricos con varargs puede ser inseguro, pero yo me aseguro de usarlo correctamente". Solo suprime una advertencia amarilla, no afecta el funcionamiento.

¿Para qué sirve este método? Evita tener que llamar agregar() una y otra vez por cada elemento:

// Sin agregarTodos() — tedioso: gestor.agregar(ana); gestor.agregar(carlos); gestor.agregar(maria); // Con agregarTodos() — mucho más limpio: gestor.agregarTodos(ana, carlos, maria);
5.8 Método eliminar()
public boolean eliminar(T elemento) { return elementos.remove(elemento); }
5.9 Método getTodos()

Devuelve una copia de la lista para no romper el encapsulamiento:

public List<T> getTodos() { return new ArrayList<>(elementos); }
5.10 Método buscarPrimero() con Optional

Busca el primer elemento que cumpla la condición (Predicate) y devuelve un Optional:

public Optional<T> buscarPrimero(Predicate<T> condicion) { return elementos.stream().filter(condicion).findFirst(); }

Optional permite manejar de forma segura el caso en que no se encuentre el elemento.

¿Qué hace este código y por qué usamos Optional?

Imagina que buscas un estudiante llamado "Luis" en la lista. Pueden pasar dos cosas:

  • Luis existe: quieres obtenerlo y mostrar sus datos.
  • Luis NO existe: si intentas usar el resultado como si existiera, tu programa lanza NullPointerException y se cae.

El problema con devolver null: Si este método retornara null cuando no encuentra nada, el programador que lo usa tiene que acordarse de verificar manualmente con un if (resultado != null). Si se le olvida, el programa truena.

La solución con Optional: Es una "cajita" que puede contener un valor o estar vacía. Java te obliga a verificar si hay algo antes de usarlo:

// Así se usa en Main.java (paso 6.10): Optional<Estudiante> encontrado = gestor.buscarPrimero(e -> e.getNombre().contains("Luis")); encontrado.ifPresentOrElse( e -> System.out.println("Sí existe: " + e), // qué hacer si SÍ está () -> System.out.println("No existe") // qué hacer si NO está );

Línea por línea del código:

  • elementos.stream() → convierte la lista en un flujo (Stream) de elementos.
  • .filter(condicion) → deja pasar solo los elementos que cumplen la condición (por ejemplo, que el nombre contenga "Luis").
  • .findFirst() → toma el primer elemento que pasó el filtro y lo envuelve en un Optional. Si no pasó ninguno, el Optional queda vacío (no es null, es un Optional sin nada dentro).
5.11 Método filtrar()

Devuelve una lista con todos los elementos que cumplen la condición:

public List<T> filtrar(Predicate<T> condicion) { return elementos.stream().filter(condicion).collect(Collectors.toList()); }
¿Qué hace filtrar()?

A diferencia de buscarPrimero() que solo devuelve el primero, este método devuelve todos los elementos que cumplen la condición en una lista nueva. Ejemplo de uso:

// Obtener estudiantes con promedio mayor a 85: List<Estudiante> destacados = gestor.filtrar(e -> e.getPromedio() > 85); // destacados contiene: Ana, Carlos, Luis (todos los que pasan el filtro)

Línea por línea: stream() → flujo de elementos, filter(condicion) → solo deja pasar los que cumplan, collect(Collectors.toList()) → junta todos los que pasaron en una nueva lista.

5.12 Método contarSi()
public long contarSi(Predicate<T> condicion) { return elementos.stream().filter(condicion).count(); }
¿Qué hace contarSi()?

Similar a filtrar(), pero en vez de devolver la lista, solo cuenta cuántos elementos cumplen la condición. Ejemplo:

// ¿Cuántos estudiantes tienen promedio mayor a 85? long cantidad = gestor.contarSi(e -> e.getPromedio() > 85); // Retorna: 3

Es como hacer filtrar().size() pero más eficiente, porque no crea una lista intermedia.

5.13 Método ordenar()
public void ordenar(Comparator<T> comparador) { elementos.sort(comparador); }
¿Qué hace ordenar()?

Ordena los elementos dentro del Gestor usando un Comparator, que es otra interfaz funcional (similar a Predicate pero para ordenar en vez de filtrar). Ejemplos:

// Ordenar estudiantes por promedio (usa el compareTo que definimos): gestor.ordenar(Comparator.naturalOrder()); // Ordenar por nombre alfabéticamente: gestor.ordenar(Comparator.comparing(Estudiante::getNombre));

¿Por qué no usa Predicate? Porque ordenar no es "sí o no", sino "va antes o después". Comparator.compare(a, b) retorna negativo, cero o positivo indicando el orden entre dos elementos.

5.14 Métodos auxiliares: estaVacio(), tamaño(), limpiar()
public boolean estaVacio() { return elementos.isEmpty(); } public int tamaño() { return elementos.size(); } public void limpiar() { elementos.clear(); }
¿Para qué sirven estos métodos?
  • estaVacio() → retorna true si no hay elementos. Útil para verificar antes de operar: if (!gestor.estaVacio()) { ... }.
  • tamaño() → retorna cuántos elementos hay guardados. Equivale a getTodos().size() pero sin crear una copia.
  • limpiar() → vacía completamente el Gestor, eliminando todos los elementos.

Son métodos de conveniencia que hacen el código más legible que manipular la lista interna directamente.

5.15 Método imprimirTodos() con lambda

Usa forEach con una referencia a método para imprimir cada elemento:

public void imprimirTodos() { if (elementos.isEmpty()) { System.out.println("No hay elementos para mostrar."); return; } elementos.forEach(System.out::println); }
¿Qué hace imprimirTodos() y qué es System.out::println?

Recorre todos los elementos y los imprime en consola, uno por línea.

System.out::println: El símbolo :: se llama "referencia a método". Es una forma abreviada de escribir una lambda. Estas dos líneas hacen exactamente lo mismo:

elementos.forEach(e -> System.out.println(e)); // lambda elementos.forEach(System.out::println); // referencia a método (más corto)

El if al inicio es para no imprimir una lista vacía sin avisar: si no hay nada, muestra un mensaje amigable en vez de simplemente no imprimir nada.

¿Qué hace Predicate? Predicate<T> es una interfaz funcional que representa una condición: boolean test(T t). Se usa con lambdas para filtrar elementos. Por ejemplo, e -> e.getPromedio() > 80 es un predicado que selecciona estudiantes con promedio mayor a 80.

La clase Main contiene el método main, que es el punto de entrada del programa. Aquí vamos a:

  • Agregarlos al Gestor.
  • Usar streams y lambdas para filtrar, ordenar y procesar datos.
  • Demostrar el uso de Optional.

6.4 Crear estudiantes

Instancia al menos 5 estudiantes con diferentes nombres, edades, carnets y carreras. Agrega varias notas a cada uno usando agregarNota().

Observa cómo la misma clase Gestor funciona con estudiantes.

¿Por qué agrego los estudiantes a un Gestor si ya los creé?

Crear los estudiantes es solo el primer paso. Imagina que tienes 5 variables sueltas: ana, carlos, maria, etc. Con variables sueltas no puedes hacer nada de esto:

  • Buscar un estudiante por nombre en todas las variables a la vez.
  • Filtrar los que tienen promedio mayor a 85.
  • Ordenarlos por promedio de mayor a menor.
  • Imprimir todos de una sola vez.
  • Contar cuántos hay por carrera.

El Gestor es la herramienta que te permite hacer todo eso. Piensa en él como una "caja organizadora":

// Sin Gestor — imposible operar sobre todos a la vez: ana.getPromedio(); // solo puedes trabajar con UNO a la vez carlos.getNombre(); // otro individual // Con Gestor — operas sobre TODOS de una vez: gestor.filtrar(e -> e.getPromedio() > 85); // filtra todos gestor.buscarPrimero(e -> e.getNombre().contains("Luis")); // busca en todos gestor.imprimirTodos(); // imprime todos

En resumen: crear los objetos te da los datos, pero el Gestor te da el poder de trabajar con todos esos datos juntos de forma eficiente.

6.7 Imprimir la lista completa de estudiantes

Usa el método imprimirTodos():

gestorEstudiantes.imprimirTodos();
6.8 Filtrar estudiantes con promedio mayor a 85

Usa filtrar() con una lambda:

List<Estudiante> destacados = gestorEstudiantes.filtrar(e -> e.getPromedio() > 85); destacados.forEach(System.out::println);
6.9 Ordenar estudiantes por promedio (descendente)

Usa Comparator.naturalOrder() porque Estudiante implementa Comparable:

List<Estudiante> ordenados = gestorEstudiantes.getTodos(); ordenados.sort(Comparator.naturalOrder()); ordenados.forEach(e -> System.out.println(e.getNombre() + " → " + e.getPromedio()));
6.10 Buscar un estudiante por nombre usando Optional

Busca "Luis" y maneja el resultado con ifPresentOrElse():

Optional<Estudiante> encontrado = gestorEstudiantes.buscarPrimero(e -> e.getNombre().contains("Luis")); encontrado.ifPresentOrElse( e -> System.out.println("Estudiante encontrado: " + e.getDescripcion()), () -> System.out.println("No se encontró ningún estudiante con ese nombre.") );

Repite la búsqueda con un nombre que no exista (ej. "Pedro") para ver cómo maneja Optional el valor ausente.

6.11 Contar estudiantes por carrera usando Collectors.groupingBy
var conteoPorCarrera = gestorEstudiantes.getTodos().stream() .collect(Collectors.groupingBy(Estudiante::getCarrera, Collectors.counting())); conteoPorCarrera.forEach((carrera, cantidad) -> System.out.println(carrera + " → " + cantidad + " estudiante(s)") );
6.12 Calcular el promedio general de todos los estudiantes
double promedioGeneral = gestorEstudiantes.getTodos().stream() .mapToDouble(Estudiante::getPromedio) .average() .orElse(0.0); System.out.println("El promedio general de todos los estudiantes es: " + promedioGeneral);
6.13 Demostrar que Gestor también funciona con profesores

Crea un Gestor<Profesor>, agrega los profesores y los imprime:

Gestor<Profesor> gestorProfesores = new Gestor<>(); gestorProfesores.agregarTodos(prof1, prof2); gestorProfesores.imprimirTodos();
