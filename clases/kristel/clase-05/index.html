El Ciclo Básico de Atención de Eventos

¿Cómo pasa un clic físico del mouse a ejecutar código Java?

Del Hardware al CPU: El viaje en 4 fases

En un entorno gráfico, el procesador no pasa preguntando en bucle "¿hicieron clic ya?". Eso consumiría el 100% de la batería y CPU (llamado Polling). En su lugar, el sistema funciona por interrupciones y colas.

1

Acción Física (Hardware Interrupt)

El usuario presiona una tecla o mueve el mouse. El hardware envía una interrupción eléctrica al microprocesador del computador.

2

Captura del Sistema Operativo

El driver de Windows/macOS/Linux detecta la coordenada (X, Y) y determina qué ventana activa posee el Foco de Entrada.

3

La Cola de Mensajes de Java (EventQueue)

La JVM empaqueta la señal en un objeto Java (AWTEvent) y lo coloca ordenadamente en la cola EventQueue.

4

Despacho y Ejecución (Event Dispatching)

El hilo despachador saca el evento de la cola, busca al componente objetivo y ejecuta el método de su Listener correspondiente.

// Cómo consultar la cola de eventos en Java
EventQueue eq = Toolkit.getDefaultToolkit().getSystemEventQueue();
// La JVM atiende esta cola transparentemente en segundo plano

El Hilo de Eventos: Event Dispatch Thread (EDT)

La Regla de Oro de Swing: ¿Por qué una ventana se congela?

Concepto Vital

El Hilo Dedicado de GUI

Java Swing es Single-Threaded (No Thread-Safe). Esto significa que un solo hilo (el EDT) se encarga de:

  • Pintar y redibujar los componentes gráficos en pantalla (paint(), repaint()).
  • Atender las pulsaciones del teclado y clics del mouse.
  • Ejecutar el código que tú escribes dentro de los métodos actionPerformed(), keyPressed(), etc.
¡Peligro de Congelamiento! Si dentro de un Listener ejecutas una tarea pesada (ej: descargar un archivo de 500MB o un Thread.sleep(10000)), bloqueas el EDT. La ventana no se redibuja, el usuario ve el cursor de reloj de arena y el sistema operativo reporta "La aplicación no responde".

La buena práctica de inicialización segura:

SwingUtilities.invokeLater(() -> {
    new VentanaPrincipal().setVisible(true);
});
¿Por qué se muere tu ventana? Demostracion.java 
//  ERROR COMÚN: Bloquear el EDT
btnDescargar.addActionListener(e -> {
    // Al estar en el EDT, este ciclo congela la UI
    for (int i = 0; i < 100; i++) {
        Thread.sleep(200); // ¡La ventana se vuelve blanca!
        lblProgreso.setText(i + "%"); // Nunca se ve en tiempo real
    }
});

//  FORMA CORRECTA: Tarea pesada en hilo separado (Semana 14)
// El EDT solo se encarga de recibir clics instantáneos

Regla de diseño:

Los métodos que atienden eventos deben ejecutarse en milisegundos. Solo toman los datos y delegan.

Clasificación y Jerarquía de Clases de Eventos

El árbol genealógico dentro del paquete java.awt.event

Jerarquía de Herencia en Java 
java.util.EventObject (Raíz general de Java)
  └── java.awt.AWTEvent (Raíz de eventos gráficos)
        ├── Eventos Semánticos / Alto Nivel
        │     ├── ActionEvent (Clics en botón, Enter en texto, selección menú)
        │     ├── ItemEvent (Cambio en CheckBox, RadioButton, ComboBox)
        │     ├── AdjustmentEvent (Movimiento en Scrollbars)
        │     └── TextEvent (Modificación de caracteres en campos)
        │
        └── ComponentEvent (Eventos de Bajo Nivel / Hardware)
              ├── MouseEvent (Clics, arrastre, entrada/salida del cursor)
              ├── KeyEvent (Teclas presionadas, soltadas o digitadas)
              ├── FocusEvent (Componente gana o pierde el foco de entrada)
              ├── WindowEvent (Ventana abierta, minimizada, cerrada)
              └── ContainerEvent (Componente agregado/removido de un JPanel)

Todos heredan los métodos getSource() (quién lo disparó) y getID() (tipo de evento).

¿Bajo Nivel vs Alto Nivel?

Eventos de Bajo Nivel (Raw / Hardware)

Representan exactamente la señal del hardware sin interpretar intenciones. Informan posiciones exactas de píxeles (X,Y) o códigos de teclas (VK_ENTER, VK_ESCAPE).

Eventos Semánticos (Alto Nivel)

Representan la intención del usuario, abstrayendo cómo ocurrió. Por ejemplo, un ActionEvent en un botón puede ocurrir por hacer clic con el mouse, o por presionar la barra espaciadora cuando el botón tiene el foco. Para tu código, ¡es lo mismo!

Consejo: Siempre preferí usar eventos semánticos (ActionListener) a menos que ocupes controlar píxeles específicos o teclas individuales.

Eventos de Hardware: El Ratón (Mouse)

Capturando clics, coordenadas, arrastres y efectos hover.

Las 2 Interfaces de Ratón

En Java, las acciones del ratón están divididas en dos interfaces según si el ratón se mueve o hace clic:

MouseListener (5 métodos)

  • mouseClicked(e): Clic completo (presionar y soltar en el mismo sitio).
  • mousePressed(e): Momento exacto de presionar el botón del mouse.
  • mouseReleased(e): Momento exacto de soltar el botón.
  • mouseEntered(e): El cursor entra al área del componente (Hover in).
  • mouseExited(e): El cursor sale del componente (Hover out).

MouseMotionListener (2 métodos)

  • mouseMoved(e): Se mueve el mouse sin presionar ningún botón.
  • mouseDragged(e): Se mueve el mouse mientras se mantiene presionado un botón.
Propiedades útiles de MouseEvent e:
e.getX() / e.getY() (coordenadas locales) | e.getClickCount() == 2 (doble clic) | e.getButton() (1=izquierdo, 3=derecho).
Implementación con MouseAdapter EfectoHover.java 
// Creamos un botón con efecto interactivo al pasar el mouse
JButton btnMagico = new JButton("Pasa el mouse sobre mí");

// Usamos MouseAdapter para no tener que implementar los 5 métodos vacíos
btnMagico.addMouseListener(new MouseAdapter() {
    @Override
    public void mouseEntered(MouseEvent e) {
        btnMagico.setBackground(Color.GREEN);
        btnMagico.setText("¡Cursor adentro!");
    }

    @Override
    public void mouseExited(MouseEvent e) {
        btnMagico.setBackground(Color.LIGHT_GRAY);
        btnMagico.setText("Pasa el mouse sobre mí");
    }
});
¿Qué es MouseAdapter? Es una clase abstracta que ya implementa los métodos vacíos. Solo sobreescribís los que te interesan.

Eventos de Hardware: El Teclado (Keyboard)

Validaciones en tiempo real: números, límites de caracteres y atajos.

La Interfaz KeyListener

Se dispara cuando un componente tiene el Foco Activo y se toca una tecla:

1. keyPressed(e)

Al pulsar la tecla física hacia abajo. Sirve para teclas especiales como F1, Ctrl, flechas o Enter.

2. keyTyped(e)

Ocurre cuando se genera un carácter Unicode imprimible (letras, números, símbolos). ¡Aquí es donde se validan campos numéricos o de solo letras!

3. keyReleased(e)

Al soltar la tecla física hacia arriba. Ideal para búsquedas en tiempo real en una tabla mientras se escribe.

e.getKeyChar() devuelve la letra o dígito.
e.getKeyCode() devuelve el código entero (ej: KeyEvent.VK_ENTER).
Validación de Campo: Solo Números ValidacionTeclado.java 
JTextField txtTelefono = new JTextField(10);

// Restringir para que el usuario NO pueda escribir letras
txtTelefono.addKeyListener(new KeyAdapter() {
    @Override
    public void keyTyped(KeyEvent e) {
        char c = e.getKeyChar();

        // Si el carácter NO es un dígito del 0 al 9:
        if (!Character.isDigit(c)) {
            // ¡CONSUMIMOS el evento! Java lo destruye y NO lo escribe
            e.consume();
            Toolkit.getDefaultToolkit().beep(); // Alerta sonora opcional
        }
    }
});
¿Qué hace e.consume()? Le dice a Java: "Este evento ya fue atendido, destrúyelo y no permitas que llegue al componente de texto". El usuario presiona una letra y simplemente nada se escribe en la caja.

Eventos de Sistema: Ventana y Foco

Confirmaciones antes de salir y validaciones al salir de un campo.

WindowEvent y WindowListener

Se aplican a los JFrame y JDialog. Permiten interceptar cuándo la ventana se abre, se minimiza o se va a cerrar.

// 1. Desactivar el cierre automático inmediato
ventana.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);

// 2. Interceptar el clic en la "X"
ventana.addWindowListener(new WindowAdapter() {
    @Override
    public void windowClosing(WindowEvent e) {
        int res = JOptionPane.showConfirmDialog(ventana,
            "¿Desea guardar antes de salir?");
        if (res == JOptionPane.YES_OPTION) {
            ventana.dispose(); // Cierra de verdad
        }
    }
});

Evita que el usuario pierda su trabajo por error al darle a la 'X' roja.

FocusEvent y FocusListener

Permite saber cuándo el usuario entra o sale de un cuadro de texto (con tabulador o clic). Súper útil para formato de cédulas o Placeholders.

txtEmail.addFocusListener(new FocusAdapter() {
    @Override
    public void focusLost(FocusEvent e) {
        // Se dispara cuando el usuario pasa a otro campo
        if (!txtEmail.getText().contains("@")) {
            txtEmail.setBackground(new Color(255,220,220));
            lblError.setText("Formato de correo inválido");
        }
    }
});

Validación inmediata sin tener que esperar a que el usuario presione el botón final.

Pseudoeventos y Eventos de Aplicación

Creando nuestros propios eventos personalizados del dominio del negocio.

¿Qué es un Pseudoevento?

No todos los eventos nacen de un clic de mouse o de una tecla. Un Pseudoevento es un evento creado por nosotros mismos para comunicar cambios internos en nuestro sistema.

Ejemplo en el mundo real:

Cuando una cuenta bancaria llega a saldo negativo, la clase Cuenta dispara un SaldoAgotadoEvent. La vista se entera y se pinta en rojo automáticamente.

Beneficio Arquitectónico:

Permite que el Modelo y el Controlador le avisen a la Vista que algo cambió sin conocer los componentes gráficos (desacoplamiento total).

Este es el corazón del Patrón de Diseño Observer que veremos en la Semana 7.
Cómo crear tu propio evento a la medida StockEvent.java 
// 1. Creamos el objeto del evento personalizado
public class StockAgotadoEvent extends java.util.EventObject {
    private String codigoProducto;

    public StockAgotadoEvent(Object source, String codigo) {
        super(source);
        this.codigoProducto = codigo;
    }
    public String getCodigo() { return codigoProducto; }
}

// 2. Creamos la interfaz del Listener personalizado
public interface StockListener {
    void onStockAgotado(StockAgotadoEvent e);
}
¡Cualquier clase de tu sistema ahora puede suscribirse a StockListener y enterarse al instante cuando se acabe el inventario!

Conectando el emisor con los escuchadores en Java puro.

public class Inventario {
    // Lista de escuchadores suscritos
    private List<StockListener> listeners = new ArrayList<>();

    public void addStockListener(StockListener l) {
        listeners.add(l);
    }

    public void venderProducto(String cod, int cant) {
        // ... lógica de reducción de stock ...
        if (stockRestante == 0) {
            dispararEventoAgotado(cod);
        }
    }

    private void dispararEventoAgotado(String cod) {
        StockAgotadoEvent evento =

Las 4 Formas de Implementar Listeners en Java

Evolución histórica y sintáctica: ¿Cuál usar en cada caso?

Forma 1 (Clásica)

implements ActionListener

La propia ventana implementa la interfaz. Obliga a poner un if/else gigante con e.getSource() para saber qué botón se presionó.

public void actionPerformed(ActionEvent e) {
  if (e.getSource() == btn1) { ... }
  else if (e.getSource() == btn2) { ... }
}
Forma 2

Clase Interna Anónima

Se instancia la interfaz directamente dentro del addActionListener. Muy usada antes de Java 8 y en adaptadores con múltiples métodos.

btn.addActionListener(new ActionListener() {
  @Override
  public void actionPerformed(ActionEvent e) {
    guardar();
  }
});
Forma 3 (Estándar Moderno)

Expresiones Lambda (->)

Sintaxis compacta y limpia introducida en Java 8. Aplica para cualquier Interfaz Funcional.

// Limpio, directo y legible
btnGuardar.addActionListener(e -> {
  guardar();
});
Forma 4 (Eventos Complejos)

Clases Adapter

Para interfaces con muchos métodos (MouseListener, WindowListener). Permite sobreescribir solo 1 método en vez de 5.

comp.addMouseListener(new MouseAdapter() {
  @Override
  public void mouseClicked(MouseEvent e) {
    seleccionar();
  }
});

Jerarquías de Atención y Propagación

¿Quién atiende primero un evento cuando hay componentes dentro de otros?

El Árbol de Componentes

Recuerden la jerarquía: JFrame → JPanel → JButton.

Cuando el usuario hace clic en el botón:

  1. El evento se envía primero al nodo más específico (el botón).
  2. Si el botón no consume el evento, o si es un evento de hardware no manejado, este se propaga hacia su contenedor padre (Event Bubbling / Propagación).
  3. El panel padre puede tener un Listener global para monitorear todos los clics de sus hijos.
El freno de mano (e.consume()): Al invocar este método, detienes la propagación del evento hacia niveles superiores o evitas el comportamiento predeterminado del componente.
Ejemplo de Listener Global en el Panel 
JPanel panelPrincipal = new JPanel();

// El panel padre puede escuchar cualquier tecla presionada
// en la ventana para proveer atajos de teclado globales (ej. F5 = Refrescar)
panelPrincipal.addKeyListener(new KeyAdapter() {
    @Override
    public void keyPressed(KeyEvent e) {
        if (e.getKeyCode() == KeyEvent.VK_F5) {
            recargarDatos();
            e.consume(); // Detiene cualquier otra acción
        }
    }
});
Para que un JPanel reciba eventos de teclado directamente, recordá llamar a panelPrincipal.setFocusable(true).

Ejemplo Completo: Formulario Interactivo

Combinando KeyListener, MouseListener y ActionListener de forma limpia.

FormularioRegistro.java Arquitectura de Eventos Limpia 
public class FormularioRegistro extends JFrame {
    private JTextField txtCedula, txtNombre;
    private JButton btnGuardar;
    private JLabel lblContador;

    public FormularioRegistro() {
        // 1. EVENTO DE TECLADO: Validación inmediata de cédula (Solo números, máx 9 dígitos)
        txtCedula.addKeyListener(new KeyAdapter() {
            @Override
            public void keyTyped(KeyEvent e) {
                if (!Character.isDigit(e.getKeyChar()) || txtCedula.getText().length() >= 9) {
                    e.consume(); // Bloquea la tecla
                }
            }
            @Override
            public void keyReleased(KeyEvent e) {
                // Contador en tiempo real
                lblContador.setText(txtCedula.getText().length() + "/9 dígitos");
            }
        });

        // 2. EVENTO SEMÁNTICO: Acción del botón guardar delegada al servicio
        btnGuardar.addActionListener(e -> ejecutarGuardado());
    }

    private void ejecutarGuardado() {
        if (txtCedula.getText().length() < 9) {
            JOptionPane.showMessageDialog(this, "La cédula debe tener 9 dígitos", "Error", JOptionPane.ERROR_MESSAGE);
            return;
        }
        // Delegar a la capa de lógica...
    }
}
