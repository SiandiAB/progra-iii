5.4 · Patrones de diseño

Es una solución reutilizable y comprobada para un problema de diseño que aparece con frecuencia.

No resuelve toda la aplicación. Describe participantes, responsabilidades, relaciones y consecuencias.

Antes de usar uno, pregunte:

  • ¿Cuál problema se repite?
  • ¿Qué partes deben variar?
  • ¿Qué dependencia quiero reducir?
  • ¿El beneficio compensa la complejidad?

Nombre conocido ≠ uso correcto. Primero se reconoce el problema; después se elige el patrón.

Tres preguntas, tres familias

La clasificación de los patrones de diseño.

Creacionales

¿Cómo se crean?

Controlan la construcción de objetos sin amarrar el código a una clase concreta.

Factory MethodBuilderSingleton

Estructurales

¿Cómo se combinan?

Organizan clases y objetos para formar estructuras más grandes.

AdapterDecoratorFacade

Comportamiento

¿Cómo colaboran?

Distribuyen tareas y comunicación entre objetos.

ObserverStrategyCommand

Patrones creacionales

Separar el "qué" del "cómo se construye".

Factory Method

Delega la creación a un método o subtipo.

Vehiculo v = VehiculoFactory
    .crear(tipo, placa, marca);

Builder

Construye por pasos un objeto con muchas opciones.

Reporte r = new Reporte.Builder()
    .conFiltros(anio)
    .build();

Singleton

Limita una clase a una instancia compartida.

Config cfg = Config
    .getInstancia();

Cuidado: puede ocultar estado global y dificultar pruebas.

Patrones estructurales

Ensamblar sin crear acoplamiento innecesario.

Adapter

Traduce una interfaz a otra compatible con el cliente.

Repositorio repo = new
    AdaptadorLector(lectorExterno);

Decorator

Agrega comportamiento envolviendo un objeto.

Operacion op = new ConRegistro(
    new ConValidacion(servicio));

Facade

Ofrece una entrada simple a varios subsistemas.

FlotaService s = new FlotaService();
s.enviarAMantenimiento(placa);

Composite, visto la semana anterior, también es estructural: permite tratar un elemento y un grupo de elementos de forma uniforme.

Patrones de comportamiento

Organizar decisiones y colaboración.

Observer

Un cambio notifica a varios interesados.

tabla.getSelectionModel()
    .selectedItemProperty()
    .addListener((o, a, n) -> cargar(n));

Strategy

Permite intercambiar una forma de realizar una tarea.

vehiculo.setEstrategia(
    new ConsumoElectrico());

Command

Representa una acción como objeto.

new RegistrarVehiculo(dto)
    .ejecutar();

Hilo conductor: estos patrones no son ajenos a MVC; ya los reconocimos como los patrones subyacentes del modelo de la semana 7.

¿Cómo elegir un patrón?

Criterio técnico antes de decidir.

1 Describa el problema 

// ¿Qué se repite? Crear el vehículo correcto
// según su tipo, sin acoplar la Vista.
if (tipo == TipoVehiculo.ELECTRICO)
    v = new VehiculoElectrico(...);
else if (tipo == TipoVehiculo.PESADO) ...

2 Ubique qué cambia 

// Cambia: el subtipo instanciado según el tipo.
// Estable: la referencia Vehiculo y sus métodos.
Vehiculo v;  // la abstracción no cambia

3 Compare alternativas 

// A) if/else en la Vista → acoplado y repetido
// B) VehiculoFactory.crear(tipo, ...) → desacoplado
v = VehiculoFactory.crear(tipo, placa, marca);

4 Evalúe consecuencias 

// B: menos duplicación y un solo punto de cambio.
// Costo: se agrega una clase nueva a mantener.
VehiculoFactory // nueva clase

Buena señal

El patrón reduce duplicación, dependencias o decisiones dispersas.

Mala señal

Se agregan clases y abstracciones sin un problema real que resolver.

5.5 · Aplicaciones n-capas

Capa lógica · layer

Agrupa responsabilidades dentro del software.

Pregunta: ¿qué función cumple este código?

Nivel físico · tier

Indica dónde se ejecuta o despliega una parte.

Pregunta: ¿en qué proceso o máquina vive?

Tres capas pueden ejecutarse en una sola computadora. En ese caso hay separación lógica, pero un solo nivel físico.

Controle el intercambio

Separación física

De una aplicación local a varios niveles.

ConfiguraciónDistribuciónEjemplo
1-tierInterfaz, lógica y datos en un procesoAplicación JavaFX con archivo local
2-tierCliente + servidor de datosJavaFX conectado directamente a MySQL
3-tierCliente + servidor de aplicación + datosJavaFX → API → MySQL
n-tierSe agregan servicios o niveles especializadosAPI, autenticación, reportes y BD separados

Más niveles pueden mejorar despliegue y escalabilidad, pero también agregan red, configuración y fallos posibles.

Datos y mensajes cumplen funciones distintas

5.6 · Transferencia entre módulos.

Datos

Representan información que otra parte necesita.

Ejemplos: placa, marca, estado, lista de vehículos.

Mensajes

Expresan una solicitud, respuesta o notificación.

Ejemplos: registrar, operación exitosa, estado actualizado.

Un mensaje puede transportar datos, pero también comunica una intención.

DTO: transportar sin exponer todo el modelo

Objeto de transferencia de datos.

¿Qué aporta?

  • Define qué campos cruzan el límite.
  • Evita entregar el objeto de dominio completo.
  • Facilita validación y serialización.
  • Reduce dependencias entre módulos.
VehiculoDTO.java
public record VehiculoDTO(
    String placa,
    String marca,
    String tipo,
    String estado
) {}

DTO significa Data Transfer Object: objeto de transferencia de datos.

Antes y después del cambio

Patrones identificados en el Laboratorio 05.

Ya estaban

  • MVC: FXML, Controller y modelo.
  • Composite: árbol de nodos FXML.
  • Observer: listener de selección.
  • Polimorfismo: iniciarRuta().

Agregamos

  • Repository: contrato de persistencia.
  • Simple Factory: creación de vehículos.
  • DTO: transferencia de datos.
  • Capa Service: coordinación y reglas.

Herencia y polimorfismo no son automáticamente Strategy: Strategy exige algoritmos intercambiables mediante composición.
